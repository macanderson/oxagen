`chSelect` previously accepted any query mentioning `org_id`, and separate migration processes could replay the same pending ClickHouse migration.

This change scopes the SELECT's table source by the active organization and workspace before evaluating caller predicates or aggregates. It refuses unsupported multi-source syntax. This helper accepts fixed repository queries, not arbitrary untrusted SQL.

`migrate()` now takes a Postgres advisory transaction lock before contacting ClickHouse. Every migration process targeting one ClickHouse deployment must use the same `DATABASE_URL` coordination database. Missing or unavailable coordination fails before DDL. ADR-116 records the decision and operational requirement.

The production store migration workflow connects to the same Aurora coordination database through an SSM remote-host tunnel. The URL retains its credentials, database, and TLS hostname. The `infra` workflow must apply the narrowly scoped forwarding-document grant from `infra/stacks-new/ci-deploy` before a production ClickHouse migration dispatch.

Refs #2972, #2192, and #2687.
