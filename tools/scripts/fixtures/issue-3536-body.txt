## In plain language

The Skills page must show counts and rows from the same data. If it shows only part of a skill's supported-tool list, it must say how many names were left out.

## Why these fixes belong together

Both reports affect the same Skills page response and how the page explains it. One fixes the counts at their source, and the other makes the display honest about its limit.

This replaces #3107, #3434. The reports are being combined at the maintainer's request. No fix is claimed by this change.

## Definition of done

### Bug from #3107

- [ ] Skill totals and rows come from one consistent database view, even when new session data arrives during the read.

Original completion checks from #3107:

- [ ] In `packages/handlers/src/skill.list.ts`, `SkillQueries.totals` and `SkillQueries.names` (or whatever replaces them) read from one snapshot: fold both queries into one `withTenantDb` call, or compute both in a single CTE-based statement
- [ ] If the two statements stay separate within one transaction, the isolation level is set explicitly (for example `repeatable read`), so `read committed`'s default per-statement snapshot cannot bring the bug back

- [ ] `packages/handlers/src/skill.list.test.ts` and `skill.list.pg.test.ts` are updated for the new single-snapshot read path and interface shape

- [ ] No contract or docs change needed: confirm `docs/capabilities/skill.list.md` still matches the (unchanged) output shape
