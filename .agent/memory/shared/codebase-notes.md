# Shared codebase notes

- Durable `RunSpecV1` does not capture the enqueuing principal; any lifecycle or delegated execution feature that claims IAM equivalence must introduce a versioned principal reference and re-resolve current grants at claim time.
- `CapabilityContext.surface` includes `runner`, while public `CapabilitySurface` does not. Internal lifecycle eligibility should be orthogonal contract metadata, not a spoofed public surface.
- `chat_ux_v2` (apps/app/src/lib/flags.ts) defaults OFF (`NEXT_PUBLIC_CHAT_UX_V2` unset). e2e and prod therefore exercise the LEGACY chat surface: no `ChatSessionProvider`, `useSessionSelectionBridge()` returns null, and `useComposerSelectionState()` falls through to `ChatSelectionProvider`. Anything asserted about the v2 session store is untested by e2e.
- Post-ADR-043 the chat `agentId` is a PER-TURN parameter of `/api/v1/chat/stream` (BodySchema: "this turn is BOUND to that agent"); there is no durable conversation-to-agent binding. `stream/code-binding.ts` is deleted. Do not reintroduce conversation-scoped agent locking.
- The composer's agent chip popover also hosts the workspace 'default assistant' star (a workspace preference, not conversation state), so disabling the chip strands an unrelated capability. Covered by `apps/app/e2e/chat-agent-picker.spec.ts`.
- `apps/app` sets `cacheComponents: true`, enabling Next 16 PPR + the client segment cache. Navigations fetch `/_tree`, `/_head`, layout and `__PAGE__` segments before the real navigation fetch. The `InvariantError: postponed state should not be provided when fallback params are provided` in webserver logs is constant background noise — it appears equally in green and red runs (verified twice, #2559).
- `proxy.ts` `WS_RENAMES` 301s legacy workspace segments: `chat`→`sessions`, `ask`→`sessions` (tail collapses), `studio`→`workbench` (tail preserved). Asserted in `apps/app/src/proxy.test.ts`. `/{org}/{ws}` itself renders the workspace Overview page — it does NOT redirect to a chat surface.
- Playwright traces in this repo capture no app console output, so `page.on("console")` evidence must be added by a spec; the trace's `0-trace.network` DOES retain full request headers and response bodies (under `resources/<sha1>`), which is usually enough.
- apps/app `features/organization/model-funding-form.tsx`: Test and save shows a verdict only when the vendor refused or the model cannot call tools, so the Verdict component's `ok`/`okWithTools` render is unreachable. An exhausted balance (`reason: "exhausted"`) shares the key-service-unreachable sentence; `model-funding-form.test.tsx` pins it as a wart (2026-09-24).
- [2026-09-28] Mac owns `oxagen.app` (bought 2026-09-27), registered at Vercel in the team with slug `oxagen-inc` (migrated there from an earlier team). Its nameservers point at Route 53 (`infra/stacks-new/oxagen/dns-oxagen-app.tf`). It is the production app's domain (ADR-215, #4655), and `app.oxagen.sh` redirects page visits there once `APP_PROD_URL` names it. The app's origin reaches production twice: `NEXT_PUBLIC_APP_URL` inlined at build from `APP_PROD_URL`, and `BETTER_AUTH_URL`/`APP_URL` from Parameter Store at container start. Nothing in the repo writes the Parameter Store values, so a registry change alone moves only the first. `Caddyfile.alb` reaches the node only through a manual `infra/tools/install-node-scripts.sh` run.
- [2026-09-28] Mac decided the API is served at `api.oxagen.app` (ADR-215 amendment, #4709). It has its own ACM certificate in `dns-oxagen-app.tf`, and `api.oxagen.sh` keeps answering with no redirect either way, because webhooks, CLIs and OAuth callbacks call it. The `oxagen-connect` GitHub App's callback and webhook live on the API. The code passes GitHub no `redirect_uri`, so GitHub returns every connect to the first Callback URL in the App's settings; a wrong first entry breaks Connect GitHub. Route handlers must redirect through `responseRedirect`: Next's standalone server builds `request.url` from its bind address, so `new URL(path, request.url)` points at localhost:3000.
- [2026-09-28] Mac decided MCP and the docs move to `.app` too (ADR-215 second amendment, #4717). `mcp.oxagen.app` and `docs.oxagen.app` each have their own ACM certificate in `dns-oxagen-app.tf`, and the `.sh` names keep answering with no redirect. Caddy answers `/healthz` for every host, so a 200 there does not show a name is routed: check `/mcp` or a docs page. The docs sitemap, `llms.txt`, and the `oxagen.dev` redirect still name `docs.oxagen.sh` until the cutover PR.
