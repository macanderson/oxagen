# Shared lessons

- [2026-07-21] In this workspace, pass Vitest file filters as positional arguments through `pnpm --dir <package> exec vitest run <file>`; `test:unit -- <file>` can forward a literal separator and unintentionally run the full package suite. (source: codex/reflections/2026-07-21-stella-telemetry-intake-task-5.md, agent: codex)
- [2026-07-21] An integration hook that skips after a service ping must have a timeout longer than the client's transport timeout, or an unavailable dependency turns the intended skip into a hook failure. (source: codex/reflections/2026-07-21-stella-telemetry-intake-task-5.md, agent: codex)
- [2026-07-21] Separate blocking `before_finalize` work from durable post-commit `after_turn` observation; commit terminal state and outbox obligations atomically. (source: root/reflections/2026-07-21-toml-artifacts-lifecycle-design.md, agent: root)
- [2026-07-21] Foreign tool permissions can be one-to-many classes; map them only through exact audited target sets and intersect with live tools, entitlements, and IAM. (source: root/reflections/2026-07-21-toml-artifacts-lifecycle-design.md, agent: root)
- [2026-09-07] When a UI affordance enforces an invariant, verify the SERVER contract that backs it still exists; after a subsystem excision the affordance often outlives its binding and becomes a pure liability (here a per-conversation agent lock survived the deletion of the durable code binding it mirrored). (source: debugger/reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] apps/app chat has TWO agent-selection stores behind the flag-off `chat_ux_v2`: `agent-picker/chat-selection-context.tsx` (legacy, what e2e and prod actually run) and `session/session-store.tsx` via `session-bridges.tsx` (flag-on). Any change to selection semantics must land in both or neither — patching one looks like a fix. (source: debugger/reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] A client-side 'lock' latch that mirrors server state is usually redundant AND one-way: it never releases on failure. Prefer deriving from the server-truth prop (here `hasMessages = messages.length > 0 || isStreaming`, already synchronous at submit). (source: debugger/reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] Playwright role locators key on the ACCESSIBLE NAME, so a component that swaps to a read-only variant with a different aria-label (`Agent: X` -> `Agent locked: X`) presents as 'element never found', not 'element disabled'. Read the variant branches before blaming navigation/state loss. (source: debugger/reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-10] On a Next App Router navigation trace, `Next-Router-Prefetch: 1` is the discriminator between prefetch noise and a real navigation: the navigation fetch has NO prefetch header and DOES carry `Next-Router-State-Tree`. Judging "the RSC request returned 200" without checking that header answers the wrong question. (source: debugger/reflections/2026-09-10-2559-dropped-navigation.md, agent: debugger)
- [2026-09-10] An RSC 200 proves nothing about usability — read the body: count Flight rows and check every `$L`/`$@` lazy reference resolves. An unresolved ref means React suspends forever and the URL never updates. (source: debugger/reflections/2026-09-10-2559-dropped-navigation.md, agent: debugger)
- [2026-09-10] `apps/app` runs `cacheComponents: true` (next.config.mjs) = Next 16 PPR + client segment cache, so every navigation is preceded by `/_tree`, `/_head` and `__PAGE__` segment prefetches, and dynamic routes prefetch with `$d$` FALLBACK params. Expect this shape before calling it anomalous. (source: debugger/reflections/2026-09-10-2559-dropped-navigation.md, agent: debugger)
- [2026-09-10] A steady sub-second screencast-frame cadence in a Playwright trace is not evidence of React re-rendering — an animated GIF loops in the compositor. Identify the animating asset before building a re-render theory on it. (source: debugger/reflections/2026-09-10-2559-dropped-navigation.md, agent: debugger)
- [2026-09-10] Before investigating a CI flake, check whether a red run exists AFTER the last diagnostic/instrumentation fix merged. If not, the instrumentation is unexercised and the newest artifacts may predate it — that reframes the whole task. (source: debugger/reflections/2026-09-10-2559-dropped-navigation.md, agent: debugger)
- [2026-09-11] Before mocking a Drizzle column's return shape in a test, grep its definition in `packages/database/src/schema/*.ts` first — a `{ mode: "bigint" }` column returns a JS `bigint`, not a string or number, and guessing the shape costs an extra edit cycle. (source: test-engineer/reflections/2026-09-11-action-metering-plan-allowance-tests.md, agent: test-engineer)
- [2026-09-11] A function's "never throws" JSDoc claim can be load-bearing architecture, not decoration — `packages/billing/src/bootstrap.ts`'s `setUsageRecorder` callback awaits `recordGovernedAction` with zero error handling of its own, so a missing try/catch in the callee was a real unhandled-rejection risk in the kernel's post-handler accrual path, not a cosmetic doc/code mismatch. Always check the caller before dismissing a doc-vs-code gap as harmless. (source: test-engineer/reflections/2026-09-11-action-metering-plan-allowance-tests.md, agent: test-engineer)
- [2026-09-13] Writing `no-issue` under `## Issue link` in a PR body does not satisfy SCR-003; `dod-check` reads the PR LABELS live, so the `no-issue` label must be applied (`gh pr edit <n> --add-label no-issue`) or `dod / dod` stays red on an otherwise-green PR (seen on #2936). (source: reviewer, PR #2936, agent: code-reviewer)
- [2026-09-14] A tx double that ignores WHERE predicates (`where: () => chain`) makes a query that can never match in production look like it resolves: WL-21's first cut fed an API-key id into a lookup keyed on `principals.parent_user_id` with `kind = 'human'` and its test 'resolves Owner' passed. When a test's subject is *which actor id reaches the query*, assert the arguments (`toHaveBeenCalledWith(orgId, userId)`) or route the double by table AND predicate; a row-only double proves nothing about the key. (source: reviewer, PR #3000, agent: code-reviewer)
- [2026-09-14] The kernel's `KernelSecurityEvent` (the production `capability.invoke_*` audit, `apps/api/src/bootstrap.ts:131`, `apps/mcp/src/middleware.ts:56`) carries capability/outcome/surface/ids/errorCode only — no input, no output. Only the `KernelTraceEvent` sink carries input/output and nothing registers it outside tests. A handler comment or capability doc that says "the audit records the input" is false; check `packages/oxagen/src/kernel.ts` `KernelSecurityEvent` before claiming a field is audited. (source: reviewer, PR #3000, agent: code-reviewer)
- [2026-09-14] A follow-up RLS migration generated by `tools/scripts/gen-rls-migration.ts` must be filtered with `--only=schema.table,…`: the generator emits `DROP POLICY IF EXISTS … CREATE POLICY` for every manifest table, and several policies were hand-tuned after the manifest run (`20260612210000_skills_builtin_readable_rls.sql`, `20260617120000_marketplace_workspace_scope.sql`), so an unfiltered regeneration silently resets them. Verify the claim by listing migrations that touch `tenant_isolation` after `20260612140000_restore_rls_policies.sql`. (source: reviewer, PR #3001 WL-24, agent: code-reviewer)
- [2026-09-14] `apps/app/knip.json` ignores `src/**/*.builders.ts` and `src/test/**`, and the arch import-graph exempts them as importers, so an unused export in a test builder is caught by NO gate; when a PR introduces a `*.builders.ts`, grep each export for a consumer outside the file (seen on #3004: `ENGINE_UP` exported, consumed only internally). (source: reviewer, PR #3004, agent: code-reviewer)
- [2026-09-14] When a PR deletes an env switch and adds a test titled "runs regardless of the environment", check the test actually stubs the DELETED switch value (here `MC_DATA=fixture`); a test that only sets `NODE_ENV` would also have passed against the old branch, so it proves nothing about the deletion on its own — the token-scan arch test is what makes it mechanical. (source: reviewer, PR #3004, agent: code-reviewer)
- [2026-09-14] "Importable only from tests" is a TARGET rule and none of apps/app's gates express one: `layers.ts` admits any same-feature edge (so `features/shell/shell-client.tsx` -> `./shell.builders` passes INV-07), knip `ignore` drops the builder from analysis rather than flagging its importer, and the INV-22 token scan has no token to match. When a PR lands the first `*.builders.ts` / `viewer.testing.ts`, require a target-side refusal in `import-graph.test.ts` (any production edge to `/\.builders$/` or `server/viewer.testing`) with a probe; a header comment saying "import graph, knip" is not enforcement (seen on #3004). (source: reviewer, PR #3004, agent: code-reviewer)
- [2026-09-14] An `export` on a helper inside `src/test/**` (arch tests included) is caught by no gate (knip ignores `src/test/**`); it is the same class as the `*.builders.ts` unbound-export lesson. When a PR adds a test module, grep each `export` for an importer; drop the keyword if there is none. (source: reviewer, PR #3004, agent: code-reviewer)
- [2026-09-14] Mutation-checked on #3004: `instrumentation.test.ts` alone passes with the `MC_DATA` skip reintroduced (it never sets the deleted switch); only `fixture-tokens.test.ts` catches it. A "no environment skip" test that must stand alone should assert the SET of `process.env` keys `register()` reads (Proxy over `process.env`) equals `{NEXT_RUNTIME, NODE_ENV}`, which fails on any env-keyed skip without spelling a banned token. (source: reviewer, PR #3004, agent: code-reviewer)
- [2026-09-14] SCR-003 (`dod-check`) reads only closing/ref keywords (`Closes #N`, `Refs #N`) and PR labels; an issue number in the PR TITLE or in body prose ("Kernel fix #2906") does not link it, so a PR that is otherwise complete goes red (seen on #3005). For an issue already closed NOT_PLANNED and folded into a worklist item, write `Refs #N` in the body. (source: reviewer, PR #3005, agent: code-reviewer)
- [2026-09-14] A handler comment that says a LEFT JOIN "adds a column, never a row" is a claim about the JOINED side's key being unique; check `packages/database/src/schema/*.ts` for a unique index on that column before accepting it. `billing.gau_settlements.stripe_invoice_id` has none (WL-29's `list_invoices` join relies on the ledger's idempotency key instead), so a duplicate would silently double a page row and miscount the `limit + 1` probe. Also: `storage-manifest.json` lists `reads: []` for every read capability (get_subscription, list_runs, list_api_keys), so an empty `reads` on a new one is the norm, not a gap. (source: reviewer, PR #3006 WL-29, agent: code-reviewer)
- [2026-09-14] knip runs only for apps/app; packages/handlers and packages/oxagen have NO unused-export gate. A handler that copies run.list.ts's export surface (cursor type, QueryDb, status mapper, toXItem) ships unbound exports unless the same consumers exist (run.get, apps/app live adapter): on #3006 InvoiceCursor, QueryDb, invoiceStatus and toInvoiceItem had zero importers. Grep every `export` in a new packages/* module for an importer outside the file; only contract `*Input`/`*Output` types are exported by convention without one. (source: reviewer, PR #3006 WL-29, agent: code-reviewer)
- [2026-09-14] When a reviewer names unbound exports, the list is evidence, not the scope: #3006 dropped exactly the four names the lesson cited and left a fifth (`InvoiceQueries`, exported, zero importers). After the fix, re-run the grep over every remaining `export` in the file rather than the reviewer's list; `declaration: true` does not require a type used in an exported signature to be exported (tsc --noEmit stayed clean with it local). (source: reviewer, PR #3006 WL-29 round 2, agent: code-reviewer)
