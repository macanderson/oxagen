# Shared lessons

- [2026-07-11] `pnpm exec <bin> ...` runs a dependency-staleness check first; if the lockfile/node_modules drifted at all it tries an interactive `pnpm install` and aborts with `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` in any non-interactive agent shell. Skip the wrapper and call the binary directly (`node_modules/.bin/vitest run --coverage`) instead of `pnpm exec vitest run --coverage` when working non-interactively. (source: test-engineer/reflections/2026-07-11-plugins-branch-coverage-gate.md, agent: test-engineer)
- [2026-07-11] V8/Istanbul branch coverage (`BRF`/`BRH` in lcov) only enumerates branches that were *reached* at least once at runtime — a big if/else chain inside a function that's always short-circuited by an early return can show as having near-zero "branches found" for the untaken code, not just zero "hit". A file's reported branch % can therefore understate the true size of the untested surface; don't trust the percentage alone, read the raw `lcov.info` BRDA/DA records (or just the source) at the reported uncovered-line range before estimating how much test-writing is needed. (source: test-engineer/reflections/2026-07-11-plugins-branch-coverage-gate.md, agent: test-engineer)
- [2026-07-11] Before pushing to a shared branch with an already-open PR, verify the PR is still open (`gh pr view <branch> --json state`) and that the local branch tip is still what you think — a PR can merge mid-session on a contested branch. If it merged, check `git merge-base --is-ancestor <old-tip> origin/main` and `git log --oneline origin/main..HEAD` before pushing/opening a new PR, so you know your push is a clean single-commit delta rather than accidentally reopening the old diff. (source: test-engineer/reflections/2026-07-11-plugins-branch-coverage-gate.md, agent: test-engineer)
- [2026-07-11] Run `git status`/`git log -3` as the literal FIRST tool call in any shared-worktree/coverage-gate task, before reading even one source file — on this codebase "an automated optimizer + other sessions work the same tree in parallel" is not theoretical: a coverage-gate-fix worktree had its own concurrent process staging (then mid-session committing+pushing) fixes to the exact same files I was targeting, AND a wholly separate PR landed on `main` fixing the identical apps/api functions/branches gate independently — making the whole branch/PR redundant with real merge conflicts. Re-check for fresh concurrent commits every few files, not just once at session start, and if the coordinator reports a competing PR already merged, stop immediately, leave uncommitted work in place exactly as instructed, and report precise `git status`/`git log` state rather than pushing, committing, or self-cleaning. (source: test-engineer/reflections/2026-07-11-apps-api-coverage-gate-superseded.md, agent: test-engineer)
- [2026-07-12] When judging whether a "use client" component's missing unit test is a repo-convention gap or acceptable, don't trust a prior/prompt's claim either way — find the closest existing analog (same directory pattern, similar interactivity: form + server action, filter bar + URL state) and check whether IT has a `.test.tsx`. In oxagen-platform, `apps/app/src/app/[orgSlug]/security/{audit,mfa}/_components/*.tsx` establishes that interactive AND purely-presentational client components both get full RTL (`@testing-library/react`) unit tests alongside e2e — e2e is not a substitute. (source: test-engineer/reflections/2026-07-12-pr979-governance-security-completeness-audit.md, agent: test-engineer)
- [2026-07-12] When a task forbids running git/tests ("write only, the lead runs it"), that worktree is not thereby safe from concurrent mutation — a parallel automated process (typecheck-fixer or another dispatched subagent) can be committing snapshots of whatever's on disk under its own commit messages and later wipe untracked files created after that snapshot (10 of 14 files vanished mid-session here, confirmed via git-log commit messages literally describing fixes to my code, e.g. adding a `!` non-null assertion for `noUncheckedIndexedAccess` to a file only I had written). Since git is off-limits for diagnosis too, periodically re-verify file presence with plain `find`/`ls` (not git) every few files written, not just at session end — catching loss at file #5 costs one rewrite, catching it at file #14 costs ten. (source: test-engineer/reflections/2026-07-12-automations-cluster-rtl-tests.md, agent: test-engineer)
- [2026-07-12] In oxagen-platform, Base UI `Switch` (`@base-ui/react/switch`) is NOT the "plain non-portal control, safe to leave unmocked" class that Checkbox/MenuItem are — it renders a non-native `<span role="switch">` (disabled state exposed as `aria-disabled`, never the native `disabled` HTML attribute) plus a visually-hidden `<input type="checkbox">`, and its click handler manually constructs+dispatches a `PointerEvent` at that hidden input rather than firing a plain onClick. A repo-wide grep found zero existing tests that `fireEvent.click` a Switch and assert on the resulting `onCheckedChange` callback — every existing Switch test only asserts `aria-checked` reflecting state driven by other means. Mock `@/components/ui/switch` to a plain native `<button role="switch" disabled={disabled} onClick={() => onCheckedChange?.(!checked)}>` (same treatment as Dialog/Menu/Select) rather than assuming the real component's click path works in jsdom. (source: test-engineer/reflections/2026-07-12-automations-cluster-rtl-tests.md, agent: test-engineer)
- [2026-07-15] Spawned agents' final reports do NOT reliably route back to the coordinator by default — agents that were told "send your report via SendMessage to the coordinator before finishing" delivered; those left to default behavior terminated unreachable and their reports had to be exhumed from .claude/projects/<session>/subagents/agent-*.jsonl (last long assistant text). Always (a) instruct explicit SendMessage delivery, and (b) know the JSONL-exhumation fallback. (source: shared/reflections/2026-07-15-quality-pass-full-refactor.md, agent: team-lead)
- [2026-07-15] In oxagen-platform the systemic defect class is cross-surface hardening drift, not bad code: protections added to the app chat route (32 KiB content cap, workspace budget ceilings) never got ported to the REST/MCP surfaces for the same capability. check:manifest verifies a capability EXISTS on each surface, not that its validation/governance matches — when auditing, diff the zod schemas and guard wiring of the same capability across apps/app, apps/api, apps/mcp. (source: shared/reflections/2026-07-15-quality-pass-full-refactor.md, agent: team-lead)
- [2026-07-15] apps/api test suites mock the kernel with a bare vi.fn() (returns undefined, NOT a promise) — route code that chains .then() directly on invoke() throws synchronously under test while working in prod. Write kernel calls as `await` inside try/catch (async helper), and set `mocks.invoke.mockResolvedValue(undefined)` in beforeEach. (source: shared/reflections/2026-07-15-quality-pass-full-refactor.md, agent: team-lead)
