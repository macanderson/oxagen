# docs-writer lessons

- [2026-09-26] Before documenting a CLI flag, trace every entry point that reaches the command: the package binary (`packages/tacho/src/cli/main.ts`), the platform CLI wrapper (`apps/cli/src/program.ts` and `commands/tacho.ts`), and the desktop sidecar args (`apps/desktop/src/commands.ts`). A wrapper that lists its own options drops a new flag without a compile error. (source: docs-writer/reflections/2026-09-26-tacho-multi-enrollment-docs.md, agent: docs-writer)
- [2026-09-26] Hand-test a `jq` sample against every shape the command emits, not only the happy one. For `tacho status --json` that means one enrollment (no `enrollments` key), two enrollments, and a retired or unreadable slot (no `shipping`, no `host`). Keep the fixtures in `/tmp`. (source: docs-writer/reflections/2026-09-26-tacho-multi-enrollment-docs.md, agent: docs-writer)
- [2026-09-26] When a CLI command enrolls again (`reassign`, `enroll --force`), follow it to the server handler it reaches before documenting what survives. `tacho reassign` passes no token, so it lands in `create_tacho_enrollment`, which mints a hostname-derived key with no agent. A token-enrolled agent loses its registration and mandate. The CLI's "device key kept" message says nothing about that. (source: docs-writer/reflections/2026-09-26-tacho-multi-enrollment-docs.md, agent: docs-writer)
- [2026-09-26] When a change adds a refusal, search the UI strings for advice that now hits it. `apps/desktop/src/app.tsx` still told users to run a bare `tacho unenroll`, which refuses on a machine with two agents. (source: docs-writer/reflections/2026-09-26-tacho-multi-enrollment-docs.md, agent: docs-writer)
