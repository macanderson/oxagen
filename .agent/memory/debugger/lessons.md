# debugger lessons

- [2026-09-07] Before reading any component, resolve WHICH code path the failing test actually runs — check feature flags (`src/lib/flags.ts` + `.env.example`) first. A fix applied to the flag-off twin looks like a fix and moves the symptom instead of removing it. (source: reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] A unit test that ASSERTS the buggy behaviour is the fastest confirmation of a behavioural regression — grep the changed files' tests for assertions about the symptom before spelunking source. (source: reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] Prove fail-before by reverting ONLY the source files (`git checkout HEAD -- <src>`) while keeping the new tests, then restoring from a scratch backup. Cheaper and more honest than trusting a pre-fix run from earlier in the session. (source: reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] In python patch scripts, assert on code tokens (`store.foo`, `locked={`) not bare identifiers — a guard like `assert "foo" not in s` matches the explanatory comment you just wrote and silently discards every in-memory edit when the write comes after the assert. (source: reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
- [2026-09-07] When deciding minimal-fix vs remove-the-concept, draw the caller graph ONCE: if removing the entry point leaves its callees uncallable, the cascade is forced and is the minimal fix. Don't re-litigate the trade-off. (source: reflections/2026-09-07-chat-agent-chip-lock-e2e.md, agent: debugger)
