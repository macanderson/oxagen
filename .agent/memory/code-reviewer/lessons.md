# code-reviewer lessons

- [2026-09-22] For a dependabot action bump, verify the pin with `gh api repos/<action>/git/ref/tags/<v>` (deref annotated tags), diff `action.yml` `runs:` and new inputs' defaults between the two SHAs, and check whether the job that runs the changed step is skipped on pull_request; if so, say what exercises it after merge. (source: reflections/2026-09-22-cgp-pr-195-configure-aws-credentials-bump.md, agent: code-reviewer)
- [2026-09-22] The local oxagen checkout can lag `origin/main` by a whole decision: ADR-137 landed the same day and the local `tools/scripts/scr-corpus-check.mjs` still carried the retired `divergeAgentsSummary`. For any cross-repo claim, `git fetch` and read `git show origin/main:<path>`, never the working tree. (source: reflections/2026-09-22-stella-pr-6552-scr-006-prose-rewrite.md, agent: code-reviewer)
- [2026-09-22] Stella's `check-prose.py` reading grade ignores sentences under three words, so a rewrite that chops prose into two-word fragments ("Never after.", "Say why.") lowers nothing and only degrades a compliance list; judge such a rewrite on readability, and the gate on the real sentences. (source: reflections/2026-09-22-stella-pr-6552-scr-006-prose-rewrite.md, agent: code-reviewer)
- [2026-09-22] A PR can carry both `no-issue` and `closes-nothing` and every gate stays green: `dod-check` takes `no-issue` and never mentions the second label. On any waived PR read `gh api repos/<o>/<r>/issues/<n>/events` filtered to `labeled` for who applied each label and when, and compare with sibling PRs of the same kind; a Dependabot bump is the `no-issue` case by the repo's own SCR-003 text, so `closes-nothing` on one is a P3 to remove. Anchor a labels finding on a changed line no earlier round used. (source: reflections/2026-09-22-cgp-pr-196-setup-go-bump-round-2.md, agent: code-reviewer)
- [2026-09-22] A review workflow can re-dispatch a round that already landed (stella #6552 round 1 was posted as 5285375650 on the same commit before a second dispatch). Before drafting, list `pulls/<n>/reviews`, match your own login, the "Adversarial review round N" prefix and the commit id, and return the existing review instead of posting a duplicate, which would burn one of the three counted rounds. Read line anchors from `pulls/<n>/comments` (the per-review endpoint returns `line: null`). The dispatcher also fires after merge and at a stale SHA (stella #6552 round 2 came for `b003e4df` after the PR had merged at `fbed89d0`), so make `gh pr view --json state,mergedAt,headRefOid` plus the reviews list the first call, before the diff. (source: reflections/2026-09-22-stella-pr-6552-scr-006-prose-rewrite.md and 2026-09-22-stella-pr-6552-scr-006-prose-rewrite-round-2-redispatch.md, agent: code-reviewer)
- [2026-09-22] On a rerun of a round on an unchanged head, read `issues/<n>/events` first: the only thing that moves is labels and threads, and a fleet agent can reapply a label a fixer removed (closes-nothing on cgp #195 at 02:29Z), which leaves the fixer's reply untrue. Report the regression and do not repeat tracked findings. (source: reflections/2026-09-22-cgp-pr-195-configure-aws-credentials-bump-rerun.md, agent: code-reviewer)
- [2026-09-22] Before re-raising a label finding that a fixer "resolved", compare its relabel timestamp across sibling PRs. The same second on every Dependabot PR means an owner batch policy (`/fix-prs` applies both `no-issue` and `closes-nothing`), not a regression, so leave it out of the findings. (source: reflections/2026-09-22-cgp-pr-197-setup-node-bump-rerun.md, agent: code-reviewer)
- [2026-09-22] `gh api ... --input file.json` sends ONLY the file as the request body and drops every `-f` field, so a review posted that way lands PENDING. Put `commit_id`, `event` and `body` in the JSON file, or submit afterwards with `POST pulls/<n>/reviews/<id>/events -f event=COMMENT`. Check that the returned state is COMMENTED. (source: reflections/2026-09-22-cgp-pr-196-setup-go-bump-round-3.md, agent: code-reviewer)
- [2026-09-22] Before trusting a fixer's "label removed" reply, read `issues/<n>/events` for a later re-add. The fix-prs brief (`~/.claude/workflows/fix-prs.js:92`) re-applies `closes-nothing` alongside `no-issue` on every pass, against SCR-003. Report the loop and its cause once as a maintainer decision instead of re-flagging the label. (source: reflections/2026-09-22-cgp-pr-196-setup-go-bump-round-3.md, agent: code-reviewer)
- [2026-09-22] Probe a new guard's `uses:` regex with quoted values, prose after `#`, and subpath actions (`owner/repo/sub@vN`). An unmatched line is neither checked nor reported, so a drift guard can pass silently. (source: reflections/2026-09-22-cgp-pr-198-checkout-bump-guard.md, agent: code-reviewer)
- [2026-09-22] Before re-reviewing a head, read each thread's replies and the PR's issue events (labeled/unlabeled), not just isResolved. On stella #6550, a thread was marked resolved even though the fixer's reply said the edit returned HTTP 403. A removed waiver label was also re-applied later by automation. Also: `gh api .../reviews --input file -f event=... -f body=...` drops the -f fields and leaves the review PENDING with no body. Put event/body/commit_id in the JSON. (source: code-reviewer/reflections/2026-09-22-stella-pr-6550-scr-006-manifest-round-3.md, agent: code-reviewer)
- [2026-09-22] When a PR relinks a doc reference to a new canonical source (e.g. `docs/scr/*.md` to `.oxagen/rules/*.toml`), check that every quotation and every enforcement claim beside the link holds against the new target and against this repo's own enforcer: cgp #199 quoted a sentence the TOML lacks, and its bullet claimed a P0–P4 guard while the local guard matched `P[0-3]`. Also read earlier rounds' label fixes against `issues/<n>/events`, because automation under the owner's login re-applies labels after a "fixed" reply. (source: reflections/2026-09-22-cgp-pr-199-adr-137-rollout.md, agent: code-reviewer)
- [2026-09-22] On a later round with an unchanged head and tracked findings, compare the head SHA and the events since the last round first. When neither moved, post "no findings" instead of re-deriving the pin and action.yml diff; spend the time on what merging a sibling fix (e.g. a comment reword on main) does to the bot branch's rebase. (source: reflections/2026-09-22-cgp-pr-195-configure-aws-credentials-bump-round-2.md, agent: code-reviewer)
- [2026-09-22] When fleet fixers push onto sibling Dependabot PRs, diff every open sibling's file list first (`gh pr view <n> --json files`). Two fixers can each add the same guard path with different code (cgp #194 and #198 both added `check-scaffold-action-pins.py`), which guarantees an add/add conflict that Dependabot can no longer resolve. Also check whether a new guard turns main red when an already-green sibling merges on a stale run. cgp's ruleset requires no status checks and no up-to-date branch. (source: reflections/2026-09-22-cgp-pr-194-setup-python-bump.md, agent: code-reviewer)
- [2026-09-22] In a later review round on an unchanged Dependabot action bump, check what can drift first: `git merge-base` against `origin/main`, then `git grep "<action>@" origin/main` to find pins on main outside the diff, then the checks JSON. Reread the upstream diff only if one of those moved. For setup-node v5+, the automatic cache fires only when a `package.json` in the working directory sets `packageManager` or `devEngines`, so search for those fields before raising a caching or cache-poisoning concern. (source: reflections/2026-09-22-cgp-pr-197-setup-node-bump-round-3.md, agent: code-reviewer)
- [2026-09-22] When a harness restarts its round count on an unchanged head, read the PR's review history and your own prior reflections first. Then check only what could have moved: the compare ahead/behind, the check buckets, and new pins or guards on main. Post no findings instead of re-flagging recorded P3s. (source: reflections/2026-09-22-cgp-pr-196-setup-go-bump-round-2-rerun.md, agent: code-reviewer)
- [2026-09-22] When a shell-parse gate gains a table of wrapper flags that take a value, check each entry for which side its value falls on. `command -v NAME` names a command without running it, but `env -S "cmd ..."` runs its value. Put `-S` in the value table and stella #6551 turned a spelling main refused into an open one. Trace old and new code token by token for each table entry. (source: reflections/2026-09-22-stella-pr-6551-gh-redirect-inputs.md, agent: code-reviewer)
- [2026-09-22] When two open PRs edit nearby lines of one file (a bot bump and a comment reword), test the merge with `git show <sha>:<path>` for base, ours and theirs, then `git merge-file -p` in a mktemp dir. One unchanged line between hunks merged clean on cgp #195/#203, and the test touches no shared repo. (source: reflections/2026-09-22-cgp-pr-195-configure-aws-credentials-bump-round-3.md, agent: code-reviewer)
- [2026-09-22] On a restarted round count for an unchanged head, check the facts that decide the round first: whether the sibling PR carrying the same hunk has merged, whether the head, main or merge base moved, and the label events after the last fix. When none moved and each fixer reply checks out against its source, post "no findings" with event, body and commit_id in the JSON input. (source: reflections/2026-09-22-stella-pr-6550-scr-006-manifest-round-4.md, agent: code-reviewer)
- [2026-09-22] On a round N rerun over an unchanged head, start by closing the "weakest decision" gap named in the previous reflection. Re-running the same checks adds nothing. (source: reflections/2026-09-22-cgp-pr-196-setup-go-bump-round-3-rerun.md, agent: code-reviewer)
- [2026-09-22] When two sibling PRs share a hunk and a PR body claims "whichever lands second fails empty-diff and should close", simulate it: `git merge-tree --write-tree <sibling-head> <this-head>` and compare with `<sibling-head>^{tree}`. Stella's `check-empty-diff.sh` fails only on a wholly empty merge, so the PR with extra content never fails and must not close. Also read a "superseded" sibling issue's current body; stella #6554 had already been rewritten to the same DoD that #6555 claimed to supersede. (source: reflections/2026-09-22-stella-pr-6552-scr-006-prose-rewrite-round-2.md, agent: code-reviewer)
