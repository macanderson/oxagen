# Marketing copy (conditional)

Features that ship invisibly do not convert. When a capability is user-facing, update the marketing site so the shipped feature is reflected. This is a real layer, not an afterthought.

## Relevance gate

Update marketing when the capability changes what a user or buyer can do or perceive: a new agent ability, a new integration, a new surface, a meaningful performance or scale claim. Skip marketing only when the capability is purely internal infrastructure with no externally observable effect, and record that omission in the manifest.

## What to update

- The relevant feature section or feature page, with intent-first copy that leads with the user outcome, not the mechanism.
- Any capability list, comparison table, or "what's new" surface.
- If the feature warrants it, a short changelog or launch entry.

## Style

Plain, active voice, present tense, Oxford commas, no hype filler. Lead with what the user can now do. Match the existing marketing voice. Frontend follows house style: Tailwind v4, shadcn, glassmorphism, light and dark mode, rich transitions.

## Rules

- Decide relevance explicitly and state the decision. Do not silently skip.
- Marketing copy describes the user-visible outcome, never internal terminology like node, edge, or workspace unless that is the product vocabulary the user already sees.
