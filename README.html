The Oxagen monorepo index

Oxagen turns a business's heterogeneous data into a live, queryable knowledge graph and lets a swarm of role-specialized AI agents act on it — auditably, and on your own infrastructure when you need it. This page is the map: every app and package, what it does, and a link straight to its README.

Get started

The monorepo uses pnpm workspaces and Turborepo. Install once at the root, then target any app or package by its name.

# from the monorepo root
pnpm install
pnpm --filter @oxagen/app dev       # app  → :3000
pnpm --filter @oxagen/website dev   # site → :3100
pnpm --filter @oxagen/api dev       # api  (Hono)
pnpm --filter @oxagen/mcp dev       # mcp  (xmcp)
pnpm turbo typecheck    # type-check the workspace
pnpm turbo test:unit    # run unit suites
pnpm turbo lint         # lint everything

CI gates (typecheck / migrate / test) run on pull requests, not direct pushes to main — verify locally before pushing to main.

▸ How are the apps deployed?

Each app is a Vercel project named oxagen-v2-<app>. Until the brand domain launches, production uses the *.vercel.app domains linked in the cards above. Prod URLs live in env vars, so the switch to oxagen.ai is a single sweep.

▸ Where is the authoritative engineering policy?

The binding law lives in .agents/skills/oxagen-engineering-policy (the four-store model, SQL conventions, naming, observability, PR discipline). The brand/visual system is oxagen-design-system; the component API is coss-ui. Consult them before changing code, schema, or UI.

▸ Why two READMEs (.md and .html)?

The README.md renders on the git host; these README.html files are richer, interactive navigation aids meant to be opened in a browser — collapsible sections, copy buttons, tabs, and a theme toggle. Every app/package has one.
