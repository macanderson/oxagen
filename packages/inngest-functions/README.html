Durable background functions

Inngest-backed durable functions for long-running agent runs, batch processing, scheduled jobs, and event-driven workflows. Everything that cannot safely block an HTTP request lives here — retryable, observable, and off the request path.

internal package agent-runtime / infra @oxagen/inngest-functions inngest 3.54

What this is

@oxagen/inngest-functions hosts the async and batch counterparts of platform capabilities. When a synchronous capability in @oxagen/agent or @oxagen/handlers needs to do something that takes seconds or minutes — or needs guaranteed retries — the work is dispatched as an Inngest event and handled here. The Inngest handler is mounted in apps/api at the standard /api/inngest route.

event fired→ inngest function→ @oxagen/agent→ graph + telemetry
⊹

Durable runs

Inngest checkpoints function state at each step boundary. A timeout or crash does not lose progress — the function resumes from the last completed step.

◇

Automatic retries

Failed steps retry with exponential backoff by default. Retry policy is configurable per function — no manual retry loops, no dead-letter queue plumbing.

≋

Observable

Every function run is visible in the Inngest dashboard with full step traces, event payloads, and timing — no custom logging needed for run-level observability.

Usage

import { inngest } from "@oxagen/inngest-functions/client"

// Define a durable function triggered by an event
export const runAgentJob = inngest.createFunction(
  { id: "run-agent-job", retries: 3 },
  { event: "oxagen/agent.run.requested" },
  async ({ event, step }) => {
    const result = await step.run("execute-agent", async () => {
      // heavy work here — checkpointed by Inngest
      return runAgent(event.data)
    })
    return { result }
  }
)
// The configured Inngest client
import { inngest } from "@oxagen/inngest-functions/client"

// Send an event from anywhere in the monorepo
await inngest.send({
  name: "oxagen/agent.run.requested",
  data: { runId: "run_abc123", orgId: "org_xyz" },
})
// apps/api — mount the Inngest handler
import { serve }     from "inngest/hono"
import { inngest }   from "@oxagen/inngest-functions/client"
import { functions } from "@oxagen/inngest-functions/functions"

app.on("ALL", "/api/inngest", serve({ client: inngest, functions }))

Source layout

  • src/inngest.ts — the configured Inngest client; sets the app ID, signing key, and event key from @oxagen/config/env
  • src/functions.ts — top-level array of all registered functions; imported by apps/api to mount the Inngest handler
  • src/functions/ — individual function definitions, one file per logical domain (agent runs, billing, scheduled maintenance, etc.)
  • src/logger.ts — structured pino logger bound to the Inngest context, forwarded to @oxagen/telemetry
  • src/index.ts — package root; re-exports client and functions

FAQ & gotchas

▸ Why does async work live here instead of inline in apps/api?

Two reasons. First, the function definitions need to be importable as a typed array by the Inngest serve() handler — keeping them in a dedicated package makes the boundary explicit and testable in isolation. Second, long-running agent work (minutes, not milliseconds) must not block HTTP request workers. Moving it behind an Inngest event gives automatic retries, step-level checkpointing, and a full audit trail in the Inngest dashboard without writing any of that infrastructure from scratch.

▸ How are these functions the async counterparts of synchronous capabilities?

Every synchronous capability in @oxagen/handlers or @oxagen/agent has an upper bound on how long it can run before it times out on the request path. When a capability needs to exceed that bound — batch enrichment, large graph traversals, multi-step agent plans — the synchronous handler fires an Inngest event and returns immediately. The Inngest function here picks up the event and runs the full work with retries and step checkpoints. The caller tracks progress via the database state that the function writes through @oxagen/database.

▸ How do I add a new function?

Create a new file under src/functions/, define the function with inngest.createFunction(), and add it to the array exported from src/functions.ts. The Inngest handler in apps/api picks it up automatically — no route changes needed. Name the event with the oxagen/ prefix and the verb.noun.tense convention (e.g. oxagen/report.generate.requested).
