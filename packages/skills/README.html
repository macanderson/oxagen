Agent skill loader & registry

Reads the .agents/skills/ library, parses each skill's YAML frontmatter, validates the schema with Zod, and builds an in-memory registry that agent runtime surfaces can query at startup. Skills are markdown — this package is the bridge between the file system and the platform.

internal package agent-runtime @oxagen/skills yaml zod

What this is

@oxagen/skills is the loading layer between the human-readable skill files in .agents/skills/ and the agent runtime that needs to discover and dispatch them. It parses YAML frontmatter from each skill's markdown file, validates it against a Zod schema, and populates a typed registry keyed by skill slug.

.agents/skills/*.md→ @oxagen/skills→ typed registry→ agent runtime
⟁

Filesystem loader

Scans a directory for .md files, extracts YAML frontmatter, and streams each parsed skill into the registry without loading the full markdown body into memory.

◈

Zod validation

Every skill frontmatter is validated against a shared SkillSchema. Missing required fields or wrong types throw at load time — not at dispatch time.

⊹

Queryable registry

Look up by slug, list all skills, filter by tag or domain. The registry is the single source of truth for what skills are available to an agent session.

Usage

import { loadSkills } from "@oxagen/skills/loader"
import { registry }   from "@oxagen/skills/registry"

// Load all skills from the .agents/skills/ directory
await loadSkills(".agents/skills")

// Query the registry
const skill = registry.get("oxagen-engineering-policy")
const all   = registry.list()
const ui    = registry.filter({ tag: "ui" })

Source layout

  • src/loader.ts — filesystem scanner; reads .md files, splits frontmatter from body, calls SkillSchema.parse
  • src/filesystem.ts — low-level file utilities (directory walk, file read) abstracted for testability
  • src/registry.ts — in-memory registry; keyed by skill slug; exposes get, list, filter, seed
  • src/seed.ts — seeds the registry from a pre-built list (used in prod to avoid filesystem access at runtime)
  • src/types.ts — Skill interface and SkillSchema Zod definition
  • src/index.ts — package root; re-exports all public symbols

FAQ & gotchas

▸ What format are skill files?

Skills are standard markdown files with a YAML frontmatter block at the top — the same format used by most static-site generators. The frontmatter block must include at minimum name, slug, description, and tags. The markdown body that follows the frontmatter is the human-readable instructions the agent receives when the skill is invoked. The loader separates them: the frontmatter becomes the registry entry, the body is stored as the skill's content field and delivered to the model at dispatch time.

▸ How does this relate to .agents/skills/?

.agents/skills/ is the canonical, human-edited source of truth — that directory is checked into the repo and is what engineers and agents author. @oxagen/skills is the runtime loading layer: it reads that directory, validates each file, and makes the skills queryable by the platform. Skills are symlinked from .claude/skills/ for agent tooling discovery. The package does not own the skill authoring format; it only owns parsing and registry population.

▸ Why does the loader validate with Zod at load time?

Failing at load time (server startup or build) is far preferable to failing at dispatch time (when an agent tries to use a skill mid-session). A skill with a missing or malformed frontmatter field is effectively unusable, and catching it early surfaces the problem to the engineer who edited the file — not to the user who triggered the agent session.
