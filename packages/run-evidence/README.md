# @oxagen/run-evidence

Turns a run's evidence into bytes you can hash, and hashes the same way every
time. Four jobs:

1. **Normalize** Context Graph Protocol (CGP) frames and queries, using the
   wire types from `@contextgraphprotocol/typescript-sdk` as the source of
   truth (ADR-036).
2. **Canonicalize and digest** any JSON value using RFC 8785 (JCS), so the same
   value always produces the same `sha256:` digest.
3. **Hash a context record** the way Stella does (`recordHash`,
   `src/record-hash.ts`), so a record in `.oxagen/rules/` verifies in both.
4. **Define the proof vocabulary**: the `proof.observed` frame body, the
   verdict, oracle, disclosure-grain, and tamper word lists, and the one
   function that rolls a run's attempts up to a verdict (`src/proof.ts`,
   ADR-064).

## Boundary

- **Owns:** JCS canonical bytes and `sha256:` digests (`src/digest.ts`), CGP
  frame and query normalization (`src/contextgraph.ts`, `src/json-wire.ts`),
  the context-record hash (`src/record-hash.ts`), the proof vocabulary and
  verdict rollup (`src/proof.ts`), the published envelope limits
  (`src/limits.ts`), and the vendored CGP golden fixtures (`fixtures/`).
- **Does not own:**
  - Storing evidence, or the run ledger's event digest chain:
    [`@oxagen/run-ledger`](../run-ledger/README.md).
  - The database CHECK constraints that reuse these word lists:
    [`@oxagen/database`](../database/README.md).
  - Applying the envelope limits. A caller has to (see "Things worth
    knowing").
- **Depends on:** No `@oxagen/*` runtime dependencies.
- **Used by:** `@oxagen/agent`, `@oxagen/billing`, `@oxagen/database`,
  `@oxagen/handlers`, `@oxagen/iam`, and `@oxagen/oxagen`.

## Entry points

- `.` (`src/index.ts`): everything in `contextgraph`, `digest`, `limits`,
  `proof`, and `record-hash`.

## Status

The CGP normalizers have no production caller yet. The digest, record hash,
and proof vocabulary are in use (see Seams). The digests are pinned against
golden fixtures generated by the upstream Rust conformance suite, so the byte
format is settled.

## What you get

```ts
import {
  digestJcs,
  jcsBytes,
  normalizeContextFrameV1,
  normalizeContextQueryV1,
  isProtocolTimestampV1,
  declaresHonestTokenCostV1,
  MAX_ENVELOPE_JCS_BYTES,
} from "@oxagen/run-evidence";

const frame = normalizeContextFrameV1(untrustedInput); // throws on anything off-spec
const bytes = jcsBytes(frame); // RFC 8785 canonical UTF-8
const digest = digestJcs(frame); // "sha256:<64 lowercase hex>"
```

`normalizeContextFrameV1` and `normalizeContextQueryV1` throw `TypeError` for
input that is not plain I-JSON (accessors, Proxies, symbols, `undefined`,
cycles, non-finite numbers, lone surrogates) and `ZodError` for input that is
valid JSON but breaks the protocol schema. Callers that report failures to a
user need to handle both.

## How input is checked

Every entry point runs the same two steps in order.

1. `snapshotJsonWire` (`src/json-wire.ts`) walks the input and builds a fresh
   copy from own data properties only. It never reads through a getter, never
   triggers a Proxy trap, and rejects anything that is not I-JSON. The result
   is a null-prototype tree, so nothing inherited can leak into validation.
2. A Zod schema (`src/contextgraph.ts`) parses that snapshot in `.strict()`
   mode, so an unknown wire field is an error rather than a silently dropped
   one.

Splitting the two matters: by the time Zod sees the value, no user code can run
during parsing.

## Things worth knowing

- **Token cost is not a parse gate.** Some pinned golden fixtures declare a
  `token_cost` that does not match their content, so parsing must accept them.
  Use `declaresHonestTokenCostV1` as a separate conformance check.
- **`provenance` and `relations` default to `[]`.** They appear in normalized
  output even when the source omitted them, and the pinned fixtures expect
  that. The representation fields (`representation`, `content_fidelity`, and
  friends) deliberately have no default.
- **Limits are published, not enforced.** `src/limits.ts` holds the envelope
  and collection caps from the spec. Nothing in this package applies them; a
  caller has to. In particular `jcsBytes` has no size or nesting-depth limit,
  so deeply nested attacker-controlled JSON can exhaust the call stack.
- **Timestamps are strict.** `isProtocolTimestampV1` accepts RFC 3339 UTC only
  (a `Z` suffix, optional fractional seconds, leap second 60, real calendar
  days). An offset like `+02:00` is rejected.

## Prototype-tampering guard

`normalizeContextFrameV1` and friends call `assertIntrinsicIntegrity()` first.
It compares `Array.prototype`, `Object.prototype`, `Set.prototype`, and
`String.prototype` against snapshots taken when the module loaded, and throws
`TypeError` if any descriptor changed. `src/digest.ts` and `src/json-wire.ts`
additionally capture the specific methods they call, so a later reassignment of
a public prototype method cannot change a digest.

The guard covers the four prototypes named above and nothing else. The static
namespaces these modules call through at runtime (`Object`, `Reflect`, `JSON`)
are neither captured at load nor rechecked, so code running in the same realm
that replaces, say, `Object.getOwnPropertyDescriptor` or `JSON.stringify` can
still change what gets hashed. Treat the guard as tamper *evidence* for the
common prototype-pollution case, not as a sandbox.

## Fixtures

`fixtures/contextgraph/` holds golden files vendored from the upstream
protocol repository, plus a `manifest.json` that pins the upstream commit and
each file's raw-byte digest. Regenerate them upstream with:

```bash
cargo test -p contextgraph-conformance --test golden_fixtures
```

`pnpm check:contextgraph-fixtures` verifies the vendored copies. Offline it
checks the digests against frozen constants. Set
`CONTEXT_GRAPH_PROTOCOL_DIR=<path to an upstream checkout>` to also compare the
vendored bytes against the pinned upstream commit.

## Tests

```bash
pnpm --filter @oxagen/run-evidence test:unit src/digest.test.ts
```
