The single AI chokepoint

Every LLM call in the platform — streaming completions, structured object generation, embeddings, image generation — enters and exits through one invoke() boundary, so metering, performance tracking, IAM enforcement, and customer billing hooks happen in exactly one place.

internal package Node.js runtime @oxagen/ai Vercel AI SDK ai@6.0.197 Anthropic default import path packages/ai

What this is

@oxagen/ai wraps the Vercel AI SDK (streamText, generateObject, generateText), embeddings, and image generation behind a typed facade. Callers receive the same streaming and structured-output ergonomics as the raw SDK, but the boundary layer automatically: records token usage and latency to @oxagen/telemetry; enforces the caller's IAM scope; writes usage to @oxagen/billing for credit metering; and selects the model from a centrally maintained catalog so model IDs are never scattered across the codebase.

caller→ invoke() [IAM · meter · telemetry]→ provider (Anthropic / OpenAI)→ usage → billing
⌁

Single boundary

No provider SDK is called directly anywhere else in the codebase. One invoke() means one place to add a new model, change a default, or audit every AI call.

◈

Metered by design

Usage is written to @oxagen/billing on every call — input tokens, output tokens, model id, surface origin. The margin is realized at the meter, not the sticker price.

✦

Typed model catalog

Model IDs live in catalog.ts as typed constants. Callers reference models.claude.sonnet rather than a raw string, so a rename is a single-file change.

Install / import

Workspace-internal package. Add "@oxagen/ai": "workspace:*" to the consuming package's dependencies.

{
  "dependencies": {
    "@oxagen/ai": "workspace:*"
  }
}
import { stream } from "@oxagen/ai";
import { models } from "@oxagen/ai/catalog";

const result = await stream({
  model:    models.claude.sonnet,
  messages: [{ role: "user", content: "Summarize this thread." }],
  context:  { userId, orgId, surface: "api" },  // metering + IAM
});

for await (const chunk of result.textStream) {
  process.stdout.write(chunk);
}
import { generateObject } from "@oxagen/ai";
import { models } from "@oxagen/ai/catalog";
import { z } from "zod";

const { object } = await generateObject({
  model:   models.claude.sonnet,
  schema:  z.object({ fields: z.array(z.object({ name: z.string(), value: z.string() })) }),
  prompt:  "Extract form fields from this text: ...",
  context: { userId, orgId, surface: "app" },
});
import { embed } from "@oxagen/ai";
import { models } from "@oxagen/ai/catalog";

const { embedding } = await embed({
  model: models.embedding.default,
  value: "The quick brown fox",
  context: { userId, orgId, surface: "agent" },
});

Model catalog

Model IDs are maintained in src/catalog.ts and exported as a typed models object. The default and preferred provider is Anthropic — Claude models are the primary choice for all text generation tasks.

Source layout

  • src/stream.ts — stream(): wraps streamText from the AI SDK; enforces IAM, meters tokens, emits telemetry
  • src/generate-object.ts — generateObject(): structured output via Zod schema; same boundary guarantees as stream
  • src/embed.ts — embed(): text embedding; meters embedding tokens separately from completion tokens
  • src/generate-image.ts — generateImage(): image generation; meters by image count and resolution
  • src/models.ts — provider adapter initialization (Anthropic, OpenAI); reads keys from @oxagen/config
  • src/catalog.ts — typed models constant; the only file that contains raw model ID strings
  • src/index.ts — root barrel re-exporting the public helpers

FAQ & design notes

▸ Why does the chokepoint exist?

Without a single boundary, metering becomes scattered: one caller bills correctly, another forgets to record tokens, a third calls the provider with no IAM check. Billing parity across all three surfaces (app, API, MCP) also requires that every call flows through the same accounting path. The invoke() boundary makes compliance structural — adding a new surface does not require adding metering code to that surface; it inherits it automatically.

A secondary benefit: swapping providers (or adding a new model) is a catalog change in one file, not a refactor across every package that calls an LLM.

▸ What context must every caller pass?

Every helper requires a context argument with at minimum userId, orgId, and surface ("app", "api", or "mcp"). The boundary uses userId and orgId for IAM enforcement and for attributing usage in billing. The surface field appears in telemetry so usage by surface can be tracked separately. Calls missing a context will be rejected at compile time by the TypeScript types.

▸ Can I call the Vercel AI SDK directly in a handler?

No. Direct calls to streamText, generateObject, or any provider SDK from @ai-sdk/anthropic or @ai-sdk/openai outside this package are a policy violation. The engineering policy mandates a single AI chokepoint precisely to prevent bypassed metering. All LLM work must route through the helpers exported from this package.

▸ Which models should I use by default?

Default to the latest Claude models from Anthropic. The model catalog is the canonical reference. Use models.claude.haiku for fast, cheap turns (routing, lookups, formatting). Use models.claude.sonnet for the majority of agent work. Escalate to models.claude.opus only for architectural decisions, security-sensitive reasoning, or multi-system coordination — matching the escalation rubric in CLAUDE.md.
