Coss UI component system

The shared design-system library for every Oxagen surface. Built on Base UI (@base-ui/react) with a stock neutral theme — no Radix, no glass. Composition via the render prop. Self-hosted theme switching with no flash and no third-party provider.

What this is

@oxagen/ui is the single source of truth for components, design tokens, and typography across apps/app, apps/website, apps/admin, and apps/docs. It is built on @base-ui/react (not Radix), reset to a stock neutral palette, and ships Aeonik variable fonts (sans, Fono display, and mono). The ThemeProvider / ThemeScript pair replaces next-themes monorepo-wide — do not reinstall it.

⊞

Base UI foundation

Built on @base-ui/react 1.5. Composition uses the render prop — not asChild. State styling targets data-[active], not data-[state].

◎

Self-hosted theming

ThemeProvider is a client component; ThemeScript injects a no-flash script server-side. Both are in this package. next-themes is removed and must not return.

✦

Aeonik variable fonts

Sans, Fono display, and mono faces ship inside styles/fonts/ and are loaded via styles/globals.css — no Google Fonts, no network requests for type.

Usage

// Named import from the package root
import { Button, Dialog, Select } from "@oxagen/ui"

// Or via the app-local alias (apps/app)
import { Button } from "@/components/ui/button"
// In your root layout or global CSS entry point
import "@oxagen/ui/styles/globals.css"   // fonts + resets + component styles
import "@oxagen/ui/styles/tokens.css"    // CSS custom properties / design tokens

The package is marked "sideEffects": ["**/*.css"] so bundlers retain these imports even when tree-shaking.

// Composition via the render prop — NOT asChild
import { Button } from "@oxagen/ui"

// Correct: render prop
<Button render={<a href="/dashboard" />}>Go to dashboard</Button>

// Wrong: asChild is not used in this system
// <Button asChild><a href="/dashboard">...</a></Button>
// In your root layout (server component)
import { ThemeScript } from "@oxagen/ui"

// ThemeScript goes in <head> — prevents flash of wrong theme
export default function RootLayout({ children }) {
  return (
    <html>
      <head><ThemeScript /></head>
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  )
}

FAQ & gotchas

▸ Why render and not asChild?

This package is built on @base-ui/react, not Radix UI. Base UI uses the render prop for polymorphic composition — you pass a React element to render and the component merges its props onto it. The asChild pattern is a Radix convention and does not exist in Base UI. If you see asChild in the codebase it is a migration artifact and should be replaced.

▸ Why data-[active] and not data-[state]?

Base UI exposes component state through data-[active], data-[checked], data-[open], etc. — not the Radix data-[state=open] / data-[state=checked] convention. Tailwind variant selectors in this package are written accordingly. If you are migrating a component from Radix, update every data-[state=...] selector to the appropriate Base UI attribute.

▸ What is the difference between --accent and --primary?

--accent is a neutral gray — it maps to the subtle hover/focus backgrounds on interactive elements, not to the brand color. Use --primary (indigo) when you want emphasis, active state color, or the brand gradient. This distinction matters most in button variants and focus rings: reach for bg-primary / text-primary, not bg-accent, when you want the element to read as "action".

▸ Why was next-themes removed?

next-themes was removed monorepo-wide and replaced by the self-hosted ThemeProvider (client component) and ThemeScript (server, no-flash inline script) that ship inside this package. The self-hosted pair gives full control over the persistence key, flash prevention, and SSR behavior without a third-party runtime dependency. Do not reinstall next-themes.
