packages/config · @oxagen/config

Foundational config & environment

Zod-validated environment loading for every surface in the monorepo. Normalizes the intentionally double-quoted dev values, exposes a typed env object, and hosts a small service registry — all in a package so lean it carries only one external dependency.

internal package foundations @oxagen/config zod 3.x

What this is

@oxagen/config is the root of the monorepo dependency graph. Every package and application that needs environment variables imports from here — never reads process.env directly. This boundary keeps the schema in one place, makes misconfigured environments fail loudly at startup, and allows the loadEnv normalizer to strip the extra quoting that dev tooling adds.

.env files→ @oxagen/config→ typed env object→ every package
◈

Typed environment

A Zod schema defines every variable. Parsing happens once at import time — a missing or wrong-type value throws before any request is served.

⊹

Dev normalization

loadEnv strips the over-quoting that the Vercel dev tooling injects so the same schema works in both dev and production without branching.

◇

Zero-bloat policy

One external dep (zod), no runtime framework, no transitive graph. Sitting at the bottom of the graph means even a small dep increase fans out to every consumer.

Usage

Import the typed env object anywhere in the monorepo. The schema is validated once when the module is first loaded.

// Import the validated, typed environment object
import { env } from "@oxagen/config/env"

// All fields are typed — no string | undefined surprises
const dbUrl: string = env.DATABASE_URL
const port:  number = env.PORT
// Import the service registry
import { registry } from "@oxagen/config"

const neo4j = registry.get("neo4j")

FAQ & gotchas

▸ Why are dev env values double-quoted, and what does loadEnv do about it?

The Vercel dev CLI and some shell dotenv loaders preserve literal quote characters when they inject values into process.env. A value defined as DATABASE_URL="postgres://..." arrives as "postgres://..." (with the surrounding quotes as part of the string). loadEnv detects and strips these extra characters before handing the value to the Zod parser, so the same schema and validation path works in both development and production without any conditional logic in calling code.

▸ Why does this package have only one external dependency?

@oxagen/config sits at the very bottom of the monorepo dependency graph. Because every other package depends (directly or transitively) on it, any dependency added here fans out to the entire workspace — it bloats every install, every bundle, and every type-check. zod is the single justified exception because it provides the validated schema that is the whole point of the package. If you think you need to add a dependency here, the answer is almost certainly to add it to the package that actually uses it instead.

▸ Can I read process.env directly in a package?

No. All environment access should go through import { env } from "@oxagen/config/env". Reading process.env directly bypasses validation, produces string | undefined types everywhere, and fragments the single-schema contract that makes misconfigured deployments fail fast.
