packages/crypto · @oxagen/crypto

Envelope encryption and field-level KMS

The cryptographic foundation of the Oxagen platform. Provides envelope encryption, a swappable KMS abstraction, and a Drizzle column helper for transparent field-level encryption. Used by @oxagen/auth to encrypt OAuth tokens before persistence and by any package that needs to protect sensitive database fields.

@oxagen/crypto internal package domain: cryptography · key management import: @oxagen/crypto

What this is

@oxagen/crypto is the single place in the monorepo where cryptographic primitives are implemented. No package should roll its own encryption. The core primitive is envelope encryption: a plaintext value is encrypted with a randomly generated data key (DEK), and the DEK is wrapped by a master key managed by the KMS abstraction. The KMS backend is swappable — local, AWS KMS, or GCP Cloud KMS — without changing call sites.

plaintext→ envelope.encrypt→ DEK (random)→ KMS.wrapKey→ ciphertext blob
✦

Envelope encryption

Each value gets its own data key. Compromise of one ciphertext blob does not expose the master key or any other value.

⊞

KMS abstraction

The KMS interface is backend-agnostic. Swap the driver in config without changing any call site — local symmetric key in dev, AWS KMS in production.

⟐

Drizzle column helper

Wrap a column definition with encrypted() and the helper transparently encrypts on write and decrypts on read — no manual encrypt/decrypt at the ORM layer.

Usage

import { envelopeEncrypt, envelopeDecrypt } from "@oxagen/crypto";

// Encrypt a sensitive string before writing to the database.
const blob = await envelopeEncrypt({
  plaintext: oauthAccessToken,
  context: { purpose: "oauth-token", userId },
});
// blob: { ciphertext: string; wrappedDek: string; algorithm: string }
// Store blob as a JSON column — never store plaintext.

// Decrypt when needed (server-side, in-memory only).
const plaintext = await envelopeDecrypt({ blob, context: { purpose: "oauth-token", userId } });

The context object is bound to the ciphertext as additional authenticated data (AAD). Decryption with a mismatched context fails — this prevents a ciphertext from being replayed into a different logical context.

import { encrypted } from "@oxagen/crypto/drizzle";
import { pgTable, text, uuid } from "drizzle-orm/pg-core";

export const integrations = pgTable("integrations", {
  id:           uuid("id").primaryKey().defaultRandom(),
  userId:       uuid("user_id").notNull(),
  // accessToken is transparently encrypted on write, decrypted on read
  accessToken:  encrypted(text("access_token")),
  refreshToken: encrypted(text("refresh_token")),
});

The column type in the database is text storing the serialized ciphertext blob. The TypeScript type seen by application code is string (the plaintext). The encryption round-trip is invisible to the ORM consumer.

import { registerKmsDriver } from "@oxagen/crypto/kms";
import { localSymmetricDriver } from "@oxagen/crypto/kms";

// Register the driver once at process startup (e.g. in apps/api/src/index.ts).
// In production, swap localSymmetricDriver for the AWS KMS driver.
registerKmsDriver(localSymmetricDriver({
  masterKey: process.env.CRYPTO_MASTER_KEY!,
}));

The driver is registered once per process. All subsequent calls to envelopeEncrypt and envelopeDecrypt — including those made transitively by @oxagen/auth — use the registered driver without any additional configuration at call sites.

Encryption model

▸ Envelope encryption explained

Envelope encryption separates the key used to protect data (the data encryption key, DEK) from the key used to protect the DEK (the master key, held by the KMS). The flow for a single value:

generate DEK→ encrypt(plaintext, DEK)→ ciphertext
KMS.wrapKey(DEK)→ wrappedDek→ store {ciphertext, wrappedDek}

To decrypt: retrieve the blob, call KMS.unwrapKey(wrappedDek) to recover the DEK in memory, then decrypt the ciphertext. The plaintext and the raw DEK exist only transiently in memory — they are never written to storage.

This model means: rotating the master key requires re-wrapping the stored DEKs, not re-encrypting every value. It also means a database dump of ciphertext blobs is useless without access to the KMS. The KMS is the security boundary.

▸ KMS backends and the abstraction contract

The KMS interface requires two operations: wrapKey(plainDek: Uint8Array): Promise<string> and unwrapKey(wrappedDek: string): Promise<Uint8Array>. Any backend that satisfies this interface can be registered as the driver.

DriverUse caseNotes
localSymmetricDriverDevelopment and testWraps the DEK using a local AES-256-GCM master key from env. Not for production.
AWS KMS driverProductionUses the AWS KMS Encrypt/Decrypt API. Preferred; AWS-leaning infrastructure default.
GCP Cloud KMS driverAlternativeUses the GCP KMS API. Register as a drop-in replacement; no call-site changes needed.

The driver is registered once per process. Every subsequent encrypt/decrypt call — including those made by @oxagen/auth token encryption — uses the registered driver without additional configuration. The KMS driver choice is an infrastructure concern, not an application concern.

▸ Drizzle column helper internals

The encrypted() helper wraps a Drizzle column definition and attaches encode/decode callbacks. On write, encode calls envelopeEncrypt and serializes the blob to a JSON string stored in the text column. On read, decode deserializes and calls envelopeDecrypt, returning the plaintext string to the application.

The TypeScript type annotation on the column remains the base column's type (e.g. string) — consumers see no trace of the encryption in the type system. This is intentional: it keeps application code clean and avoids the temptation to "manually handle" the ciphertext.

Do not store the ciphertext blob anywhere other than the database column it is bound to. Each blob's AAD context is tied to the column's logical purpose; a blob moved to a different column or table will fail decryption.

FAQ & gotchas

▸ Can I store a plaintext field alongside the encrypted one as a cache?

No. The entire point of field encryption is that plaintext never persists. A plaintext cache column defeats the protection entirely. If you need to query by value, consider storing a keyed HMAC of the plaintext for equality lookups — never store the raw value.

▸ How do I rotate the master key?

Key rotation in an envelope-encryption model means re-wrapping the stored DEKs with a new master key, not re-encrypting every value. The process: introduce the new master key in the KMS, run the rotation job (reads each wrappedDek, unwraps with the old key, re-wraps with the new key, writes back), then retire the old key. The ciphertext blobs themselves are unchanged. There is no rotation job implemented yet — file a Linear ticket before attempting a manual rotation.

▸ Does the Drizzle helper work with Drizzle migrations?

Yes. The underlying database column type is text. Drizzle sees and migrates it as a plain text column. The encryption layer is applied at the application level, not at the database level. Adding encrypted() to an existing column requires a data migration to encrypt the currently-plaintext rows — never apply the helper to a column that already has unencrypted data without a migration.

▸ What algorithm is used for the DEK encryption?

AES-256-GCM for the data encryption step — authenticated encryption that protects both confidentiality and integrity. The AAD context is included in the GCM tag, so any tampering with the context or ciphertext is detected at decryption time and will throw rather than returning garbage plaintext.
