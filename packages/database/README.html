What this is

@oxagen/database is the PostgreSQL layer of Oxagen's four-store data model. It wraps Drizzle ORM, exports the full schema, a typed client, security helpers, seed utilities, and all migration tooling. Every package that needs to read or write transactional state depends on this package — it is the only place SQL is written.

Row conventions

Every row carries a UUID id (internal FK target) and a public_id (externally visible, collision-resistant). Soft-delete via deleted_at.

Security helpers

The ./security export enforces row-level access rules so consumers never construct ad-hoc permission checks.

Store boundary

⟁ What belongs in PostgreSQL

This store owns transactional state — data that must be consistent, ACID-safe, and queryable by primary key. When in doubt, ask: does this row change over time and does it represent the authoritative state of a business entity? If yes, it belongs here.

Belongs here

  • Users, organisations, memberships, invites
  • Permissions and IAM policy rows
  • Billing subscriptions, invoices, credit balances
  • Feature flags and tenant configs
  • Job metadata and scheduled task records
  • File reference rows (binary content lives in @oxagen/storage)
  • Any durable application state with CRUD semantics

Must never go here

  • Graph relationships or entity topology → @oxagen/ontology (Neo4j)
  • Append-only runtime events, logs, metrics, traces → @oxagen/telemetry (ClickHouse)
  • Binary file or object content → @oxagen/storage (Vercel Blob)
  • Agent memory or workflow execution graphs → @oxagen/ontology

Mixing stores is a hard architectural violation. If you are unsure which store a piece of data belongs to, consult the engineering policy before writing the schema.

Usage

Generate SQL migration files from the current schema, then apply them to the local Postgres instance on port 5433.

# Step 1 — generate migration SQL from schema changes
pnpm --filter @oxagen/database generate

# Step 2 — apply pending migrations to the database
pnpm --filter @oxagen/database migrate

In CI, migrate runs automatically on pull requests via the Turborepo pipeline. Never apply migrations directly to production outside of the CI gate.

Drizzle Studio opens a local browser UI to inspect and edit the database. Useful during development; never run against the production connection string.

# Spin up Drizzle Studio at http://local.drizzle.studio
pnpm --filter @oxagen/database studio

Import the typed client and schema in any server-side package or app. Never import the database client in client components or edge runtimes.

import { db } from "@oxagen/database/client"
import { users, orgs } from "@oxagen/database/schema"
import type { User, Org } from "@oxagen/database"

// Typed query — Drizzle infers the return shape from the schema
const user = await db
  .select()
  .from(users)
  .where(eq(users.publicId, publicId))
  .limit(1)

FAQ & conventions

▸ The UUID + public_id pattern

Every table carries two identifiers. The id column is a UUID used exclusively as the internal primary key and foreign-key target — it is never returned to or accepted from the outside world. The public_id column is a separate, externally-visible identifier (typically a prefixed CUID2, e.g. usr_…) that appears in URLs, API responses, and client payloads.

This split means internal row references never leak to clients, external IDs can be rotated without breaking FK integrity, and accidental UUID enumeration in public APIs is impossible by construction.

▸ Soft-delete behavior

Rows are soft-deleted by setting deleted_at to the current timestamp. Hard deletes are reserved for compliance-driven purge operations and must go through the security helpers in ./security — never issue a raw DELETE from application code.

All standard queries in @oxagen/database automatically filter WHERE deleted_at IS NULL. If you need to read deleted rows (e.g. audit export), use the explicit includeDeleted query option rather than bypassing the filter.

▸ Why does dev Postgres run on 5433 instead of 5432?

The Oxagen v1 stack runs locally on the default 5432 port. To prevent collision, the v2 local Postgres is mapped to 5433. The connection string is read from DATABASE_URL in the workspace .env.local — do not hard-code the port in application code.

▸ Can I write raw SQL queries?

Raw SQL belongs only inside drizzle-kit-generated migration files. All application queries must go through the Drizzle query builder so TypeScript can verify column names and return types at compile time. If Drizzle's query API does not cover your use case, open a discussion before reaching for db.execute(sql\`…\`).
