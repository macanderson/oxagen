apps/cli · @oxagen/cli

The terminal CLI for Oxagen

A terminal-native interface to the Oxagen platform — built with Ink (React for CLIs) and commander. Exposes the oxagen binary so operators and developers can drive the platform from the shell. This is a local tool, not a deployed web service.

binary oxagen Ink 5.2 commander 12 React 19.2 TypeScript

What this is

apps/cli is the terminal surface of the Oxagen platform. Like the API and MCP server, it exposes the platform's capabilities through a different surface — the principle is that every capability is reachable identically from MCP, API, in-app agent, and CLI. Commander parses subcommands and flags; Ink renders interactive terminal UI components using React. Configuration is shared via @oxagen/config.

terminal→ oxagen <cmd>→ commander→ Ink UI→ platform API
✦

Ink UI

Interactive terminal components are React components rendered by Ink — the same mental model as apps/app, adapted for the terminal viewport.

⇄

commander routing

Subcommands and flags are defined with commander 12. Each subcommand is a discrete module under src/commands/.

◇

Shared config

Reads platform config via @oxagen/config — API base URL, credentials, and workspace context are resolved once and shared across commands.

Install & usage

# from the monorepo root
pnpm install
pnpm --filter @oxagen/cli dev   # runs: tsx src/index.tsx

In dev mode, tsx executes src/index.tsx directly — no compile step needed. TypeScript is transpiled on the fly.

# compile TypeScript to dist/
pnpm --filter @oxagen/cli build   # tsc → dist/index.js

# the oxagen bin is now runnable via node
node dist/index.js --help

# or link globally (from apps/cli/)
npm link   # makes `oxagen` available in PATH

The package.json bin field maps oxagen → ./dist/index.js. After npm link (or publishing), oxagen is available as a global command.

# show all commands and flags
oxagen --help

# example: authenticate with the platform
oxagen auth login

# example: select a workspace
oxagen workspace select

# example: run an agent prompt
oxagen run "summarise the last 10 events"

Source layout

Directory structure

  • src/index.tsx — binary entry point; commander program definition and command wiring
  • src/commands/ — one file per top-level subcommand (e.g. auth.tsx, run.tsx)
  • src/components/ — Ink UI components (spinners, tables, prompts, error displays)
  • dist/ — compiled output from tsc; produced by pnpm build

Dependencies

The CLI is intentionally lean. Ink and commander are the only runtime additions beyond the shared config package.

Internals

▸ Config sharing via @oxagen/config

The CLI reads all platform configuration — API base URL, API key, active workspace, and user identity — from the @oxagen/config workspace package. This is the same config layer used by other packages in the monorepo. Config is resolved once at startup; commands receive a resolved config object and do not read env vars directly.

The config file location on disk follows the XDG base directory spec: ~/.config/oxagen/config.json. The oxagen auth login command writes credentials here; subsequent commands read from it.

▸ Ink and React in the terminal

Ink renders React component trees into terminal output using a custom reconciler. This means interactive elements — spinners, selection lists, progress bars, input prompts — are written as standard React components in src/components/. The same component composition patterns used in apps/app apply here: props flow down, state is local, side effects are in hooks.

The key constraint: Ink renders to a fixed terminal viewport. Components must be aware of terminal width (use useStdoutDimensions() from Ink) and avoid DOM assumptions. There are no divs — Ink's primitive is <Box> (flexbox) and <Text>.

▸ This is not a deployed web service

Unlike apps/api, apps/mcp, apps/app, and apps/website, the CLI has no Vercel deployment, no production URL, and no HTTP server. It is a local binary installed on the developer or operator's machine. It communicates with the platform by making HTTP requests to the API (apps/api) using the configured API key.
