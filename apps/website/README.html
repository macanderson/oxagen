The public brand surface

Oxagen's marketing site — a Next.js App Router application built on @oxagen/ui. At the foundations milestone it ships deliberately minimal: a statically generated hello-world surface. Brand, type, and palette are already wired; interactive features come in later milestones.

oxagen-v2-website.vercel.app Next.js 16.2.7 React 19.2 @oxagen/ui localhost :3100

What this is

apps/website is the public-facing brand surface of the Oxagen platform. It is intentionally static at this stage — no auth, no interactive agent, no backend calls. Its job is to carry the Oxagen visual identity (indigo→green gradient, Aeonik type, the design-system palette) reliably to the public web so the brand is established before product milestones ship.

Built on @oxagen/ui (the coss/Base UI component system) so every UI primitive is consistent with apps/app and the rest of the monorepo. When interactive features land they will slot into an already-branded shell with no visual debt to pay down.

◎

Static first

Statically generated at build time. No runtime Node process needed post-deploy; CDN-native by default.

◈

Brand-accurate

Consumes @oxagen/ui and the design-system tokens — palette, type, and motion are identical to the product app.

⊹

No lock-in

Vercel-ejectable. All URL and config values are isolated to env vars so the brand-domain switch is a single sweep.

Quick start

Install once at the monorepo root, then run the website target. No local database or env file is required for the static shell.

# from the monorepo root
pnpm install
pnpm --filter @oxagen/website dev   # → http://localhost:3100

Dev env values are double-quoted; loadEnv normalizes them. Never hard-code the production URL — it lives in env so the brand-domain switch is a single variable sweep.

pnpm --filter @oxagen/website build
pnpm --filter @oxagen/website start   # serves the production build on :3100

Source layout

Directory structure

  • src/app/ — App Router routes and layouts (Next.js 16 convention)
  • src/app/page.tsx — the single root page, statically rendered
  • src/app/layout.tsx — root layout, brand fonts, theme script
  • src/components/ — page-level UI components

Dependencies

The site keeps its dependency surface narrow. All shared UI is pulled from the workspace package; no additional component libraries are introduced here.

Roadmap

▸ Current status — foundations milestone

The website is intentionally a hello-world surface at this milestone. The decision is deliberate: ship the brand accurately and statically, verify the deployment pipeline end-to-end, and avoid introducing interactive complexity before the product's foundational packages (@oxagen/auth, @oxagen/agent, etc.) are stable.

There is no interactive features, no form submission, no dynamic routing, and no backend integration. This is the correct state for the foundations milestone.

▸ What will grow here

As product milestones ship, the marketing site will expand to include: a landing page with product narrative and pricing, a waitlist / early-access flow, blog / changelog content (likely MDX-driven via apps/docs patterns), and eventually SEO-optimized product pages. Each addition will be tracked as a discrete Linear ticket to preserve the one-ticket-one-PR discipline.

The current static shell means there is zero migration cost when these features arrive — routes and components simply drop in alongside the existing layout.

▸ Brand-domain switch

Until oxagen.ai is live, production deploys via oxagen-v2-website.vercel.app. All URL references live in env vars — not in source. When the brand domain is ready, the switch is a single env-var sweep in Vercel's project settings. No source changes needed.
