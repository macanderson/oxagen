03·5The sharp edge

Your agents only know
what they're allowed to know.

Oxagen resolves every retrieval against the caller's contracted capabilities before a single node leaves the store. Not filtering after the fact. Not prompt guardrails. Authorization at the graph edge itself, so an agent inherits exactly its principal's view.

EnforceDenied at the edge

Node and edge ACLs compiled from repo, team, and tenant boundaries. An allowed node can never bridge into a denied subgraph. Reachability is a permission, not an accident.

ParityAgents borrow your view

If a person can't see it, their agent can't see it. Revoke a group in Okta, and the agent's world shrinks on its next query. No restart, no re-index.

InertInjection retrieves nothing

A poisoned instruction can't widen a typed contract. The attack fires, and the graph returns only the caller's entitled surface.

Gateways govern the tool call. Oxagen governs what the model reads. That's the plane no one else occupies.

05Under the hood

Four graphs and one engine
make agents accountable.

OntologyKnowledge graph

A Neo4j ontology of your business. Agents answer from cited, time-aware nodes — not a hallucinated guess. Every claim links back to a node you can inspect.

Code graphTyped & queryable

A typed graph of your code — symbols, call edges, recent commits. Agents query it before editing instead of grepping blindly, so changes are grounded and reviewable.

Execution graphEvery run, traced

Each run is a span tree: every step, tool call, sub-agent, with duration, tokens, cost and status. This is the record an auditor asks for.

Agent engine+ Fleet mode

One engine powers chat, CLI and fan-out. Fleet mode dispatches a governed team of sub-agents — each in isolation, with lineage — under hard budget caps.

Every layer runs under the same identity, metering and audit spine — not bolted on afterward.

06Governance you can prove

The agent can't do what it
isn't entitled to do.

Identity on every action

Org, workspace and role travel with the API key. Every capability is gated — assertOrgMember, assertBillingManager, assertSecurityManager — and tenant isolation is enforced at the database with row-level security. An agent inherits least privilege, not blanket access.

Typed contracts, un-poisonable tools

Every tool is a typed capability contract with a fixed shape. A prompt-injected instruction can't invent a new tool or widen an existing one — the contract is the boundary, and it's the same boundary in the API, the MCP server and the CLI.

New · Per-turn budgeting

Just shipped: a hard cap on the tool loop per execution round, plus fan-out limits — a dispatch that would exceed 100 tasks, depth 3, or 250 descendants is rejected outright. The runaway overnight loop that produced the mystery bill simply can't happen.

SOC 2, derived from live signal

The compliance catalog isn't a PDF — controls are derived from real events: CC7.2 from security events, CC6.1/6.2 from your MFA and RLS enforcement. The audit log exports as signed NDJSON/CSV for your GRC team.

08Full auditability

Open any run. See everything
it did, in order.

The execution span tree

A run expands into its ordered steps; each step shows its tool calls with duration, tokens, cost and status, and every sub-agent it spawned as child lineage. The same view lives in the CLI as oxagen trace and in the app's Activity screen.

  • Nothing runs off the record
  • Sub-agent & A2A lineage is preserved end-to-end
  • Errors and retries are visible, not swallowed

The audit & access surface

A filterable, paginated audit log with signed NDJSON/CSV export, periodic access reviews, and session visibility — all role-gated. When security asks "what could this agent reach, and what did it touch," the answer is a query, not a fire drill.

  • Answers "who / what / when / why" for every action
  • Export is tamper-evident and GRC-ready
  • Tenant-scoped — no cross-org leakage, enforced in the DB
