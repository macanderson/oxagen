Harness engineering · Feature briefing · July 2026

Un-poisonable edits.
Anchored. Verified. Audited.

Torn and misapplied patches are the number-one silent killer of agent accuracy. As of today, every file edit an Oxagen agent makes is hash-anchored against stale reads, parsed before it lands, and recorded with a verifiable before/after anchor. Bad writes are refused by the harness, not discovered by the build.

01 The failure class

One clean-looking edit can poison a whole session.

An agent edit fails in two quiet ways, and both compound: the agent keeps stacking turns on top of a poisoned file, then spends the rest of the budget undoing its own damage.

Torn patches

The file changed on disk between the agent's read and its edit. The patch lands on the wrong version, or in the wrong place.

Silent damage

The replacement applies cleanly but breaks the syntax. Nothing notices until a build fails, many turns and many dollars later.

Contested trees

Multiple sessions, subagents, and an optimizer share one checkout. External change between turns is normal, not rare.

No accountability

Afterwards, nothing records which turn damaged the file, what it changed, or whether the breakage was intentional.

These are structural failures. The defense has to be structural too: a harness that refuses the bad write, not a prompt that asks the model to be careful.

02 Shipped today · 1 of 3

Every edit is anchored to a content hash.

Each whole-file read records a sha256 anchor in a per-run ledger. Before any mutation, the harness re-hashes the file on disk. A mismatch means the world moved: the edit is refused with a corrective message, never misapplied.

Stale-read rejection

"Stale anchor: the file changed on disk since you last read it." One re-read recovers. Nothing gets clobbered.

Chained edits stay cheap

Every successful mutation re-anchors the file, so consecutive edits need no re-read in between.

Zero model burden

The ledger is harness state. The model never manages hashes; it simply gets stopped when it is about to be wrong.

03 Shipped today · 2 of 3

New damage never lands silently.

Before a write touches disk, the harness parses the candidate content (TypeScript, TSX, JavaScript, JSON). An edit that would introduce new syntax errors is rejected with the exact diagnostics. A file that was already broken is not re-punished: only new damage gates.

Edit rejected (would introduce 1 new syntax error in src/auth.ts):
  line 42: ')' expected.
Fix the edit, or pass expect_errors:true only if this is an intentional mid-refactor breakage.
Declared, not silent
expect_errors:true is the escape hatch for legitimate "this will break until step 4" refactors. The write proceeds and the declaration is recorded in the audit trail, so intent is visible forever.
04 Shipped today · 3 of 3

One seam. Every surface inherits it.

The gates live at the single tool layer every agent run shares, the same seam that already enforces graph-backed file locks. No per-surface wiring, and no surface can opt out.

Chat agents

The in-app coding agent gets anchored, gated edits on every turn.

CLI sessions

The terminal agent runs the same tool layer, so the same physics apply.

Fleet dispatch

Every fanned-out worker edits under the same anchors and gates.

Sandboxed runs

Remote sandbox workspaces inherit the gate through the identical seam.

Plus a pluggable diagnostics port
A DiagnosticsProvider seam ships today, so a full project typechecker plugs into the same before/after delta gate next, with no new enforcement point.
05 The audit trail

Every edit leaves a verifiable record.

Each mutation event now carries its before and after anchors, its diagnostic delta, its declared-breaking flag, and its replacement count. That is the raw material of per-edit lineage: which turn touched which file, what changed, and whether it admitted breaking things.

{ type: "file-edit", path: "src/auth.ts",
  beforeHash: "9f2c41d8a03b57e6", afterHash: "b71a0cd94e22f813",
  newDiagnostics: 0, declaredBreaking: false, replacements: 2 }

Identity → permitted action → verified outcome → audit record. The accountability chain, applied per edit.

06 Where this goes next

From gated edits to governed edits.

V1.1 · weeksTypecheck delta

An incremental language service behind the diagnostics port. An edit that breaks a sibling file's types is refused at write time, not at build time.

V2 · next quarterAST transforms

rename_symbol, add_import, update_signature applied through the AST. Node anchors survive reformatting entirely; whitespace drift stops existing.

V2.2 · next quarterLineage graph

Every gated edit lands in Neo4j linked to its turn and execution. "Which turn broke this file, and did it declare it?" becomes a query.

V3 · two quartersCross-language gates

tree-sitter grammars and per-language diagnostic providers extend the same physics to Python, Go, Rust, SQL, and YAML.

V4 · the wedgeEdit as a capability contract

Metered, IAM-gated mutation: scope which paths an agent may touch, price mutation classes, and meter governed edit capacity.

07 Why we think this is important

The wedge, applied to the file system itself.

Oxagen's promise is one enforced object binding identity, permitted action, verified outcome, and audit record. Un-poisonable edits apply that chain to the most frequent thing agents do: mutating code. Models are no longer the differentiator; the harness is. Accuracy is a property of the loop.

Oxagen, todayRefused, not repaired

Every edit anchored, parsed, and recorded at a seam no surface can bypass. The bad write never happens, so nobody pays to undo it.

State of the art elsewhereAnchored, at best

Hash-anchored patching exists in the best mid-2026 harnesses. Nobody gates on a diagnostic delta, and nobody lands edits in a lineage graph.

Accuracy moat, trust moat
Fewer poisoned sessions means better outcomes per dollar (the accuracy moat). A per-edit audit chain means enterprises can prove what their agents did (the trust moat). Both compound with every phase of the roadmap.
08 The close
Torn patches: structurally impossible.
Shipped today: hash-anchored stale detection, a pre-write syntax gate with declared breakage, a pluggable diagnostics port, and a per-edit audit record, enforced at one seam for chat, CLI, fleet, and sandbox. Next: typecheck deltas, AST transforms, lineage edges, and edits as governed, billable capabilities.

The platforms that win the agent era are the ones whose loops cannot silently damage your code, and can prove it.
