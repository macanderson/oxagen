Equip a workspace with the external tools or connectors its agents need. A plugin installation belongs to that workspace. Installation, authentication, and authorization are separate decisions.

## Discover and install

Browse the [plugin catalog](/docs/plugins/marketplace) with `browse_plugin_catalog`. Inspect a result with `get_catalog_plugin` before calling `install_plugin`.

| Type | Purpose |
|---|---|
| `mcp_server` | Tools served by an external MCP endpoint |
| `integration` | Connections to third-party systems |
| `agent_capability` | Capability packs registered in the plugin catalog |
| `agent_skill` | Catalog entries for agent skills |
| `knowledge_source` | Catalog entries for context sources |

A catalog type does not imply a built-in pack ships for it. The former media and document packs are retired.

## Connect and govern

For a mediated connection, Oxagen encrypts and holds the downstream credential. An agent requests a tool, and the governed tool path decides whether it may run. Installing a plugin does not override the agent's mandate, IAM role, consent, or approval requirements.

- [Workspace plugins](/docs/plugins/workspace-plugins): authentication and enable or disable.
- [Plugin governance](/docs/governance/plugins-governance): role requirements and audit events.
- [MCP server registries](/docs/plugins/registries): catalog sources.
- [External MCP servers](/docs/mcp/external-servers): supported runtime configuration.
