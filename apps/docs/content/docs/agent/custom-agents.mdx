---
title: Agent identities
description: "Register an agent identity and manage its mandate and environment bindings."
---

Register each agent that your team operates under its own identity. Open **Agents** in a workspace to register one, inspect its enrollment, and open its mandate.

## Register from the CLI

```bash
oxagen agent register --slug review-worker --name "Review worker" --harness claude-code
oxagen agent status review-worker
```

Registration requires an organization Owner or Admin. It creates the agent identity, delegated principal, default role, and a credential shown once. Treat that credential separately from an ordinary Oxagen API key. See [API authentication](/docs/api/authentication).

The registration flow can issue a one-time enrollment token for the host. [Wrap an agent](/docs/cli/wrap-an-agent) covers installation and recording.

## Definition and mandate

The agent definition lives in `.oxagen/agents/<slug>.toml` in the workspace repository. The `commit_agent_definition` capability commits the definition. For a Claude Code, Cursor, or Stella agent it also regenerates `.claude/agents/<slug>.md` from the definition on the same branch, because those harnesses read subagents there. A Codex agent gets the definition file alone. `get_agent` returns the cached definition of record alongside identity and enrollment details.

Open the agent's mandate to inspect its authority, budget, equipment, and rules. [Agent roles](/docs/governance/agent-roles) describes the role ceiling. Registration and a definition do not start a scheduled runtime in Oxagen. Your harness runs the work.

## Environments

Bind the identity to the secret scope it needs:

```bash
oxagen agent env bind review-worker --env development --primary
oxagen agent env list review-worker
```

An environment binding is governance metadata. Without a binding, the workspace default applies. See [Environments and secrets](/docs/configuration/environments-and-secrets).
