You govern each agent your team runs under its own identity. An agent is one operator on one runtime with one harness. Your laptop running Claude Code is one agent. The same laptop running Codex is a second agent.

## Register an agent

1. Open **Runtimes** in a workspace and add a runtime. Give it a name. Oxagen derives the slug from the name: spaces become hyphens, and every other special character is dropped, so "Mac's Laptop" becomes `macs-laptop`.
2. Register the runtime's first agent. Choose a name, a harness, the runtime, and a toolbelt.
3. Run the enrollment command the page shows on the runtime's machine.

A runtime that already runs the harness you chose stays in the list, disabled. Hover over it to see which agent holds that pair. The same holds for a harness the chosen runtime already runs.

Registration requires an organization Owner or Admin. It creates the agent, its delegated principal, its default role, its first version, and a credential shown once. Treat that credential separately from an ordinary Oxagen API key. See [API authentication](/docs/api/authentication).

The enrollment command runs on the runtime's machine, so install the Oxagen app there first. It links the `oxagen` and `tacho` commands onto your PATH. [Wrap an agent](/docs/cli/wrap-an-agent) covers installation and recording.

## Toolbelt

A toolbelt is the set of tools an agent is shown. Every workspace has an **All tools** belt, which holds every tool an owner or admin made available. Clone it on the **Toolbelts** tab of **Tools**, then remove servers or turn servers and tools on or off in the clone. A toolbelt narrows what an agent can reach. Roles, mandates, and kill switches still decide each call.

When the workspace has no imported tools, the register form's toolbelt step completes itself and links to the page that imports MCP servers.

## Versions

The agent's principal, operator, and harness never change. Its runtime and its toolbelt can. Moving the agent to another runtime (`move_agent`) or giving it another toolbelt (`assign_agent_toolbelt`) writes a new agent version. The principal keeps its roles, mandates, credentials, and runs, so a hardware replacement or a cloud migration does not start the agent over.

An agent carries no prompt and no definition file. Steering records tell it what to do, and its toolbelt says what it can reach.

## Mandate

Open the agent's mandate to inspect its authority, budget, and rules. [Agent roles](/docs/governance/agent-roles) describes the role ceiling. Registration does not start a scheduled runtime in Oxagen. Your harness runs the work.

## Environments

Bind the identity to the secret scope it needs:

```bash
oxagen agent env bind review-worker --env development --primary
oxagen agent env list review-worker
```

An environment binding is governance metadata. Without a binding, the workspace default applies. See [Environments and secrets](/docs/configuration/environments-and-secrets).
