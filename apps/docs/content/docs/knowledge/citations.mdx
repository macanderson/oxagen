When a memory recall, a knowledge-graph lookup, or an `@`-mention grounds an agent's answer, Oxagen records a **citation** in the graph. The **Citations** dashboard totals those citations across every run, so you can see which knowledge carries weight, which is dead weight, and where your promoted rules are broken.

Open it at **Workspace → Knowledge → Citations**.

## What a citation records

A citation links a run to the memory or graph node it cited, and carries two judgments made at cite time:

| Axis | Values | Meaning |
|---|---|---|
| **Influence** | `DECISIVE` → `CONTRIBUTING` → `CONSIDERED` → `IGNORED` | How much the cited knowledge shaped the output. `DECISIVE` and `CONTRIBUTING` count as useful. `CONSIDERED` and `IGNORED` mean the agent recalled it, but it did not change the answer. |
| **Compliance** | `COMPLIED` / `DISCRETION` / `VIOLATION` / `NA` | For RULE and FACT memories: whether the agent followed the rule. `VIOLATION` means the agent acted against a promoted rule. |

Citations accrue on their own, and you instrument nothing. A recall made while answering records a `CONSIDERED` citation (this is the "citation pressure" that surfaces promotion candidates). An `@`-mentioned node records a `DECISIVE` one. An agent can also cite explicitly, with a full influence and compliance judgment.

## The dashboard

The period switcher (7d, 30d, or 90d) sets the window for everything on the page:

- **Totals**: citations in the window, distinct runs that cited anything, distinct memories cited, and distinct graph nodes cited.
- **Useful vs. not useful**: the influence breakdown. A healthy workspace leans toward `DECISIVE` and `CONTRIBUTING`. A large `IGNORED` share means recall surfaces knowledge nobody uses.
- **Daily series**: citations and violations per day across the window.
- **Most cited memories**: the memories that carry the most weight, each with its influence breakdown.
- **Least useful memories**: cited again and again but never `DECISIVE` or `CONTRIBUTING`. This is your cleanup queue. [Demote them](/docs/agent/memory#the-promotion-lifecycle) back to observations, retire them, or dismiss them from the promotion queue.
- **Most violated rules**: RULE and FACT memories ranked by `VIOLATION` citations. Either the rule needs stronger enforcement, or it is wrong and should be demoted.
- **Top cited nodes**: the non-memory graph entities agents rely on most. Each one shows its human label. Hover or click the chip to inspect the full property bag.

## Acting on the numbers

The dashboard closes the loop on memory quality:

1. **Promote what works.** Memories climbing "Most cited" with decisive influence are the ones the promotion-candidate queue surfaces. Promote them to RULE or FACT from the [Memory page](/docs/agent/memory#the-promotion-lifecycle).
2. **Demote what does not.** "Least useful" is a ready-made demotion list: memories the agents keep seeing and never use.
3. **Fix what is violated.** A rule that is violated often either needs its enforcement score raised (agents treat a higher score as more binding) or no longer matches reality and should be demoted or edited.

## Programmatic access

The `get_citation_stats` capability backs the dashboard, and it is on every surface:

```bash
# API
curl -X POST "https://api.oxagen.sh/v1/{org_slug}/{workspace_slug}/agent/memory/citations/stats" \
  -H "Authorization: Bearer $OXAGEN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"days": 30, "limit": 10}'

# CLI
oxagen memory citations --days 30 --limit 10
```

`days` (1 to 365, default 30) sets the window. `limit` (1 to 50, default 10) caps each top-N list. The MCP tool `get_citation_stats` takes the same input, so an agent can read its own citation quality.
