---
title: Organizations and teams
description: "Separate teams into workspaces and review agent authority, equipment, and spend."
---

Give each team a workspace for its agents, context, and tools. The organization owns membership and billing. Workspace scope keeps operational records apart.

## Organize the work

Open **Organization** at `/{org}` to manage workspaces and members. New workspaces require a main repository. The first workspace created during signup can bind its repository during onboarding.

Use **Organization → Roles** to inspect permissions. Owners and Admins can create custom roles and edit or delete custom roles. Built-in roles are read-only. The page shows whether the organization's tier enforces the displayed grants.

[RBAC and roles](/docs/governance/rbac) explains the authorization limits. [Tenant isolation](/docs/security/tenant-isolation-rls) describes the data boundary.

## Fund and inspect agent work

Use **Organization → Model funding** to configure who pays for model calls. Use **Billing** for subscription and credits, and a workspace's **Spend** page for recorded cost. [Spend budgets](/docs/cli/budget) documents the organization and workspace ceilings.

## Review evidence

Use **Organization → Audit** for security events. Open a run from Fleet to inspect its recorded work and enforcement tier. Observe-mode activity is recorded, not enforced. A hook-based record is client-attested.

[Security](/docs/security/overview) and the [SOC 2 controls mapping](/docs/security/soc2) describe implementation controls.
