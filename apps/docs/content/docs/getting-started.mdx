## Sign up

Go to [app.oxagen.sh](https://app.oxagen.sh) and click **Sign up**. Enter your name, email address, and a password.

Oxagen emails you a verification link. Click it before you sign in; an unverified account cannot get past the login screen. If the email does not arrive, check your spam folder before you request another one.

Google and GitHub sign-in are on the same screen.

Email verification is turned off when you run Oxagen on your own machine, so local development does not need a working mail server. See [Local development](/docs/configuration/local-development) and [Email & SMTP](/docs/configuration/email).

## Create your organization

After signup you land on the **New organization** screen. You need one organization before you can do anything else. The organization is the top-level boundary: it owns billing, IAM policies, and audit logs.

1. Enter an organization name. A URL-safe slug is generated automatically; you can edit it.
2. Click **Create organization**.

Creating an organization also creates a default workspace within it. You are automatically assigned the **Owner** role in both.

## Explore the app shell

After you create the organization you land at `/{orgSlug}/{workspaceSlug}/ask`, the Ask surface. The shell has three parts:

- **Org and workspace switchers** in the top bar (right of the Oxagen mark). If you belong to multiple organizations or workspaces, switch between them here.
- **Sidebar** with four workspace zones: Ask, Knowledge, Automation, and Activity. The Organization section below handles members, access (IAM), security, billing, and developer settings.
- **Ask bar**: the persistent AI entry point. Available on every screen; the agent has context about the page you are on.

## Wrap one machine

The fastest way to see your own numbers is to put a machine you already run Claude Code on under Oxagen.

```console title="Terminal"
$ oxagen login
$ oxagen tacho enroll
$ oxagen tacho status
```

`enroll` writes the hooks into Claude Code's settings, installs the collector as a user service, and enrolls the host against your workspace. From then on every run on that machine is recorded frame by frame and shipped to Oxagen; open **Activity** to read the first one. [The Oxagen app](/docs/cli/desktop) does the same from one window, and [the CLI reference](/docs/cli/commands) covers the rest of `oxagen tacho`.

## Have your first agent conversation

1. Click **Ask** in the sidebar, or use the Ask bar at the top of any page.
2. Type a message and press Enter or click Send.
3. The agent responds using the model tier available on your plan.

Every message is recorded as a conversation under `/{orgSlug}/{workspaceSlug}/ask`. Conversations persist; archive or delete them from the conversation list.

## Invite a teammate

1. Go to **Organization → Members**.
2. Click **Invite member**.
3. Enter their email address and assign a role (Owner, Admin, Billing, Compliance, or a workspace role).
4. They receive an invite email with a one-click acceptance link.

Workspace access is granted separately under **Workspace settings → Members**.

## Connect via the REST API

Every capability in the app is also reachable over the versioned REST API at `https://api.oxagen.sh/v1/`.

**Create an API key:**

1. Go to **Organization → Developer → Tokens**.
2. Click **Create API key** and give it a name.
3. Copy the key. It is shown only once.

API keys carry org and workspace scope, and act with the access of the user who created them. Pass the key as a Bearer token:

```http
Authorization: Bearer ox_…
```

**Check that the key works.** Replace `acme/main` with your org and workspace slugs. A JSON body with a `tools` array means the key is valid; a `401` means it is not.

```console title="Terminal"
$ export OXAGEN_API_KEY="ox_…"
$ curl -X POST "https://api.oxagen.sh/v1/acme/main/agent/tools" \
    -H "Authorization: Bearer $OXAGEN_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{}'
```

See [API authentication](/docs/api/authentication) for the full reference, and the [API overview](/docs/api/overview) for the same request in TypeScript and Python.

## Connect via MCP

Oxagen exposes every capability as an MCP server at `https://mcp.oxagen.sh/mcp` over streamable HTTP. The API key carries the org and workspace scope, so there is no path segment.

```bash tab="Claude Code"
claude mcp add --transport http oxagen https://mcp.oxagen.sh/mcp \
  --header "Authorization: Bearer $OXAGEN_API_KEY"
```

```jsonc tab="Claude Desktop"
// claude_desktop_config.json — bridges to the HTTP endpoint via mcp-remote
{
  "mcpServers": {
    "oxagen": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.oxagen.sh/mcp", "--header", "Authorization:${OXAGEN_AUTH_HEADER}"],
      "env": { "OXAGEN_AUTH_HEADER": "Bearer ox_…" }
    }
  }
}
```

```bash tab="Codex"
codex mcp add oxagen --url https://mcp.oxagen.sh/mcp --bearer-token-env-var OXAGEN_API_KEY
```

**Connect from the unified install page:**

Go to **Organization → Developer → MCP** for copy-ready snippets for Claude Code, Claude Desktop, and Cursor, pre-filled with your API key. [Connecting to the MCP server](/docs/mcp/connecting) covers Codex and VS Code.

See [MCP overview](/docs/mcp/overview) and [Connecting to the MCP server](/docs/mcp/connecting) for details.
