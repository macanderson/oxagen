Oxagen governs and operates the autonomous agents your organization runs: one mandate per agent, set by the teams accountable for it and enforced on every run. This page creates the organization that owns those mandates, wraps one machine so its runs land in the record, and gives you an Oxagen API key for the REST API and MCP.

## Sign up

Go to [app.oxagen.sh](https://app.oxagen.sh) and click **Sign up**. Enter your name, email address, and a password.

Oxagen emails you a verification link. Click it before you sign in. An unverified account cannot get past the login screen. If the email does not arrive, check your spam folder before you request another one.

Google and GitHub sign-in are on the same screen.

Oxagen turns email verification off when you run it on your own machine, so local development does not need a working mail server. See [Local development](/docs/configuration/local-development) and [Email & SMTP](/docs/configuration/email).

## Create your organization

After signup you land on the **New organization** screen. You need one organization before you can do anything else. The organization is the top-level boundary. It owns billing, IAM policies, and audit logs.

1. Enter an organization name. Oxagen generates a URL-safe slug, and you can edit it.
2. Click **Create organization**.

Creating an organization also creates a default workspace inside it. Oxagen assigns you the **Owner** role in both.

## Explore the app shell

After you create the organization, you land on the organization **Dashboard** at `/{orgSlug}`, the usage and metering home. The shell has three parts:

- **Org and workspace switchers** in the top bar, to the right of the Oxagen mark. If you belong to more than one organization or workspace, switch between them here.
- **Sidebar** with the workspace pages (Overview, Sessions, Knowledge, Agents, Tools, Environments, Marketplace, and Settings) and the organization pages (Dashboard, Workspaces, Members, Governance, Access, Security, Billing, Developer, and Settings).
- **Ask bar**: the entry point to the in-app agent, on every screen. The agent knows which page you are on.

## Wrap one machine

The fastest way to see your own numbers is to put a machine you already run Claude Code on under Oxagen.

```console title="Terminal"
$ oxagen login
$ oxagen tacho enroll
$ oxagen tacho status
```

`enroll` writes the hooks into Claude Code's settings, installs the collector as a user service, and enrolls the host against your workspace. From then on, Oxagen records every run on that machine frame by frame. `oxagen tacho status` shows whether the collector is shipping, and `oxagen trace` reads one run as a tree. [The Oxagen app](/docs/cli/desktop) does the same from one window, and [the CLI reference](/docs/cli/commands) covers the rest of `oxagen tacho`.

## Have your first agent conversation

1. Click **Sessions** in the sidebar, or use the Ask bar at the top of any page.
2. Type a message and press Enter or click Send.
3. The agent answers with the model tier your plan includes.

Oxagen keeps every conversation under `/{orgSlug}/{workspaceSlug}/sessions`. Conversations persist. Archive or delete them from the conversation list.

## Invite a teammate

1. Go to **Organization → Members**.
2. Click **Invite member**.
3. Enter their email address and assign a role (Owner, Admin, Billing, Compliance, or a workspace role).
4. They receive an invite email with an acceptance link.

Workspace membership is granted separately from organization membership.

## Connect via the REST API

Every capability in the app is also reachable over the versioned REST API at `https://api.oxagen.sh/v1/`.

**Create an API key:**

1. Go to **Organization → Developer → Tokens**.
2. Click **Create API key** and give it a name.
3. Copy the key. Oxagen shows it only once.

An Oxagen API key carries org and workspace scope and acts as the person who created it. It is for you, your scripts, and the MCP clients you run. It is not a credential to hand to an agent for the systems the agent reaches. Those stay in Oxagen, and the agent asks for them. Pass the key as a Bearer token:

```http
Authorization: Bearer ox_…
```

**Check that the key works.** Replace `acme/main` with your org and workspace slugs. A JSON body with a `tools` array means the key is valid. A `401` means it is not.

```console title="Terminal"
$ export OXAGEN_API_KEY="ox_…"
$ curl -X POST "https://api.oxagen.sh/v1/acme/main/agent/tools" \
    -H "Authorization: Bearer $OXAGEN_API_KEY" \
    -H "Content-Type: application/json" \
    -d '{}'
```

See [API authentication](/docs/api/authentication) for the full reference, and the [API overview](/docs/api/overview) for the same request in TypeScript and Python.

## Connect via MCP

Oxagen exposes every capability as an MCP server at `https://mcp.oxagen.sh/mcp` over streamable HTTP. The API key carries the org and workspace scope, so the URL has no path segment for them.

```bash tab="Claude Code"
claude mcp add --transport http oxagen https://mcp.oxagen.sh/mcp \
  --header "Authorization: Bearer $OXAGEN_API_KEY"
```

```jsonc tab="Claude Desktop"
// claude_desktop_config.json — bridges to the HTTP endpoint via mcp-remote
{
  "mcpServers": {
    "oxagen": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://mcp.oxagen.sh/mcp", "--header", "Authorization:${OXAGEN_AUTH_HEADER}"],
      "env": { "OXAGEN_AUTH_HEADER": "Bearer ox_…" }
    }
  }
}
```

```bash tab="Codex"
codex mcp add oxagen --url https://mcp.oxagen.sh/mcp --bearer-token-env-var OXAGEN_API_KEY
```

**Connect from the install page:**

Go to **Organization → Developer → MCP** for copy-ready snippets for Claude Code, Claude Desktop, and Cursor, pre-filled with your API key. [Connecting to the MCP server](/docs/mcp/connecting) covers Codex and VS Code.

See [MCP overview](/docs/mcp/overview) and [Connecting to the MCP server](/docs/mcp/connecting) for details.
