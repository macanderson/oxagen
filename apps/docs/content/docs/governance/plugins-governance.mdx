---
title: Plugin governance
description: How organizations control which MCP servers, integrations, and content tools agents can access.
---

Oxagen plugins extend the agent toolchain with external capabilities: MCP servers that connect to third-party APIs, data-source integrations that bring external data into the knowledge graph, and content tools that enable specialized generation workflows.

Every plugin must be explicitly approved at the organization level before any workspace can use it. This two-tier model gives security and compliance teams centralized control over the external attack surface of your AI agents.

## The two-tier governance model

```
Organization level    → admins install and maintain the org allow-list
       ↓
Workspace level       → workspace owners enable from the org allow-list
```

Plugins installed at the org level are **disabled by default** in every workspace. Workspace owners must explicitly enable a plugin for their workspace before agents in that workspace can access its tools.

This means a plugin compromise or misconfiguration is bounded to the workspaces that have explicitly enabled it — not the entire organization.

## Installing plugins at the org level

See [Plugin Marketplace](/docs/plugins/marketplace) for the full installation guide.

In summary:

1. Go to **Organization settings → Plugins → Browse marketplace**.
2. Review the plugin's tools, README, and authentication requirements.
3. Click **Install to organization**. The plugin is added to the org allow-list (disabled in all workspaces by default).
4. Org Admins can also add custom MCP servers by URL and custom plugin registries.

## The denylist

The org denylist is the hard block: any plugin on the denylist cannot be installed or enabled in any workspace under the organization, regardless of workspace preferences. Denylisted plugins are shown in the marketplace with a "Blocked" badge.

Use the denylist for:
- Known malicious or untrusted MCP servers.
- Plugins that access data types prohibited by your data classification policy.
- Plugins from vendors who have not completed your security review.

Manage the denylist at **Organization settings → Plugins → Denied plugins**.

## Enabling plugins in workspaces

Workspace Owners and Admins enable org-installed plugins at **Workspace settings → Integrations**. Plugins that require authentication show a **Connect** button (OAuth) or **Set secret** button (API key).

Plugin OAuth tokens and API keys are encrypted at rest with AES-256-GCM. If a token expires, the user who authorized it receives an in-app notification and email, and must re-authenticate.

## Disabling and uninstalling

- **Disable in a workspace:** Toggle the plugin off in **Workspace settings → Integrations**. The plugin's tools are immediately removed from the agent toolchain in that workspace.
- **Uninstall from org:** Go to **Organization settings → Plugins → Installed plugins** and click Uninstall. This immediately disables and removes the plugin from all workspaces. Existing tool call records referencing the plugin are retained in the audit log.

## Audit trail

All plugin governance actions are recorded:

- `plugin.org.install` / `plugin.org.uninstall` — org-level installation changes.
- `plugin.org.set_enabled` — org-level enable/disable toggle.
- `plugin.workspace.set_enabled` — workspace-level enable/disable toggle.
- `plugin.denylist.add` / `plugin.denylist.remove` — denylist changes.
- `plugin.credential.set_secret` / `plugin.credential.reauth` — credential changes.

These events appear in both the Postgres `security.security_events` table and the ClickHouse `audit_events` store.

## Role requirements

| Action | Required role |
|---|---|
| Browse marketplace | Any org member |
| Install or uninstall from org | Org Owner or Admin |
| Manage denylist | Org Owner or Admin |
| Add custom server or registry | Org Owner or Admin |
| Enable or disable in workspace | Workspace Owner or Admin |
| Connect OAuth or set API key | Workspace Owner or Admin |

For more information on the marketplace and workspace plugin configuration, see the [Plugin Marketplace](/docs/plugins/marketplace) and [Workspace Plugins](/docs/plugins/workspace-plugins) guides.
