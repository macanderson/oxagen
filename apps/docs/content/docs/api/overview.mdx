The Oxagen REST API serves capabilities declared for its API surface as versioned HTTP endpoints. Use it for server-to-server integrations, your own tooling, and automation pipelines that do not speak MCP.

**Base URL:** `https://api.oxagen.sh`

**Current version:** `v1`

Every endpoint sits under `/v1/`, and the version prefix is required. Workspace-scoped endpoints take the org and workspace slugs as the next two path segments:

```text
https://api.oxagen.sh/v1/{orgSlug}/{workspaceSlug}/agent/tools
                     └┬┘ └───┬───┘ └─────┬─────┘ └────┬────┘
                   version  org     workspace     capability route
```

## Your first request

List the capabilities the workspace offers as agent tools. The call only reads, and it consumes no credits.

```bash tab="curl"
curl -X POST "https://api.oxagen.sh/v1/acme/main/agent/tools" \
  -H "Authorization: Bearer $OXAGEN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "includeExternal": false }'
```

```ts tab="TypeScript"
const res = await fetch("https://api.oxagen.sh/v1/acme/main/agent/tools", {
  method: "POST",
  headers: {
    Authorization: `Bearer ${process.env.OXAGEN_API_KEY}`,
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ includeExternal: false }),
});

if (!res.ok) {
  const { error, requestId } = await res.json();
  throw new Error(`${error.code}: ${error.message} (request ${requestId})`);
}

const { tools } = await res.json();
for (const tool of tools) {
  console.log(tool.name, tool.riskLevel, tool.requiresApproval);
}
```

```python tab="Python"
import os
import httpx

res = httpx.post(
    "https://api.oxagen.sh/v1/acme/main/agent/tools",
    headers={"Authorization": f"Bearer {os.environ['OXAGEN_API_KEY']}"},
    json={"includeExternal": False},
)

if res.is_error:
    body = res.json()
    raise RuntimeError(f"{body['error']['code']}: {body['error']['message']}")

for tool in res.json()["tools"]:
    print(tool["name"], tool["riskLevel"], tool["requiresApproval"])
```

Each entry in `tools` carries `name`, `description`, `domain`, `category`, `riskLevel` (`low`, `medium`, or `high`), `requiresApproval`, and `external`.

## Design principles

**Declared surfaces.** A capability contract declares whether it is exposed on API, MCP, agent, or CLI. Shared handlers use the same kernel, but availability differs by contract. Check the declared surfaces before moving an integration.

**Thin shell, shared logic.** The API server is a thin routing layer over the shared platform library. Business logic lives in the shared layer, not in route handlers, so the API behaves the same way the app does.

**Versioned.** Every endpoint carries the `/v1/` prefix. A breaking change ships in a new version, with a window where both versions run.

**Scoped.** Each API key is scoped to exactly one org and one workspace when you create it. You do not pass `orgId` or `workspaceId` in request bodies. When a request authenticates with an API key, its scope comes from the key, not from the slugs in the path.

*Every route is a thin adapter over `invoke()`. The gates, the meter, and the audit record are the same ones the MCP server and the in-app agent pass through.*

## Authentication

[Authentication](/docs/api/authentication) has the full reference. In short:

```http
Authorization: Bearer ox_…
```

Every request needs an `Authorization` header with a Bearer token. A request without a valid token returns `401 Unauthorized`. When IAM denies the capability for the calling principal, the request returns `403 Forbidden` with a `forbidden` error code.

## Error format

Errors share one envelope. `requestId` sits beside `error`, and the `x-request-id` response header carries the same value:

```json
{
  "error": {
    "code": "forbidden",
    "message": "IAM denied \"list_agent_tools\" for principal: deny"
  },
  "requestId": "3f1c9a52-7d4e-4b8a-9c1e-2a6f0b5d8e47"
}
```

Common error codes:

| Code | HTTP status | Meaning |
|---|---|---|
| `unauthorized` | 401 | Missing, malformed, invalid, or expired token |
| `forbidden` | 403 | IAM denied the capability, or the capability is not on the API surface |
| `pending_approval` | 403 | The rule requires approval. Oxagen recorded an access request (`accessRequestId` is included) |
| `insufficient_credits` | 402 | The org has zero credit balance |
| `billing_suspended` | 402 | The org subscription is suspended |
| `budget_exceeded` | 402 | A spend ceiling was reached |
| `not_found` | 404 | The resource or capability does not exist, or is outside the token's scope |
| `validation_error` | 400 | The request body failed schema validation (`details` lists the issues) |
| `bad_request` | 400 | The capability rejected the input |
| `internal_error` | 500 | Unexpected server error. Include `requestId` in support tickets |

A rate-limited request is the one exception to the envelope. It returns `429` with the body `{ "error": "rate_limited" }` and a `Retry-After` header in seconds.

## Capabilities and parity

[Capabilities](/docs/api/capabilities) lists the available capabilities and their REST routes.

Some flows also require a browser redirect or an approval interaction. Consult the operation's route and contract before assuming it can run unattended.

## Rate limits

The API enforces rate limits. Past a limit, the response is `429 Too Many Requests` with `Retry-After`, `X-RateLimit-Limit`, `X-RateLimit-Remaining`, and `X-RateLimit-Reset` headers. Oxagen does not publish per-plan limits. Contact support if you hit sustained rate limiting.

## Streaming

The chat endpoint (`/v1/{orgSlug}/{workspaceSlug}/chat/stream`) returns a `text/event-stream` (SSE) response instead of a JSON body. [Chat streaming](/docs/api/chat-streaming) describes the event format.
