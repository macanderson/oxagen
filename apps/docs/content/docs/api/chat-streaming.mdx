---
title: Chat streaming
description: "How to read the chat SSE stream: event types, request fields, and connection handling."
---

The chat capability (`send_message`) streams its response as Server-Sent Events (SSE). The in-app agent reads this same stream. There is no separate streaming API.

## Endpoint

```
POST https://api.oxagen.sh/v1/{orgSlug}/{workspaceSlug}/chat/stream
```

The API key's scope decides the org and workspace. You still include the slugs in the URL path.

## Request

```http
POST /v1/acme-corp/engineering/chat/stream
Authorization: Bearer ox_…
Content-Type: application/json

{
  "content": "Summarize the last 10 agent runs and identify any failures.",
  "conversationId": "uuid"
}
```

| Field | Type | Required | Description |
|---|---|---|---|
| `content` | string | Yes | The message text you send. |
| `conversationId` | string | No | Existing conversation to continue. Omit it to start a new conversation. |
| `activeServerIds` | string[] | No | MCP server IDs to turn on for this turn. Omit it or pass `[]` to load every workspace server. |
| `tier` | string | No | Model tier override: `"fast"`, `"balanced"`, or `"precise"`. Omit it to use workspace defaults. |
| `model` | string | No | Explicit model ID override. Omit it to use workspace defaults. |
| `effort` | string | No | Reasoning effort override: `"low"`, `"medium"`, or `"high"`. Omit it to use workspace defaults. |

## Response

The response has `Content-Type: text/event-stream`. Each event is a JSON object preceded by `data: ` and followed by a blank line.

```
data: {"type":"text","text":"Here are the last 10 agent runs:"}

data: {"type":"tool-call-start","toolCallId":"uuid","capability":"list_agent_tools","inputPreview":{},"riskLevel":"low"}

data: {"type":"tool-call-end","toolCallId":"uuid","status":"completed","output":{"tools":[...]},"durationMs":142}

data: {"type":"usage","usage":{"promptTokens":1240,"completionTokens":312,"totalTokens":1552}}

event: done
data: [DONE]
```

## Event types

| Type | Fields | Description |
|---|---|---|
| `text` | `text` | A chunk of streamed assistant text. Concatenate chunks in order. |
| `reasoning-start` | `reasoningId` | Start of a reasoning block (sent for models with extended thinking). |
| `reasoning-delta` | `reasoningId`, `text` | A chunk of reasoning text. |
| `reasoning-end` | `reasoningId`, `durationMs` | The reasoning block is complete. |
| `step-start` | `stepIndex` | The agent is starting a new step: a model call or a tool call. |
| `step-finish` | `stepIndex` | The step is complete. |
| `tool-input-start` | `toolCallId`, `capability` | The model is streaming tool input, before the tool call runs. |
| `tool-input-delta` | `toolCallId`, `delta` | A chunk of tool-input text. |
| `tool-call-start` | `toolCallId`, `capability`, `inputPreview`, `riskLevel` | The tool call is about to run. |
| `tool-call-end` | `toolCallId`, `status`, `durationMs`, `output?`, `errorReason?` | The tool call finished. `status` is `"completed"` or `"failed"`. |
| `approval-required` | `approvalId`, `capability`, `inputPreview`, `riskLevel`, `expiresAt` | The rule routed the request to a person, and the turn waits for the answer. Answer it with `resolve_approval`. |
| `usage` | `usage.promptTokens`, `usage.completionTokens`, `usage.totalTokens` | Token totals for the turn, sent after the model call finishes. |
| `budget-notice` | `state`, `costUsd`, `limitUsd`, `mode` | The turn reached its per-turn budget. `state` is `"within_grace"` or `"stopped"`. Sent only when a per-turn budget is set. |
| `error` | `message` | Something failed. The stream closes after this event. |

The stream ends with a named SSE event, not a JSON object:

```
event: done
data: [DONE]
```

## Handling approval events

When the stream sends `approval-required`, the turn pauses. The event carries `approvalId`, `capability`, `inputPreview`, `riskLevel`, and `expiresAt`. Answer the request with a separate API call:

```http
POST /v1/{orgSlug}/{workspaceSlug}/agent/approvals/resolve
Authorization: Bearer ox_…
Content-Type: application/json

{
  "approvalId": "uuid",
  "decision": "approved"
}
```

The stream resumes once the request is answered. `decision` is `"approved"` or `"denied"`. You can also send an optional `note` string.

## Message threading

Pass `conversationId` to continue an existing thread. The route loads the conversation's history for you, so you do not pass message IDs to keep it. The model reads up to the last 50 messages word for word. When a thread grows past that, Oxagen summarises the older messages into one note and sends it ahead of them, so facts from early in the thread still reach the model. The summary is stored with the conversation and rewritten about once every five turns. The run for each turn records whether it carried a summary.

Omit `conversationId` to start a new conversation. Keep the conversation ID from the first response and send it with later messages in the same thread.

## Token usage

The stream sends the `usage` event after the model call completes. It holds the token counts for the turn under a `usage` object:

| Field | Description |
|---|---|
| `promptTokens` | Input tokens sent to the model |
| `completionTokens` | Output tokens generated |
| `totalTokens` | Sum of prompt and completion tokens |

## Error handling

Stream errors arrive as `error` events:

```
data: {"type":"error","message":"Model provider returned an error"}
```

The stream closes after an `error` event. Send the next message with the same `conversationId` to continue the conversation.

## Connection management

SSE connections stay open for the length of the turn. If your HTTP client enforces a short timeout, set it to at least 120 seconds so a turn with many steps can finish. The response sets the `connection: keep-alive` HTTP header. The stream sends no periodic SSE heartbeat comment.
