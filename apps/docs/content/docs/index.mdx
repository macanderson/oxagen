## Where you are

Your team runs coding agents in terminals today. Each one holds a key, acts as whoever installed it, and reports done when it decides it is done. Afterward, nobody can say what it read, what it changed, or what it cost.

## What Oxagen does

Oxagen sits beside the agents you already run. It does not run them and it does not replace them. Claude Code, Codex, SDK agents, and agents you wrote yourself keep working the way they work today.

### Wrap

`oxagen tacho enroll` installs hooks in Claude Code and Codex on one machine. From then on, every run on that machine is recorded as a hash-chained sequence of frames and shipped to your workspace: what the agent was told, every tool call, every model call, every decision. The hooks answer in under 50 milliseconds and keep answering if the collector is down. See [the Oxagen app](/docs/cli/desktop) and [the CLI](/docs/cli).

### Govern

Every agent has an identity, a role, and a budget. Every capability, whether a model call, a tool call, or a memory write, passes one `invoke()` boundary that checks identity, role, budget, and entitlement before the handler runs, then writes the audit record. There is no second path, so a new integration cannot skip it by accident. See [governance and RBAC](/docs/governance/overview).

*The order `invoke()` runs in. Every gate sits before the handler, so a refused call never touches data, and both outcomes leave an audit record.*

### Record

Every run is saved next to the data it touched: who asked, what the agent read, what it changed, and what it cost. Two audit stores hold it, one in Postgres with seven-year retention and one in ClickHouse with chain-hash tamper evidence. See [audit logging](/docs/security/audit-logging).

### Spend

Every model call and tool call is priced by token class and attributed to an operator, an agent, a run, a turn, and a step. Hard ceilings per organization and per workspace stop a run between steps, never mid-tool. See [billing](/docs/billing) and [budgets](/docs/cli/budget).

### Ground

A typed knowledge graph hands an agent your company's facts and rules at run time, scoped to what the caller may see, with a citation on every answer. See [the knowledge graph](/docs/knowledge).

### Remember

What a run learned is written back as memory the next run reads, with a count of how often each memory fired and what it cost. See [agent memory](/docs/agent/memory).

## One capability model, three surfaces

Every capability is declared once in the contract registry and exposed identically across the REST API (`/v1/…`), the MCP server (streamable HTTP at `/mcp`), and the in-app agent. Running a compliance check, firing an automation, or writing agent memory produces the same audit record whichever surface the action came from.

## Built for the security review

### Tenant isolation with row-level security

Every row in every tenant-scoped table carries `org_id` and `workspace_id`, and Postgres row-level security is enforced by the database itself, not by application predicates a developer might forget. The `oxagen_app` role has no `BYPASSRLS` privilege. A query without an active tenant scope returns zero rows.

The same rule holds in Neo4j (a scoped session guard), ClickHouse (org-scoped inserts and selects), and blob storage (access-controlled asset routes). See [tenant isolation](/docs/security/tenant-isolation-rls).

### SOC 2 controls

The Trust Service Criteria are architectural requirements, not a retrofit:

- **CC6 (access control):** role-based IAM with org roles (Owner, Admin, Compliance, Billing) and workspace roles (Owner, Member, Viewer), resolved per capability at the `invoke()` boundary, recorded access requests for approval-gated capabilities, member access reviews, and force-revoke on any login session.
- **CC7 (monitoring):** two independent audit stores covering 40 typed event kinds from every auth, billing, and capability call.
- **CC8 (change management):** versioned migrations, expand-then-contract schema changes, CI-gated deploys.
- **CC9 (risk mitigation):** Oxagen governs agents and does not run them, so there is no first-party agent runtime to compromise. Capabilities with a high blast radius need explicit approval before they run.

See [the SOC 2 controls mapping](/docs/security/soc2).
