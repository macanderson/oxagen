## Encryption at rest

Oxagen encrypts every store at rest:

| Store | Encryption | Key management |
|---|---|---|
| Postgres (Aurora PostgreSQL) | Aurora storage encryption | AWS KMS |
| Neo4j and ClickHouse | Encrypted EBS volumes on the application host | AWS KMS |
| Blob storage (binary assets) | Server-side encryption | Provider-managed |

Oxagen also encrypts plugin OAuth tokens and API key secrets at the application layer with AES-256-GCM before writing them to Postgres. The encryption key lives in AWS (KMS and Parameter Store), not in the database or in code.

## Encryption in transit

Client connections to Oxagen services use TLS 1.2 or higher, terminated by Caddy on the application host. Neo4j and ClickHouse listen on the host's loopback interface only, and the security group opens nothing to them. Postgres runs on a separate Aurora cluster that admits connections from the application host only.

## Data residency

Oxagen runs in AWS `us-east-1` (US East):

| Service | Region |
|---|---|
| Application host (API, app, MCP server, docs) | AWS `us-east-1` |
| Postgres (Aurora PostgreSQL) | AWS `us-east-1` |
| Neo4j and ClickHouse (on the application host) | AWS `us-east-1` |
| Blob storage | US region |

Customer data does not leave the United States in normal operation. If a workspace connects an external MCP server, that server's own data handling policies govern the data sent to it. Oxagen does not control or log the payloads sent to external servers.

## Data classification

Oxagen handles four categories of customer data:

- **Identity data:** account profiles, email addresses, and authentication credentials. Stored in Postgres `auth.*` tables. Never written to ClickHouse. Never included in agent prompts.
- **Operational data:** conversations, agent runs, memories, tool calls, and file uploads. Stored in Postgres with tenant-scoped RLS, and in Neo4j for graph relationships.
- **Telemetry:** token usage, run latency, tool call counts, and audit events. Stored in ClickHouse (append-only). Never contains message content.
- **Billing data:** subscription status, credit balances, and payment method tokens. Stripe manages it. Oxagen stores only Stripe-issued identifiers, not raw card data.

## Retention

| Data type | Retention policy |
|---|---|
| Security audit events (Postgres) | 7 years, monthly RANGE partitions |
| Audit events (ClickHouse) | 7-year TTL |
| Conversations and messages | Kept until the person or org deletes them. Soft-delete with a 30-day recovery window. |
| Token usage telemetry | Kept for the life of the organization, and exportable |
| Credit ledger | Permanent (append-only financial record) |
| Binary assets | Kept until deleted. Hard-delete is immediate. |

You can export all of your personal data (conversations, profile, and audit events scoped to your account) from **Account → Privacy → Export data**. Oxagen generates the export as a signed download link, valid for 7 days.

You can request account deletion from **Account → Privacy → Delete personal data**. Oxagen keeps a 30-day soft-delete window. On hard-delete, Oxagen removes PII and anonymizes audit events to `<deleted-user>`, keeping a stable hash for referential integrity.

## Sub-processors

Oxagen uses these sub-processors:

| Sub-processor | Purpose | Data categories |
|---|---|---|
| **Amazon Web Services** | Compute, Postgres (Aurora), the host that runs Neo4j and ClickHouse, and secrets (Parameter Store and KMS) | All categories (primary infrastructure) |
| **Model gateway (OpenRouter or Vercel AI Gateway)** | Model inference | Messages and system prompts sent to a model |
| **Stripe** | Payment processing and subscription management | Billing |
| **Inngest** | Background job orchestration | Job payloads (org and workspace IDs, capability names) |

DPAs are available on request for all primary sub-processors. Contact privacy@oxagen.sh.

## Model providers and AI inference

All model inference routes through a model gateway (OpenRouter or the Vercel AI Gateway). The Oxagen codebase holds no direct Anthropic or OpenAI keys, because the gateway handles provider authentication. An organization can store its own gateway key instead. See [Model governance](/docs/governance/byok-and-models).

An inference request contains your message and the agent's system prompt. It does not contain passwords, API keys, raw payment data, or other secrets. The model providers' data handling policies apply to the content of inference requests.

Model training opt-out is on by default for every account (see **Account → Privacy → Consent settings**).

## Data processing agreements

Oxagen offers a Data Processing Agreement (DPA) for customers subject to GDPR, HIPAA, or other regulatory requirements. Contact hello@oxagen.sh to start a DPA.
