title: Tenant isolation and row-level security
description: How Oxagen enforces tenant isolation at the database layer across Postgres, Neo4j, and ClickHouse.

Oxagen enforces tenant isolation in the database, not by application convention. A developer writing a new handler does not need to remember `WHERE org_id = $orgId`. The database returns zero rows if the tenant scope is missing or wrong. That is the SOC 2 argument: the infrastructure enforces isolation once, and it does not depend on every future developer doing the right thing.

## The design: one seam, three enforcers

All three data stores share one identity seam (`@oxagen/tenancy`). Oxagen enters the seam once, inside `kernel.invoke()`, and `AsyncLocalStorage` carries the scope to every data accessor downstream. No function signature threads tenant IDs by hand.

*One seam, entered once inside `kernel.invoke()`, carries tenant scope to all three stores. No tenant ID is threaded by hand.*

`runInTenantScope` checks that both `orgId` and `workspaceId` are valid UUIDs before it enters scope. An empty or missing ID throws a `TenantScopeError` immediately. The seam **fails closed, not open**.

## Postgres: the hard wall

Every tenant-scoped table uses `ENABLE ROW LEVEL SECURITY` plus `FORCE ROW LEVEL SECURITY`. `FORCE` subjects the table owner to the policy as well, which closes the owner bypass that makes standard RLS insufficient for multi-tenant isolation.

The platform connects as a non-superuser role (`oxagen_app`) with the `NOSUPERUSER` and `NOBYPASSRLS` attributes. At startup, the application checks that the connected role cannot bypass RLS. If it can, and `TENANT_RLS_ENFORCEMENT_ENABLED=true`, the service refuses to start.

The policy template for every standard tenant-scoped table:

```sql
CREATE POLICY tenant_isolation ON agent.agents
  USING (
    current_setting('app.rls_bypass', true) = 'on'
    OR (
      org_id       = nullif(current_setting('app.current_org_id',       true), '')::uuid
      AND workspace_id = nullif(current_setting('app.current_workspace_id', true), '')::uuid
    )
  )
  WITH CHECK ( … same … );
```

The `nullif(current_setting(…, true), '')::uuid` expression fails closed on purpose. If the GUC is unset or empty, the expression evaluates to `NULL`, `col = NULL` is `NULL`, and Postgres excludes the row. An unscoped query returns no rows, not all rows.

`withTenantDb` sets the two GUCs inside a transaction before it runs the caller's queries:

```ts
await tx.execute(
  sql`select set_config('app.current_org_id', ${orgId}, true),
             set_config('app.current_workspace_id', ${workspaceId}, true)`
);
```

`SET LOCAL` scopes the GUC to the transaction, so it is safe with connection poolers in transaction mode.

### Policy classes

| Table class | Policy predicate | Examples |
|---|---|---|
| Standard owned | `org_id = GUC.org AND workspace_id = GUC.ws` | `agent.agents`, `chat.conversations`, `mcp.mcp_servers` |
| Workspace-nullable | `org_id = GUC.org AND (workspace_id IS NULL OR workspace_id = GUC.ws)` | `iam.principals`, `security.security_events` |
| Org-only | `org_id = GUC.org` | `billing.*`, `org.org_users`, `workspace.workspaces` |
| Workspace-only | `workspace_id = GUC.ws` (no `org_id` column) | `workspace.workspace_users` |
| Standard-or-builtin | `org_id = GUC.org AND workspace_id = GUC.ws`, or nil-UUID sentinel rows (platform builtins readable by all tenants) | `agent.skills`, `agent.skill_versions` |
| Global identity | No policy (Better Auth managed) | `auth.users`, `auth.sessions` |

The RLS manifest (`packages/database/src/tenant-policy.manifest.ts`) covers 77 tables. The count grows as tables are added, and the manifest file is the authoritative reference. A CI test asserts that every `orgScopeMixin` table has a manifest entry, so a new table without a policy fails CI before it ships.

### Enforcement flag

RLS ships with a server-side bypass GUC (`app.rls_bypass`) that the `TENANT_RLS_ENFORCEMENT_ENABLED` environment variable controls. When the flag is `false`, `withTenantDb` sets the bypass GUC and RLS policies allow all rows. Manual `WHERE` predicates stay active as the enforcement layer. When the flag is `true`, `withTenantDb` does not set the bypass, and the policies enforce at the database layer. Production has run with the flag set to `true` since 2026-06-06.

The cutover is reversible. Flip the environment variable, with no schema migration.

## Neo4j: seam wall

Neo4j has no native row-level security. Oxagen enforces isolation at the one query seam. `scopedSession()` wraps the Neo4j driver and does two things:

1. It injects `$orgId` and `$workspaceId` parameters into every Cypher query.
2. It rejects any query run over the seam that does not reference `$orgId`. The rejection is a `TenantScopeError` at the call site, before the query reaches Neo4j.

An ESLint `no-restricted-imports` rule and a CI guard test ban raw `session()` calls outside the seam package.

## ClickHouse: seam wall

ClickHouse holds append-only telemetry and is never a source of truth in the four-store data model. `chInsert` and `chSelect` enforce scope at the seam:

- **Inserts** stamp `org_id` and `workspace_id` from the active scope before writing.
- **Selects** must reference `org_id = {orgId:UUID}`. A guard rejects any select that does not bind the org scope parameter.

## What this means for a SOC 2 audit

One integration test suite shows the isolation holds. The suite seeds two organizations (A and B) with data. It then runs deliberately unfiltered `SELECT * FROM <table>` queries under each org's tenant scope and asserts that the other org's rows never come back. The suite covers every table policy class and the fail-closed case (no scope set, zero rows).

This is the artifact you point your auditor to: one integration test suite, one migration file defining all policies, and one enforcement flag. Your auditor can read the migration and run the test.
