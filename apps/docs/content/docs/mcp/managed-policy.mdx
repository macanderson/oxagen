---
title: Managed policy
description: Organization-level control over which MCP servers and tools are allowed — for enterprise governance.
---

Managed policies let organization admins control which external MCP servers a workspace may connect and which tools are allowed or blocked. This is the enterprise governance layer, and it cannot be widened by a workspace's own settings.

## How it works

The policy is published once for the organization and evaluated by the runtime on every server registration and every tool materialization. It acts as an **unoverridable floor**: a workspace can tighten it, never loosen it.

## Policy structure

```json
{
  "mcpServers": {
    "company-jira": {
      "transport": "streamable-http",
      "url": "https://mcp.internal.acme.com/jira",
      "auth": "oauth",
      "managed": true
    }
  },

  "managedPolicy": {
    "allowedServerUrls": [
      "https://api.githubcopilot.com/mcp/",
      "https://mcp.linear.app/**",
      "https://mcp.internal.acme.com/**"
    ],
    "deniedServerUrls": [
      "http://**"
    ],
    "deniedTools": [
      "*.delete_*",
      "*.drop_*",
      "*.rm_rf"
    ]
  }
}
```

## Policy rules

### Server URL allowlist

When `allowedServerUrls` is non-empty, **only** URLs matching at least one pattern can be registered. All others are blocked.

```json
{
  "allowedServerUrls": [
    "https://api.githubcopilot.com/mcp/",
    "https://mcp.linear.app/**",
    "https://mcp.internal.acme.com/**"
  ]
}
```

Registering a server outside the list fails with an explicit refusal:

```
Blocked by organization policy: URL "https://random-server.com/mcp" is not in the allowed server list. Contact your admin.
```

### Server URL denylist

URLs matching `deniedServerUrls` are always blocked, even if they match the allowlist:

```json
{
  "deniedServerUrls": [
    "http://**"
  ]
}
```

This blocks all non-TLS servers — a common enterprise requirement.

### Tool denylist

Blocks specific tools across all servers. Patterns are matched against both the tool name alone and the qualified `serverName.toolName` form:

```json
{
  "deniedTools": [
    "*.delete_*",
    "*.drop_*",
    "*.truncate_*",
    "internal-api.admin_*"
  ]
}
```

Denied tools are filtered out before they reach the model. They never appear in the tool list.

## Managed servers

Org-provisioned servers in the `mcpServers` section (with `"managed": true`) are:

- Automatically available in every workspace
- Cannot be removed by workspace members
- Cannot have their auth overridden by workspace settings
- Cannot be disabled by workspace members

This ensures critical integrations (internal tools, company Jira, etc.) are always available and correctly configured.

## Enforcement points

| Action | Enforcement |
|--------|-------------|
| Registering a server | URL checked against allowlist/denylist |
| Tool materialization | Tools checked against `deniedTools` |
| Removing a server | Blocked for managed servers |
| Auth override | Blocked for managed servers |

## For org admins

Managed policies are configured in the platform at **Organization → Governance → MCP Policy**. Publishing a change takes effect for every workspace in the organization on its next server registration or tool materialization.

To set up a managed policy:

1. Define allowed server URLs (or leave empty to allow all)
2. Add any denied URL patterns (e.g. `http://**` for TLS-only)
3. Add denied tool patterns for dangerous operations
4. Optionally provision managed servers that all workspaces receive
5. Publish the policy
