---
title: Managed policy
description: Org-level rules for which MCP servers a machine may connect and which tools stay denied, which no user, project, or local setting can override.
---

A managed policy lets org admins decide which external MCP servers a developer's machine may connect and which tools are allowed or denied. No user, project, or local setting can override it.

## How it works

The managed config lives at `~/.config/oxagen/managed.json`. Its rules are a floor: they take precedence over every user, project, and local setting. The runtime reads the file before it connects to any file-configured server.

## Managed config structure

```json
{
  "_managed": true,
  "_orgId": "org_abc123",
  "_syncedAt": "2026-06-25T10:00:00Z",

  "mcpServers": {
    "company-jira": {
      "transport": "streamable-http",
      "url": "https://mcp.internal.acme.com/jira",
      "auth": "oauth",
      "managed": true
    }
  },

  "managedPolicy": {
    "allowedServerUrls": [
      "https://api.githubcopilot.com/mcp/",
      "https://mcp.linear.app/**",
      "https://mcp.internal.acme.com/**"
    ],
    "allowedCommands": [
      "npx -y @modelcontextprotocol/*",
      "npx -y @anthropic/*"
    ],
    "deniedServerUrls": [
      "http://**"
    ],
    "deniedTools": [
      "*.delete_*",
      "*.drop_*",
      "*.rm_rf"
    ]
  }
}
```

## Policy rules

### Server URL allowlist

When `allowedServerUrls` is non-empty, the runtime connects **only** to URLs that match at least one pattern. It refuses every other URL.

```json
{
  "allowedServerUrls": [
    "https://api.githubcopilot.com/mcp/",
    "https://mcp.linear.app/**",
    "https://mcp.internal.acme.com/**"
  ]
}
```

A server outside the list is refused before the runtime spawns a process or sends a request, with a message like this:

```
Blocked by organization policy: URL "https://random-server.com/mcp" is not in the allowed server list. Contact your admin.
```

### Server URL denylist

The runtime refuses URLs that match `deniedServerUrls`, even when they also match the allowlist:

```json
{
  "deniedServerUrls": [
    "http://**"
  ]
}
```

This refuses every non-TLS server, a common enterprise requirement.

### Command allowlist (for stdio)

Sets which local commands the runtime may spawn as stdio MCP servers:

```json
{
  "allowedCommands": [
    "npx -y @modelcontextprotocol/*",
    "npx -y @anthropic/*",
    "docker run acme-registry.internal/*"
  ]
}
```

### Tool denylist

Denies specific tools across all servers. The runtime matches each pattern against the tool name alone and against the qualified `serverName.toolName` form:

```json
{
  "deniedTools": [
    "*.delete_*",
    "*.drop_*",
    "*.truncate_*",
    "internal-api.admin_*"
  ]
}
```

The runtime drops denied tools before they reach the model. They never appear in the tool list.

## Managed servers

Org-provisioned servers in the `mcpServers` section (with `"managed": true`) are:

- Available in every workspace
- Not removable from user, project, or local settings
- Not open to an auth override from local settings
- Not disableable from user, project, or local settings

An internal tool, such as the company Jira, stays available and configured the same way on every machine.

## Enforcement points

| Action | Enforcement |
|--------|-------------|
| Server connection | URL or command checked against the allowlist and denylist before the runtime connects |
| Tool materialization | Tools checked against `deniedTools` |
| Removing a managed server | Blocked |
| Auth override | Blocked for managed servers |

## Distributing the policy

The runtime reads the file from each machine. The retired `oxagen mcp` command group no longer syncs it, and `oxagen login` does not write it, so place the file on each machine with your device management tooling. The `_syncedAt` field records when the file was last written:

```bash
cat ~/.config/oxagen/managed.json | jq '._syncedAt'
```

## For org admins

To write a managed policy:

1. Define allowed server URLs (or leave the list empty to allow all)
2. Add any denied URL patterns (e.g. `http://**` for TLS only)
3. Add denied tool patterns for destructive operations
4. Optionally provision managed servers that every member receives
5. Place the file at `~/.config/oxagen/managed.json` on each member's machine

A machine enforces the new rules the next time the runtime reads the file.
