The Oxagen MCP server puts the Oxagen capability set in front of any MCP client: Claude Code, Cursor, Claude Desktop, Codex, VS Code, ChatGPT, and Windsurf. Every tool call passes the same `invoke()` kernel as the in-app agent, so a rule answers each call and the record keeps the answer.

**MCP server URL:** `https://mcp.oxagen.sh/mcp`

**Transport:** Streamable HTTP (the current MCP standard). SSE is not used.

## What the MCP server provides

Every capability declared with `surfaces: ['mcp']` in the contract registry is an MCP tool. That includes agent memory recall and write, conversation management, asset upload, and plugin management.

The kernel answers a tool call when the call is made, not when the client fetches the list. When the caller's role does not allow a tool, the `invoke()` kernel denies the call and records a `capability.invoke_denied` event.

## Connect a client

The server speaks streamable HTTP, so any client that accepts a remote MCP URL and a custom header can connect. Replace the key placeholder with an Oxagen API key from **Organization → Developer → Tokens**. The key identifies you and your workspace to Oxagen. It is not a credential for any system an agent reaches.

```bash tab="Claude Code"
claude mcp add --transport http oxagen https://mcp.oxagen.sh/mcp \
  --header "Authorization: Bearer $OXAGEN_API_KEY"
```

```jsonc tab="Cursor"
// ~/.cursor/mcp.json
{
  "mcpServers": {
    "oxagen": {
      "url": "https://mcp.oxagen.sh/mcp",
      "headers": { "Authorization": "Bearer <your-api-key>" }
    }
  }
}
```

```jsonc tab="VS Code"
// settings.json
{
  "mcp": {
    "servers": {
      "oxagen": {
        "type": "http",
        "url": "https://mcp.oxagen.sh/mcp",
        "headers": { "Authorization": "Bearer <your-api-key>" }
      }
    }
  }
}
```

## Authentication and scoping

The MCP server accepts an Oxagen API key and nothing else. The key sets three things:

- The organization every call belongs to
- The workspace every call runs in
- Whose IAM grants answer each call: the person who created the key

The URL carries no org or workspace segment. The key carries the scope.

*The server refuses an app sign-in token before any tool runs. Only an Oxagen API key carries the org and workspace a tool call runs in.*

## The record

Every tool call through the MCP server passes the same `invoke()` kernel boundary as API and in-app calls:

- Every call leaves a `capability.invoke_allowed` or `capability.invoke_denied` security event in both audit stores.
- The kernel meters token usage and debits it from the org's credit balance.

The record shows who called which tool, when, from which surface, and which answer the call got.

## Parity with the REST API

The MCP tool list mirrors the REST API capability list. A capability that declares `surfaces: ['api', 'mcp']` is both an API route and an MCP tool.

See [Tools](/docs/mcp/tools) for the current tool list and any known parity gaps.

The unified install page at **Organization → Developer → MCP** writes a copy-ready snippet for every supported MCP client, filled in with your API key.
