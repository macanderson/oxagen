## Tool naming

An MCP tool has the name of the capability behind it, with no translation step. The capability `recall_memory` is the tool `recall_memory`.

Capability names are verb-first snake_case: an imperative verb, then the thing it acts on, joined by underscores. See [Capability naming](/docs/api/capabilities#capability-naming) for the full rule. These names contain no dots, so they are already legal MCP tool names, and what you call is exactly what the contract registry declares.

## Available tools

Ask the connected server for `tools/list` to read the available names and input schemas. A contract's `surfaces` field determines exposure, and authorization still applies when a tool is called.

See [Capabilities](/docs/api/capabilities) for the registry and route conventions. Machine-purpose keys can be narrower than the server catalog. See [Authentication](/docs/api/authentication).

## Parity model

The contract registry builds the tool list, the same registry that builds the REST API. A capability that declares `mcp` in its `surfaces` array becomes a tool. One that does not is left out. Nobody keeps the two surfaces in sync by hand: the registry is the only list.
