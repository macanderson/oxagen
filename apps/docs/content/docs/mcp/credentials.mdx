---
title: Credentials
description: Where external MCP server credentials are held, how the runtime resolves them, and how they are refreshed.
---

An external MCP server that requires authentication needs a credential: a bearer token, an API key, or an OAuth token. The runtime resolves the credential from several sources, so no secret has to be committed to version control. On the platform runtime, the credential stays in Oxagen, and Oxagen uses it to make the connection on the agent's behalf. The agent never sees it.

## Resolution order

When the runtime needs a credential for a server, it checks these sources in order, and the first match wins:

1. **Environment variable**: the `envToken` field names a variable that holds the token
2. **Credential file**: stored at `~/.config/oxagen/credentials/<server-name>.json`
3. **Remote API**: fetches the workspace's encrypted credential from the platform (requires `oxagen login`)

## Environment variables

Environment variables suit CI/CD and local development:

```json
{
  "mcpServers": {
    "linear": {
      "transport": "sse",
      "url": "https://mcp.linear.app/sse",
      "auth": "bearer",
      "envToken": "LINEAR_MCP_TOKEN"
    }
  }
}
```

Set the variable in your shell:

```bash
export LINEAR_MCP_TOKEN="lin_api_..."
```

For header-based auth, use `${VAR}` expansion in the headers:

```json
{
  "mcpServers": {
    "internal": {
      "transport": "streamable-http",
      "url": "https://mcp.internal.acme.com/v1",
      "auth": "header",
      "headers": { "X-API-Key": "${ACME_MCP_KEY}" }
    }
  }
}
```

## Credential files

Credential files live at `~/.config/oxagen/credentials/<server-name>.json` with `0600` permissions (owner read and write only). Keep them out of version control.

### Structure

```json
{
  "accessToken": "ghp_abc123...",
  "refreshToken": "ghr_xyz789...",
  "tokenType": "Bearer",
  "expiresAt": "2026-07-01T12:00:00.000Z",
  "scopes": ["repo", "read:org"],
  "updatedAt": "2026-06-25T10:30:00.000Z"
}
```

| Field | Description |
|-------|-------------|
| `accessToken` | The bearer or access token sent in the Authorization header |
| `refreshToken` | OAuth refresh token for automatic renewal |
| `tokenType` | Token type (default: `"Bearer"`) |
| `expiresAt` | ISO timestamp when the access token expires |
| `scopes` | OAuth scopes that were granted |
| `headers` | For header-auth servers: the resolved header key-value pairs |
| `updatedAt` | When this credential was last written |

### Storing a credential

Write the credential file at `~/.config/oxagen/credentials/<server-name>.json` with the structure above and `0600` permissions:

```bash
# Write the credential file
cat > ~/.config/oxagen/credentials/linear.json <<'EOF'
{
  "accessToken": "lin_api_abc123",
  "tokenType": "Bearer",
  "updatedAt": "2026-06-29T00:00:00.000Z"
}
EOF
chmod 600 ~/.config/oxagen/credentials/linear.json
```

For OAuth, the platform runtime stores the token after you complete the browser authorization flow.

## OAuth flow

For servers with `"auth": "oauth"` (like GitHub MCP), the web app runs the full OAuth 2.1 + PKCE flow:

1. In your workspace, open **Tools → MCP Servers** in the sidebar
2. Click **Authenticate** on the server's row
3. Complete the OAuth authorization in your browser
4. Oxagen stores the token encrypted, holds it for the workspace, and uses it on the agent's behalf (web and API runtime)

Without the platform, paste an access token from another flow into the credential file:

```bash
cat > ~/.config/oxagen/credentials/github.json <<'EOF'
{
  "accessToken": "gho_abc123...",
  "tokenType": "Bearer",
  "updatedAt": "2026-06-29T00:00:00.000Z"
}
EOF
chmod 600 ~/.config/oxagen/credentials/github.json
```

## Token expiry and refresh

The runtime checks token expiry before it connects to a server:

- **Not expired**: the runtime uses the token as is.
- **Expired, with a refresh token**: the platform's OAuth refresh watcher runs every 30 minutes and refreshes tokens that expire within the next 10 minutes. Without the platform, the next connection fails and asks you to authenticate again.
- **Expired, with no refresh token**: the runtime skips the server with a warning. Write a fresh token to `~/.config/oxagen/credentials/<server-name>.json`.

The example below uses `oxagen mcp check`, which is retired in the Oxagen CLI and prints a retirement notice. See [CLI reference](/docs/mcp/cli-reference).

```bash
oxagen mcp check
# ● github: healthy (42ms)
# ◐ linear: auth_required — token expired
# ● filesystem: healthy
```

## Handling credentials

- Credential files use `0600` permissions (owner only).
- Credential files hold tokens in plain text, so limit who can read your home directory.
- Do not commit `.oxagen/settings.local.json`. Add it to `.gitignore`.
- For secrets a team shares, use environment variables backed by a secret manager.
- The `envToken` field holds the **variable name**, not the value, so it is safe to commit in `.oxagen/settings.json`.
- Oxagen encrypts the credentials it holds (through OAuth) at rest with AES-256-GCM.

## Credential file location

```bash
# List the credential directory
ls ~/.config/oxagen/credentials/

# View a specific credential (be careful in shared terminals)
cat ~/.config/oxagen/credentials/github.json

# Delete a credential (keeps the server config in place)
rm ~/.config/oxagen/credentials/github.json
```
