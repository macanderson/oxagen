title: Environments & secrets
description: "Scope secret values per environment: encrypted vault keys with per-environment overrides."

A workspace separates runtime configuration into **environments** (for example,
`production`, `development`, and `preview`). Each environment decides which
**secret values** apply. Manage environments under **Environments** in the
workspace sidebar.

## Environments

- Every workspace has exactly one **default** environment. Promoting another
  environment swaps the default in one step.
- You cannot delete or deactivate the default environment. Promote a
  replacement first.
- An agent resolves its environment through an
  [environment binding](/docs/agent/custom-agents#environments): governance
  metadata that names the secret scope an agent identity may resolve.
  An unbound agent uses the workspace default.

## The secrets vault

Oxagen models secrets as **keys with per-environment overrides**:

- A key (for example, `DATABASE_URL`) lives at the workspace root, with an
  optional default value.
- Each environment can override the key's value. Unset an override and the
  key falls back to its default.
- Keys are **sensitive by default** and envelope-encrypted at rest (KMS).
  Listing keys returns masked metadata only.
- Reading a plaintext value takes an explicit reveal or export
  (`reveal_secret`, `export_secrets`, or `oxagen secret reveal`). Each one writes
  a `secret.revealed` or `secret.exported` security event.
- You can paste `.env` text to bulk-import. Oxagen parses it, previews new
  keys and overrides, and commits nothing until you confirm.

The values stay in Oxagen. Oxagen holds them for the connectors and agent
identities whose binding names them (for example, a data connector's own
credentials). Oxagen has no agent runtime of its own to inject them into.
