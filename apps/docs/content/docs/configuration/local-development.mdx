## Overview

A few controls are **on in deployed environments and off on a developer
machine**: mandatory email verification, the mandatory OAuth-token-encryption key,
and hardened cookies and rate limits. Oxagen decides which mode it is in through one
predicate that gives the same answer every time.

## The `OXAGEN_LOCAL_DEV` flag

`pnpm dev` sets `OXAGEN_LOCAL_DEV=1` for the whole local stack, so you do not
normally set it by hand. It marks the process tree as a developer machine, and the auth layer
relaxes its deployed-only controls.

### Why an explicit flag (and not just `NODE_ENV`)?

Oxagen builds the auth configuration **once**, at module load. At that moment,
`NODE_ENV` alone cannot say whether the process is local:

- `next dev` sets `NODE_ENV=development` slightly late, so the auth module could read
  `production` during early boot and bake in `requireEmailVerification: true`. That
  intermittently returned `403 EMAIL_NOT_VERIFIED` on local sign-in until an unrelated
  recompile re-evaluated the module.
- `tsx`-run services (`apps/api`, `apps/mcp`) never set `NODE_ENV` at all.

The explicit `OXAGEN_LOCAL_DEV` flag removes that race. Every process in the stack
detects local mode the same way.

## What "local" relaxes

When Oxagen resolves to a local or development environment, it:

- skips mandatory email verification (you sign up and sign in immediately)
- does not require the OAuth-token-encryption master key
- relaxes cookie and rate-limit hardening

## It cannot weaken a real deployment

The predicate that reads `OXAGEN_LOCAL_DEV` is gated on `process.env.VERCEL`, which
every real Vercel deployment sets. **A deployed environment ignores the flag**,
even if it leaks into a deployed env file, so the flag cannot relax production
controls.

A process counts as local when **any** of these hold:

| Signal | Set by |
| --- | --- |
| `OXAGEN_LOCAL_DEV=1` and **not** on a Vercel deploy | `pnpm dev` (`tools/scripts/dev.ts`) |
| `NODE_ENV=development` or `NODE_ENV=test` | the runtime or test harness |
| `VERCEL_ENV=development` | the Vercel "Development" environment |
| `E2E_TEST=true` | the Playwright browser test harness |

## When you set it by hand

Only when you run a service **outside** `pnpm dev` (for example, `apps/api` on its
own with `tsx`) and want the local relaxations. Export `OXAGEN_LOCAL_DEV=1`
before you start the process. Never set it in a deployed environment.
