Run `oxagen --help` for the live list, and append `--help` to any command for its flags.

Most platform commands need an [authenticated CLI](/docs/cli/account-setup). `cost`, `logs`, and `telemetry` work offline. Agent enrollment uses a one-time token, and some wrapping commands inspect local state.

Each one is still registered, prints a retirement notice that points at the `stella` CLI, and exits non-zero.

## oxagen budget: spend ceilings

```bash
oxagen budget show [--json]
oxagen budget set --scope <scope> --period <period> --limit <usd> [flags]
```

Hard period-to-date spend ceilings that gate agent runs. `show` lists every configured ceiling with its live burn. `set` creates or replaces one. See [Spend budgets](/docs/cli/budget) for the full model.

| Flag (`set`) | Description |
|---|---|
| `--scope <scope>` | `org` or `workspace`. |
| `--period <period>` | The accounting period the ceiling resets on. |
| `--limit <usd>` | The ceiling, in dollars. |
| `--window-days <n>` | Rolling-window length, for window-based periods. |
| `--enabled <bool>` | Turn the ceiling on or off without deleting it. |
| `--json` | Machine-readable output. |

`set` requires org **Owner**, **Admin**, or **Billing**, because it changes spend behavior.

## oxagen cost: project model cost

```bash
oxagen cost --in <tokens> --out <tokens> [-m <slug>] [--json]
oxagen cost --rates [--json]
```

Prices a token workload against the rate card built into the CLI. With no `--model`, it compares every priced model, cheapest first, and reports the spread. With one, it projects that model alone. `--rates` prints the card.

This is a **projection**, not an observation. It makes no network call and needs no credential. For what was spent, use `oxagen budget show` (period-to-date burn) or `oxagen trace <executionId>` (spend per run).

```bash
oxagen cost --in 200000 --out 40000
oxagen cost --in 200000 --out 40000 -m anthropic/claude-sonnet-5 --json
oxagen cost --rates
```

## oxagen trace: one run as a tree

```bash
oxagen trace <executionId> [--json]
```

Shows one agent run as a tree: each step, the tool calls it made, and any child runs it started, with timing. `<executionId>` is the run's public id (`aex_…`) or UUID. This is the *explain* surface: the record of what an agent did, read back from the run ledger.

## oxagen graph: knowledge graph

```bash
oxagen graph search -q "<text>" [-l <labels>] [-n <limit>] [--json] [--quiet]
```

Bounded semantic (vector) search across the workspace context graph. `-l/--labels` takes a comma-separated list of domain labels (for example `Person,Company`). `-n/--limit` accepts 1–50 (default 10). See [Knowledge graph from the CLI](/docs/cli/knowledge-graph).

## oxagen memory & remember: agent memory

```bash
oxagen remember "<lesson>" [--class <class>] [--kind <kind>] [--enforcement <n>] [--node <ref>]
oxagen memory list|show|edit|salience|promote|demote|dismiss|candidates|citations|rm|import
```

The workspace's memory of what agents learned. `remember` captures a lesson and infers its class and kind. The `memory` subcommands curate them. See [Memory from the CLI](/docs/cli/memory).

| Subcommand | Description |
|---|---|
| `list` | List memories, filtered by `--class`, `--kind`, `--min-enforcement`, `--min-citations`, or `--node`, and sorted by `--sort`. |
| `show <id>` | One memory in full detail (id or publicId). |
| `edit <id>` | Change a memory's `--lesson`, `--kind`, or `--source`. |
| `salience <id>` | Adjust `--confidence`, `--enforcement`, or lifecycle `--status`. |
| `promote <id> --to <class>` | Raise to RULE or FACT and record an audit event. FACT requires human confirmation. |
| `demote <id> --to <class>` | Lower to RULE or OBSERVATION and record an audit event. |
| `dismiss <id>` | Remove from the promotion candidate queue (`--restore` puts it back). |
| `candidates` | Top OBSERVATION memories by citation pressure, ripe for promotion. |
| `citations` | Workspace citation analytics over `--days`: influence, compliance, most-cited, least-useful, and most-violated. |
| `rm <id>` | Delete a memory permanently. |
| `import <files...>` | Bulk-import markdown rule docs as memories. Previews unless `--yes`. |

## oxagen init: link a project

```bash
oxagen init [--org <slug>] [--workspace <slug>] [--no-link] [--json]
```

Resolves an org and workspace and writes `.oxagen/workspace.json`, which every other command reads to scope itself. `--org` and `--workspace` name the pair, so `init` runs without prompting, in CI or any shell without a terminal. Without them, `init` picks the only option or asks you to choose. It then checks the workspace for a GitHub connection and, in an interactive terminal, offers to create one so the graph has a source to ground on. `--no-link` skips that step and cannot be combined with `--org` or `--workspace`.

Inside a git repository, `init` writes the link at the repository root, whatever subdirectory you run it from. It also adds `.oxagen/workspace.json` to the root `.gitignore` when git does not already ignore it, because the link binds one machine, not every clone. Outside a repository, the link goes in the current directory and `.gitignore` is left alone.

`init` is idempotent. Running it again in a linked project reuses the existing link. When `--org` or `--workspace` names a different pair, `init` replaces the link and prints the pair it replaced.

Last, `init` reports the directory to Oxagen, and it appears on the Working copies tab of the Repositories page with its machine, path, repository, branch, and head commit. The machine is named by a hash of a random id kept in `~/.config/oxagen/machine-id`, never a hardware serial. If the report fails, `init` prints one warning and still succeeds. With `--json`, the result carries the recorded `workingCopy` id or the error.

With `--org` or `--workspace`, `init` exits 1 when it cannot link the pair you named.

The link names the org and the workspace by slug, ID, and name:

```json
{
  "orgSlug": "acme",
  "orgId": "org_8fK2mQ9xLw3RtY6bN1pZ4c",
  "orgName": "Acme",
  "workspaceSlug": "payments",
  "workspaceId": "wrk_3Hs7Vd1QkP9mXe2Lt5Ga8r",
  "workspaceName": "Payments",
  "linkedAt": "2026-09-24T16:00:00.000Z"
}
```

Commands address the workspace by its slugs. The CLI reads the IDs only to find the org and workspace again after one is renamed, and then rewrites the slugs. `init` writes database IDs. To write the file by hand, copy the public IDs (`org_…` and `wrk_…`) from the Workspaces section of the Organization page. The CLI accepts either form.

## oxagen pull: write the published steering here

```bash
oxagen pull [--binding <rpb_id>] [--force] [--dry-run] [--json]
```

Writes the steering published in this workspace into this directory's `.oxagen/`. Steering is published by merging a Context PR onto the main repository's production branch, and `pull` reads that tree from Oxagen at the branch head, so the machine needs no git access to the main repository. `--binding` pulls from another linked repository instead of the main one.

Run it anywhere inside a project that `oxagen init` linked. `pull` walks up to the nearest `.oxagen/workspace.json` and uses the workspace it names.

`pull` does not overwrite your edits. It records what it wrote in the `pull` block of `.oxagen/workspace.json` and decides each file three ways:

| Here | Result |
|---|---|
| Absent | Created. |
| Same as published | Left alone. |
| Unchanged since the last pull | Replaced with the published file. |
| Edited here | A conflict. |

A file the last pull wrote that is no longer published is deleted if you did not edit it, and is a conflict if you did. One conflict refuses the whole pull, lists the paths, and writes nothing. `--force` overwrites or deletes the edited files. `--dry-run` prints the plan and writes nothing.

`pull` writes only inside `.oxagen/`. It refuses a published path outside `.oxagen/`, a path that climbs out of it, the machine's own `.oxagen/workspace.json`, and a local symlink that would carry a write out of `.oxagen/`. `--force` does not override those refusals.

After a pull, the directory is reported to Oxagen with the commit it pulled, the same way `init` reports it. The command exits 0 on success or when there is nothing to do, 1 on a refusal or an API failure, and 2 on a bad argument.

## oxagen agent: the agent identity

```bash
oxagen agent register --slug <slug> --name <name> --harness <stella|claude-code|codex|cursor|claude-agent-sdk|custom> [--description <text>] [--validity-days <n>] [--json]
oxagen agent status <agent> [--json]
oxagen agent unenroll <agent> [--host <tch_id>] [--reason <text>] [--json]
```

`register` mints the identity (`register_agent`): the agent row, its delegated principal, the default agent role and one long-lived credential, printed once and never recoverable. The definition is a file, `.oxagen/agents/<slug>.toml`, committed to the workspace repository through `commit_agent_definition`. `status` reads `get_agent`: the identity, its credentials (prefix and dates, never the secret), the roles on its principal, the hosts enrolled under its key and the definition of record the last commit cached. `unenroll` revokes the agent's live host enrollments through `revoke_tacho_enrollment`, or one host with `--host`. `register` and `unenroll` are org Owner/Admin writes: the key `oxagen login` minted authenticates as the user who approved the login, and the handler checks that user's org role. The credential `register` prints is locked to its purpose and is not accepted as a bearer by the API or the MCP server; it is the credential the run-token exchange of the spec consumes.

## oxagen agent enroll: put this machine under a registered agent's key

The Oxagen app puts this command on the machine's PATH. [Install the Oxagen app](/docs/cli/wrap-an-agent#install-the-oxagen-app) on the host first.

```bash
oxagen agent enroll --token <oxe_1time_…> [--harness claude-code|codex|cursor|stella] [--port <n>] [--no-service] [--force]
```

The scripted path of the register flow (Mission Control spec §14.1). The one-time enrollment token (issued once from the Agents page or through `create_enrollment_token`, good for thirty minutes) is the credential, so no `oxagen login` is needed: the control plane resolves the organization, the workspace and the agent from it, and the host file records what it answered. The routine is the one `oxagen agent enroll` runs: the device key, the host credential, the `tachod` user service and the harness hooks. A token that was already used or has expired is refused (`token_used`, `token_expired`); issue a new one. The git remote of the directory the command runs in is reported so the onboarding gate can offer it as the workspace's main repository.

## oxagen agent env: bind agents to environments

```bash
oxagen agent env bind <agent> --env <slug> [--primary] [--json]
oxagen agent env unbind <agent> --env <slug> [--json]
oxagen agent env list <agent> [--json]
```

`<agent>` is an agent's public id (`agt_…`), slug, or agent-key. `--env` is an environment slug or `env_` id. An agent's first binding becomes its primary. `--primary` makes the new binding primary and demotes the previous one in the same write.

## oxagen env: workspace environments

```bash
oxagen env list [--json]
oxagen env get <idOrSlug>
oxagen env create <name> [--slug <slug>] [--description <text>]
oxagen env update <idOrSlug> [--name <n>] [--slug <s>] [--description <t>] [--active|--inactive]
oxagen env rm <idOrSlug>
oxagen env set-default <idOrSlug>
```

Environments are governed configuration records: a named scope that secrets resolve against and agents bind to. You cannot delete the workspace default.

## oxagen secret: credential vault

```bash
oxagen secret list [--json]
oxagen secret set <key> <value> [--env <slug>] [--no-sensitive]
oxagen secret rm <key> [--env <slug>]
oxagen secret reveal <key> [--env <slug>]
oxagen secret import [--env <slug>] [-f <path>] [--yes]
oxagen secret export [--env <slug>] [-o <path>]
```

The workspace's encrypted credential vault. `list` shows masked metadata only. Values are stored per key, with optional overrides per environment. `--env` targets one environment's override. Omit it for the default value.

`reveal` and `export` return plaintext, and Oxagen **records each one in the access log**. `import` reads `.env` text from a file or stdin and previews the change unless you pass `--yes`.

## oxagen router: verified-outcome market router

```bash
oxagen router stats [--task-class <c>] [--window <days>] [--min-samples <n>] [--json]
oxagen router preview <prompt> [--files <n>] [--cross-package] [--task-class <c>] [--json]
oxagen router policy get [--json]
oxagen router policy set [--scope <s>] [--mode <m>] [--threshold <n>] [--min-samples <n>] [--window <days>] [--escalate <bool>] [--json]
```

Learned, cost-aware model routing. `stats` reports observed outcomes per task class and model, and the cheapest model that clears the quality bar in each class. `preview` dry-runs the routing decision for a prompt and changes nothing. `policy set` requires org **Owner** or **Admin**, because it changes spend behavior.

## oxagen conversation: export a conversation

```bash
oxagen conversation export <id> [--format md|pdf] [-o <file>] [--json]
```

Exports a conversation's active branch. Markdown goes to stdout or to `-o`. A PDF is stored privately, and the command prints the serve URL.

## oxagen asset: ingest a binary asset

```bash
oxagen asset upload <url> [--kind <kind>] [--filename <name>] [--conversation <id>] [--json]
```

Ingests an asset from a public URL into object storage. With `--conversation`, it records the asset as a private chat attachment linked to that conversation.

## oxagen logs: CLI debug log

```bash
oxagen logs [-n <lines>] [--category <c>] [-f] [--path] [--clear] [--json]
```

Reads the CLI's own log at `~/.oxagen/logs/cli.output`. The CLI records every command it runs. Set `OXAGEN_CLI_DEBUG=1` for full detail. `--category` filters by `invoke`, `api`, `llm`, or `error`. `--path` prints the log location, `--clear` truncates it, and `-f/--follow` tails it.

## oxagen telemetry: anonymous usage telemetry

```bash
oxagen telemetry [on|off|status]
```

Anonymous usage telemetry: command names, durations, coarse success and error categories, and OS and architecture. It never includes code, prompts, file contents, paths, model slugs, or keys. It is on by default. `oxagen telemetry off` or `DO_NOT_TRACK=1` turns it off.

## Login and logout

```bash
oxagen login                                                   # browser OAuth + org/workspace picker

```
