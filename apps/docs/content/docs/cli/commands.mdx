Most platform commands need an [authenticated CLI](/docs/cli/account-setup). `cost`, `logs`, and `telemetry` work offline. `oxagen agent enroll` with a one-time token needs no login. The commands under `oxagen agent` that take no agent argument act on this machine's local state.

## oxagen budget: spend ceilings

```bash
oxagen budget show [--json]
oxagen budget set --scope <scope> --period <period> --limit <usd> [flags]
```

Hard period-to-date spend ceilings that gate agent runs. `show` lists every configured ceiling with its live burn. `set` creates or replaces one. See [Spend budgets](/docs/cli/budget) for the full model.

| Flag (`set`) | Description |
|---|---|
| `--scope <scope>` | `org` or `workspace`. |
| `--period <period>` | The accounting period the ceiling resets on. |
| `--limit <usd>` | The ceiling, in dollars. |
| `--window-days <n>` | Rolling-window length, for window-based periods. |
| `--enabled <bool>` | Turn the ceiling on or off without deleting it. |
| `--json` | Machine-readable output. |

`set` requires org **Owner**, **Admin**, or **Billing**, because it changes spend behavior.

## oxagen cost: project model cost

```bash
oxagen cost --in <tokens> --out <tokens> [-m <slug>] [--json]
oxagen cost --rates [--json]
```

Prices a token workload against the rate card built into the CLI. With no `--model`, it compares every priced model, cheapest first, and reports the spread. With one, it projects that model alone. `--rates` prints the card.

This is a **projection**, not an observation. It makes no network call and needs no credential. For what was spent, use `oxagen budget show` (period-to-date burn) or `oxagen trace <executionId>` (spend per run).

```bash
oxagen cost --in 200000 --out 40000
oxagen cost --in 200000 --out 40000 -m anthropic/claude-sonnet-5 --json
oxagen cost --rates
```

## oxagen trace: one run as a tree

```bash
oxagen trace <executionId> [--json]
```

Shows one agent run as a tree: each step, the tool calls it made, and any child runs it started, with timing. `<executionId>` is the run's public id (`aex_…`) or UUID. This is the *explain* surface: the record of what an agent did, read back from the run ledger.

## oxagen graph: knowledge graph

```bash
oxagen graph search -q "<text>" [-l <labels>] [-n <limit>] [--json] [--quiet]
```

Bounded semantic (vector) search across the workspace context graph. `-l/--labels` takes a comma-separated list of domain labels (for example `Person,Company`). `-n/--limit` accepts 1–50 (default 10). See [Knowledge graph from the CLI](/docs/cli/knowledge-graph).

## oxagen memory: workspace memories

```bash
oxagen memory list|show|promote|dismiss|drop|import
```

The memories agents wrote in their harnesses, which Oxagen collects from enrolled hosts. See [Memory from the CLI](/docs/cli/memory).

| Subcommand | Description |
|---|---|
| `list` | Memories ranked by uses, one row per group that says the same thing. Filter by `--state`, `--harness`, `--agent`, `--repository`, or `--type`. |
| `show <id>` | One memory with its text, source, uses, and memory PR. |
| `promote <ids...>` | Draft steering records on the open memory PR, or a new one. Set `--kind`, `--force`, `--effect`, `--statement`, or `--repo`. |
| `dismiss <ids...>` | Set memories aside so the curator does not propose them again. `--restore` brings them back. |
| `drop <number> <path>` | Take one proposed record out of an open memory PR. When the PR merges, the record's statements are rejected and its memories wait again. |
| `import <files...>` | Read Markdown rule docs into steering records with a kind and a force for each statement. Previews unless `--yes`, which opens one steering PR. |

## oxagen init: link a project

```bash
oxagen init [--org <slug>] [--workspace <slug>] [--no-link] [--json]
```

Resolves an org and workspace and writes `.oxagen/workspace.json`, which every other command reads to scope itself. `--org` and `--workspace` name the pair, so `init` runs without prompting, in CI or any shell without a terminal. Without them, `init` picks the only option or asks you to choose. It then checks the workspace for a GitHub connection and, in an interactive terminal, offers to create one so the graph has a source to ground on. `--no-link` skips that step and cannot be combined with `--org` or `--workspace`.

Inside a git repository, `init` writes the link at the repository root, whatever subdirectory you run it from. It also adds `.oxagen/workspace.json` to the root `.gitignore` when git does not already ignore it, because the link binds one machine, not every clone. Outside a repository, the link goes in the current directory and `.gitignore` is left alone.

`init` is idempotent. Running it again in a linked project reuses the existing link. When `--org` or `--workspace` names a different pair, `init` replaces the link and prints the pair it replaced.

Last, `init` reports the directory to Oxagen, and it appears on the Working copies tab of the Repositories page with its machine, path, repository, branch, and head commit. The machine is named by a hash of a random id kept in `~/.config/oxagen/machine-id`, never a hardware serial. If the report fails, `init` prints one warning and still succeeds. With `--json`, the result carries the recorded `workingCopy` id or the error.

With `--org` or `--workspace`, `init` exits 1 when it cannot link the pair you named.

The link names the org and the workspace by slug, ID, and name:

```json
{
  "orgSlug": "acme",
  "orgId": "org_8fK2mQ9xLw3RtY6bN1pZ4c",
  "orgName": "Acme",
  "workspaceSlug": "payments",
  "workspaceId": "wrk_3Hs7Vd1QkP9mXe2Lt5Ga8r",
  "workspaceName": "Payments",
  "linkedAt": "2026-09-24T16:00:00.000Z"
}
```

Commands address the workspace by its slugs. The CLI reads the IDs only to find the org and workspace again after one is renamed, and then rewrites the slugs. `init` writes database IDs. To write the file by hand, copy the public IDs (`org_…` and `wrk_…`) from the Workspaces section of the Organization page. The CLI accepts either form.

## oxagen pull: write the published steering here

```bash
oxagen pull [--binding <rpb_id>] [--force] [--dry-run] [--json]
```

Writes the steering published in this workspace into this directory's `.oxagen/`. `pull` reads the `.oxagen/` tree at the head of the steering repo's production branch through Oxagen, so the machine needs no git access to the steering repo. A steering repo in the current layout keeps its steering records under `steering/` and has no `.oxagen/` tree. For a workspace that uses one, `pull` finds no published files and deletes the unedited files an earlier pull wrote. `--binding` pulls from a linked repository instead of the steering repo.

Run it anywhere inside a project that `oxagen init` linked. `pull` walks up to the nearest `.oxagen/workspace.json` and uses the workspace it names.

`pull` does not overwrite your edits. It records what it wrote in the `pull` block of `.oxagen/workspace.json` and decides each file three ways:

| Here | Result |
|---|---|
| Absent | Created. |
| Same as published | Left alone. |
| Unchanged since the last pull | Replaced with the published file. |
| Edited here | A conflict. |

A file the last pull wrote that is no longer published is deleted if you did not edit it, and is a conflict if you did. One conflict refuses the whole pull, lists the paths, and writes nothing. `--force` overwrites or deletes the edited files. `--dry-run` prints the plan and writes nothing.

`pull` writes only inside `.oxagen/`. It refuses a published path outside `.oxagen/`, a path that climbs out of it, the machine's own `.oxagen/workspace.json`, and a local symlink that would carry a write out of `.oxagen/`. `--force` does not override those refusals.

After a pull, the directory is reported to Oxagen with the commit it pulled, the same way `init` reports it. The command exits 0 on success or when there is nothing to do, 1 on a refusal or an API failure, and 2 on a bad argument.

## oxagen check: steering PR checks

```bash
oxagen check [paths...] [--base <ref>] [--refresh] [--json]
```

Run `check` inside a clone of a steering repo to see what the steering PR check will report before you push. It runs the same checks on your working tree. The tree is every file git tracks or would add among `AGENTS.md`, `CLAUDE.md`, `README.md`, `.gitattributes`, `workspace.toml`, and the files under `agents/`, `steering/`, `tools/`, and `policy/`. The checks compare the tree with the production branch: `--base <ref>`, else `origin/HEAD`, else `origin/main`. With no base, they read the tree whole, as for a first publish.

Paths narrow the report. The checks still read the whole tree, and the report keeps the findings in the files and folders you name.

Some checks read more than the tree. The hash, conflicts, and references checks compare your change with the records the workspace has published. The references check also looks up each runtime, operator, reviewer group, and credential your repo names. `check` fetches the published index and this context from Oxagen in one call and caches the answer for ten minutes. `--refresh` fetches it again. The cache keeps one answer for each API address, organization, workspace, and login, so a run after `oxagen login` to another workspace fetches again.

- A workspace repo reads the workspace its `workspace.toml` names. Your login must be for that workspace. If it is for another one, `check` stops with `scope_mismatch` and exits 2. Run `oxagen login --org <org> --workspace <workspace>` for the workspace `workspace.toml` names, or fix `workspace.toml`.
- An organization repo reads the context of the workspace the CLI has selected. It reads no index, because no organization version is published yet, so its records check as a first publish.

Oxagen does not store member handles, teams, or reviewer group slugs yet. Until it does, the references check reports each agent's `operator` and each reviewer group as missing.

Two checks do less on your machine. The settings check is skipped, and the compile check does not evaluate the Cedar policies.

`--json` prints one finding per line on stdout and the result line on stderr.

The command exits 0 when no finding is an error and 1 when at least one is. It exits 2 when the checks cannot run: outside a steering repo or a git clone, with a `--base` that names no commit, when your login is for another workspace than the one `check` reads, or when `check` cannot fetch the index and context, for example before you log in.

## oxagen steering import: Markdown files into steering

```bash
oxagen steering import <paths...> [--as records|policies|memories] [--yes] [--json]
```

Reads Markdown files into steering records, Cedar policies, or memories. Pass files, folders, or both. The command searches a folder for `.md`, `.markdown`, and `.mdx` files, and skips `node_modules` and every folder whose name starts with a dot. It takes a file you name as given.

Without `--as`, each file takes the target its text implies. A file with a fenced `cedar` block becomes a policy file at `policy/<file-name>.cedar`, the import skips a README or index file, and it splits any other file into records. `--as records`, `--as policies`, or `--as memories` sets one target for every file. `--as memories` splits each file into statements the same way, and each statement becomes a memory.

```bash
oxagen steering import AGENTS.md docs                    # preview
oxagen steering import AGENTS.md docs --yes              # open the steering PR
oxagen steering import notes --as memories --yes         # store the memories
```

The preview lists each record with its kind, its force, its source line, and any duplicate or conflict with a published record, then each policy file with its statements and any issue, then each memory with its source line. It writes nothing. `--yes` opens one steering PR on `steering/import-<date>` with every record and policy marked add. It leaves out a record that conflicts with a published record and a policy file with an issue, and names each one. Nothing steers an agent until the PR merges.

`--yes` stores every memory marked add as a waiting memory, with `import:<file>#L<line>` as its source. It names no agent, because a person imported it. It leaves out a memory that repeats a waiting memory or a statement a person rejected, and names each one. A memory steers no agent until a person promotes it into a steering record. An import of memories alone opens no PR.

The command sends files in calls of 25 and then compares the rows of every call. A statement two calls both hold is marked a duplicate, and when two files in different calls become the same policy file, the later one is skipped. The command skips a file over 100,000 characters. One steering PR holds at most 299 records and policy files, so `--yes` refuses an import that marks more add. The command calls `parse_markdown_import` and `commit_markdown_import`.

## oxagen agent: the agent identity

```bash
oxagen agent register --name <name> --harness <stella|claude-code|codex|cursor|claude-agent-sdk|custom> --runtime <rtm_id> [--slug <slug>] [--toolbelt <tbt_id>] [--description <text>] [--validity-days <n>] [--json]
oxagen agent status <agent> [--json]
oxagen agent unenroll <agent> [--host <tch_id>] [--reason <text>] [--json]
```

Without an agent argument, `status` and `unenroll` act on this machine instead. See [oxagen agent on this machine](#oxagen-agent-on-this-machine).

`register` mints the agent (`register_agent`): one operator on one runtime with one harness, carrying a toolbelt. It writes the agent row, its delegated principal, the default agent role, the first agent version and one long-lived credential, printed once and never recoverable. An agent carries no prompt and no definition file. `status` reads `get_agent`: the identity, the runtime it runs on, the toolbelt it carries, its versions, its credentials (prefix and dates, never the secret), the roles on its principal and the hosts enrolled under its key. `unenroll` revokes the agent's live host enrollments through `revoke_tacho_enrollment`, or one host with `--host`. `register` and `unenroll` are org Owner/Admin writes: the key `oxagen login` minted authenticates as the user who approved the login, and the handler checks that user's org role. The credential `register` prints is locked to its purpose and is not accepted as a bearer by the API or the MCP server; it is the credential the run-token exchange of the spec consumes.

## oxagen agent enroll: put this machine under Oxagen

The Oxagen app puts this command on the machine's PATH. [Install the Oxagen app](/docs/cli/wrap-an-agent#install-the-oxagen-app) on the host first.

```bash
oxagen agent enroll --token <oxe_1time_…> [--harness <list>] [--api-url <url>] [--credentials brokered|passthrough] [--validity-days <n>] [--port <n>] [--no-service] [--force]
oxagen agent enroll [--token <apiKey>] [--org <slug>] [--workspace <slug>] [--harness <list>] [--api-url <url>] [--credentials brokered|passthrough] [--validity-days <n>] [--port <n>] [--no-service] [--managed] [--print-managed] [--force] [--verify]
```

Enrollment writes the device key, the host credential, the collector's user service, and the harness hooks. The first form enrolls this machine as a registered agent's host. The second form enrolls it under your CLI login, or under a platform API token you pass with `--token`. After a successful enroll, both forms move every other agent on the machine whose hooks and service still run the older executable to the `oxagen` CLI. `--print-managed` moves nothing. See [Older enrollments](/docs/cli/wrap-an-agent#older-enrollments).

| Flag | Description |
|---|---|
| `--token <token>` | A one-time enrollment token (`oxe_1time_…`) from agent registration, or a platform API token. Without it, the command uses your CLI login. |
| `--org <slug>` | Organization slug. Defaults to the logged-in org. Refused with an enrollment token. |
| `--workspace <slug>` | Workspace slug. Defaults to the logged-in workspace. Refused with an enrollment token. |
| `--harness <list>` | `claude-code`, `codex`, `cursor`, `stella`, or a comma list such as `claude-code,cursor`. A fresh enrollment defaults to `claude-code`. A re-apply keeps the current list. |
| `--api-url <url>` | The Oxagen API base URL, when it is not the one `oxagen login` chose. |
| `--credentials <mode>` | `brokered`, the default: the gateway holds each model vendor key and the harness holds a run token. `passthrough`: the harness keeps its own key. |
| `--validity-days <n>` | How many days the enrollment stays valid. Defaults to 180. |
| `--port <n>` | The loopback port for the collector. |
| `--no-service` | Install no user service. Run `oxagen daemon` yourself. |
| `--managed` | Also print the managed settings document for MDM. Refused with an enrollment token. |
| `--print-managed` | Only print the managed settings document, and write no user settings. Refused with an enrollment token. |
| `--force` | Enroll again even if already enrolled. |
| `--verify` | Run one headless turn afterwards, of the first harness `--harness` names, or Claude Code. Refused with an enrollment token. |

The first form is the scripted path of the register flow. The one-time enrollment token (issued once from the Agents page or through `create_enrollment_token`, good for thirty minutes) is the credential, so no `oxagen login` is needed. The control plane resolves the organization, the workspace, and the agent from it, and the host file records what it answered. A token that was already used or has expired is refused (`token_used`, `token_expired`). Issue a new one. A machine holds one enrollment per agent. Every agent keeps its files in its own directory, `~/.config/oxagen/tacho/agents/<id>/`. On a machine that is already enrolled, a token for a harness that no agent hooks enrolls another agent in a new directory and revokes nothing. A token for a harness that an agent on the machine already hooks is refused: the command exits non-zero, presents nothing, and names the agent and host already enrolled. Pass `--force` to replace that agent's enrollment with the agent the token names, which is the one case that flag is for. The other agents on the machine keep their enrollments. A token that names a harness an agent already hooks together with a new one is refused with a message to run `oxagen login`. Adding a harness to an enrollment revokes it first, and only the CLI's session can revoke. With `--force`, the same command replaces that agent's enrollment with the token's agent instead of extending it. See [Two agents on one machine](/docs/cli/wrap-an-agent#two-agents-on-one-machine). The command also reports the git remote of the directory it runs in. While onboarding is open, Oxagen records the GitHub repository that remote names.

## oxagen agent on this machine

```bash
oxagen agent status [--json]
oxagen agent unenroll [--harness <name>] [--all] [--token <apiKey>] [--purge] [--reason <text>]
oxagen agent reassign [--workspace <slug>] [--org <slug>] [--harness <list>] [--token <apiKey>] [--api-url <url>] [--reason <text>] [--default]
oxagen agent export [--session <id>] [--format <format>] [--out <file>] [--list]
oxagen agent verify [--harness claude-code|codex|cursor|stella] [--json]
oxagen agent detect [--json]
oxagen agent hosts [--status active|paused|suspended|revoked] [--limit <n>] [--json]
```

Each of these acts on the machine you run it on, except `hosts`, which reads the control plane. See [Wrap an agent](/docs/cli/wrap-an-agent) for the full behavior.

| Subcommand | Description |
|---|---|
| `status` | This machine's enrollments, collector, hooks, policy bundle, and spool. It first moves an older enrollment's hooks and service to the `oxagen` CLI. It exits 1 when no agent is enrolled, or when any agent's events are not reaching Oxagen. |
| `unenroll` | Removes an agent's hooks and service, revokes its enrollment, and deletes its host key. On a machine with more than one enrollment, name the one to remove with `--harness`, or remove them all with `--all`. Pass one of the two. `--purge` also deletes the local event log, spool, and quarantine. `--token` is the operator token for the server-side revoke. |
| `reassign` | Points an agent at another workspace or org. It revokes the enrollment and enrolls again through your CLI login, keeping the device key. `--harness` with no `--workspace` replaces the harness list. `--default` also makes the new org and workspace the CLI default in `config.json`. |
| `export` | Exports a session from the local event log. `--format trace` writes the `contextgraph-trace` journal, and `--format otlp` writes OTLP JSON. The default, `--format tacho`, writes the recorder's own NDJSON. `--list` lists the sessions in the log. `--out` writes a file in place of stdout. |
| `verify` | Runs one headless turn of a harness, Claude Code by default, and confirms the collector chained it. `--json` prints the result as JSON. It exits 1 when the turn was not chained. |
| `detect` | Lists the harnesses this machine has (Claude Code, Codex, Cursor, Stella, and Claude Desktop) and which of them are enrolled. |
| `hosts` | Lists every machine enrolled in this workspace, with the tier each of its apps reaches. |

## oxagen agent run: one agent session under Oxagen

```bash
oxagen agent run [--name <agent>] [--contained] [--image <ref>] [--workspace <dir>] [--github-repository <owner/name>] -- <command> [args...]
```

Runs one agent session under Oxagen control. Everything after `--` is the agent's command and its arguments. What the command names decides what happens:

- **A custom agent.** Any other command is recorded as a custom agent under `--name`. Oxagen opens the session with a `SessionStart` hook call. The agent starts only when Oxagen accepts the session, and it runs with `OXAGEN_AGENT`, `OXAGEN_SESSION_ID`, and `OXAGEN_HOOK` in its environment, so it can report its own steps. The session closes with `SessionEnd` when the agent exits.
- **A harness this machine wraps.** `claude`, `codex`, `cursor-agent`, or `stella` runs as it is, and that harness's own hooks record the session. A harness no agent on this machine wraps is refused.
- **`--contained`.** Starts Claude Code or Codex in the contained launcher, on Linux with Docker. `oxagen run -- claude …` does the same.

| Flag | Description |
|---|---|
| `--name <agent>` | The custom agent's name: lowercase letters, digits, `.`, `_`, and `-`. Defaults to the command's file name. With `--name`, any command is recorded as a custom agent. |
| `--contained` | Start Claude Code or Codex in the contained launcher. |
| `--image <ref>` | With `--contained`: the image. `OXAGEN_CONTAINED_IMAGE` also sets it. |
| `--workspace <dir>` | With `--contained`: the repository root to mount at `/workspace`. Defaults to the current directory. This is a directory, not the workspace slug `enroll` takes. |
| `--github-repository <owner/name>` | With `--contained`: the one repository the run may fetch and push. Oxagen's Git custody gets the credential for each request, so you mint no token. The workspace must have the repository bound. |

The command exits with the agent's own exit code. It exits 1 when the machine is not enrolled, when Oxagen refuses the session, or when the command cannot start. It exits 2 when no command follows `--`, when the custom agent's name is invalid, or when the harness is not wrapped on this machine. See [Wrap a custom agent](/docs/cli/wrap-an-agent#wrap-a-custom-agent).

## Machine commands

These commands are hidden from `oxagen --help`. Enrollment writes them into the machine's hooks, service, and app settings, and those programs run them. You run one yourself only to report a custom agent's steps with `oxagen hook --agent <name>`.

| Command | What runs it |
|---|---|
| `oxagen hook` | Each wrapped harness's hooks, on every hooked event. A custom agent runs it with `--agent <name>`. It reads the payload on stdin, prints the answer on stdout, and exits 0. |
| `oxagen daemon` | The user service. It runs the collector in the foreground. |
| `oxagen mcp-stdio` | A connected app, to reach this machine's Oxagen toolbelt over stdio. |
| `oxagen credential issue`, `oxagen credential status` | Claude Code runs `issue` as its `apiKeyHelper` for a fifteen-minute model token. `status` shows the model credentials the gateway holds. |
| `oxagen github configure`, `oxagen github credential` | git, to route repository requests through this machine's credential custody. |
| `oxagen arp` | Captures and prepares local Agent Run Protocol checkpoints. |

## oxagen agent env: bind agents to environments

```bash
oxagen agent env bind <agent> --env <slug> [--primary] [--json]
oxagen agent env unbind <agent> --env <slug> [--json]
oxagen agent env list <agent> [--json]
```

`<agent>` is an agent's public id (`agt_…`), slug, or agent-key. `--env` is an environment slug or `env_` id. An agent's first binding becomes its primary. `--primary` makes the new binding primary and demotes the previous one in the same write.

## oxagen env: workspace environments

```bash
oxagen env list [--json]
oxagen env get <idOrSlug>
oxagen env create <name> [--slug <slug>] [--description <text>]
oxagen env update <idOrSlug> [--name <n>] [--slug <s>] [--description <t>] [--active|--inactive]
oxagen env rm <idOrSlug>
oxagen env set-default <idOrSlug>
```

Environments are governed configuration records: a named scope that secrets resolve against and agents bind to. You cannot delete the workspace default.

## oxagen secret: credential vault

```bash
oxagen secret list [--json]
oxagen secret set <key> <value> [--env <slug>] [--no-sensitive]
oxagen secret rm <key> [--env <slug>]
oxagen secret reveal <key> [--env <slug>]
oxagen secret import [--env <slug>] [-f <path>] [--yes]
oxagen secret export [--env <slug>] [-o <path>]
```

The workspace's encrypted credential vault. `list` shows masked metadata only. Values are stored per key, with optional overrides per environment. `--env` targets one environment's override. Omit it for the default value.

`reveal` and `export` return plaintext, and Oxagen **records each one in the access log**. `import` reads `.env` text from a file or stdin and previews the change unless you pass `--yes`.

## oxagen router: verified-outcome market router

```bash
oxagen router stats [--task-class <c>] [--window <days>] [--min-samples <n>] [--json]
oxagen router preview <prompt> [--files <n>] [--cross-package] [--task-class <c>] [--json]
oxagen router policy get [--json]
oxagen router policy set [--scope <s>] [--mode <m>] [--threshold <n>] [--min-samples <n>] [--window <days>] [--escalate <bool>] [--json]
```

Learned, cost-aware model routing. `stats` reports observed outcomes per task class and model, and the cheapest model that clears the quality bar in each class. `preview` dry-runs the routing decision for a prompt and changes nothing. `policy set` requires org **Owner** or **Admin**, because it changes spend behavior.

## oxagen logs: CLI debug log

```bash
oxagen logs [-n <lines>] [--category <c>] [-f] [--path] [--clear] [--json]
```

Reads the CLI's own log at `~/.oxagen/logs/cli.output`. The CLI records every command it runs. Set `OXAGEN_CLI_DEBUG=1` for full detail. `--category` filters by `invoke`, `api`, `llm`, or `error`. `--path` prints the log location, `--clear` truncates it, and `-f/--follow` tails it.

## oxagen telemetry: anonymous usage telemetry

```bash
oxagen telemetry [on|off|status]
```

Anonymous usage telemetry: command names, durations, coarse success and error categories, and OS and architecture. It never includes code, prompts, file contents, paths, model slugs, or keys. It is on by default. `oxagen telemetry off` or `DO_NOT_TRACK=1` turns it off.

## Login and logout

```bash
oxagen login                                                   # browser OAuth + org/workspace picker
oxagen login --token ox_… --org acme --workspace main          # CI / headless
oxagen login --no-browser                                      # paste a token instead of opening a browser
oxagen logout                                                  # clear the stored session
```

See [Account setup](/docs/cli/account-setup).
