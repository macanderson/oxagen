---
title: Spend budgets
description: "Hard period-to-date spend ceilings that gate agent runs: the org ceiling, the workspace ceiling, live burn, and the threshold ladder."
---

A spend budget is a hard USD ceiling on what an org or a workspace may spend in an accounting period. The platform's billing admission gate enforces it. Once spend exceeds a ceiling, the gate denies every governed action that consumes credits until the period rolls over or someone raises the ceiling.

Two ceilings apply independently:

- The **org** ceiling covers every workspace in the organization.
- The **workspace** ceiling covers the active workspace alone.

A run must clear both. The same ceilings back the `get_spend_budget` and `set_spend_budget` capabilities, so the CLI, the app, the API, and MCP all read and write one governed record. There is no CLI-local budget.

## Read the current ceilings

```bash
oxagen budget show
```

For each configured scope, this prints the ceiling and its **live burn**: period-to-date spend, a projection to the end of the period, the percent of the ceiling consumed, and whether the gate is denying now.

```bash
oxagen budget show --json
```

`--json` prints the exact contract payload on one line: an array of budget statuses, each carrying `scope`, `enabled`, `period`, `windowDays`, `limitUsd`, `spentUsd`, `projectedUsd`, `ratio`, `state`, `reachedThreshold`, `windowStart`, and `windowEnd`.

## The threshold ladder

`state` reports where the scope sits now:

| State | Meaning |
|---|---|
| `ok` | Below 50% of the ceiling. |
| `threshold_50` | Crossed 50%. |
| `threshold_80` | Crossed 80%. |
| `threshold_95` | Crossed 95%, the last warning before denial. |
| `exceeded` | At or over the ceiling. The admission gate is denying. |

`reachedThreshold` records the highest rung crossed in this period, so a notification fires once per rung rather than on every run.

## Set a ceiling

```bash
oxagen budget set --scope workspace --period monthly --limit 500
oxagen budget set --scope org --period rolling --window-days 30 --limit 5000
```

| Flag | Description |
|---|---|
| `--scope <org\|workspace>` | Which ceiling to write. Required. |
| `--period <monthly\|rolling>` | `monthly` resets on the calendar month. `rolling` uses a trailing window. Required. |
| `--limit <usd>` | The ceiling in dollars. Required. |
| `--window-days <n>` | Trailing-window length. Required with `--period rolling`, rejected with `monthly`. |
| `--enabled <bool>` | Turn a ceiling off without deleting it (`--enabled false`), or turn it back on. |
| `--json` | Machine-readable output. |

`set` replaces in place. It writes the ceiling for that scope and creates it if absent. It requires org **Owner**, **Admin**, or **Billing**, because changing a ceiling changes spend behavior.

The CLI checks the rolling and monthly `--window-days` rule before it sends the request, so a bad combination fails fast with a usage error (exit 2). The platform validates it again regardless.

## Projection vs. observation

`oxagen budget show` reports what was **actually spent**: metered usage, the same numbers that reach billing.

To price a workload *before* it runs, use [`oxagen cost`](/docs/cli/commands#oxagen-cost-project-model-cost), which projects token counts against the rate card built into the CLI and makes no network call. To see where the spend on one run went, use [`oxagen trace <executionId>`](/docs/cli/commands#oxagen-trace-one-run-as-a-tree).
