The Oxagen app puts one machine under Oxagen control. It bundles the `oxagen` command, and enrollment runs through it. It also bundles tacho, the older executable for the same commands, so the hooks on a machine enrolled before these commands moved into `oxagen` keep working. You never need to run tacho yourself.

## Download

<LatestDownloads />

Every version, with a SHA-256 for each file, is listed at [downloads.oxagen.sh](https://downloads.oxagen.sh/). To check a download, put that version's `SHA256SUMS.txt` beside the file and run:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

## First launch on macOS

Builds are not yet notarized, so macOS refuses the first launch and offers **Move to Trash**. Choose **Done** or **Cancel** instead.

1. Open **System Settings > Privacy & Security**. On macOS 12 it is **System Preferences > Security & Privacy**.
2. Scroll to the message about Oxagen and click **Open Anyway**.
3. Confirm with **Open** and your login password.

The **Open Anyway** button shows for about an hour after the refused launch. macOS 15 removed the older Control-click and **Open** route, so that route no longer works.

If you already have a terminal open, clearing the quarantine flag does the same thing:

```bash
xattr -dr com.apple.quarantine /Applications/Oxagen.app
```

Then open Oxagen as usual. Either way, macOS asks only once.

## First launch on Windows

Builds are not yet signed, so SmartScreen warns that the publisher is unknown. Choose **More info**, then **Run anyway**.

## Linux

The packages are unsigned and no apt or dnf repository exists yet. Install the file you downloaded directly:

```bash
sudo dpkg -i Oxagen_amd64.deb
sudo rpm -i Oxagen.x86_64.rpm
chmod +x Oxagen_amd64.AppImage && ./Oxagen_amd64.AppImage
```

## Per-user copy

Each time it opens, the app copies `oxagen` and the older tacho executable out of itself into a directory named for its version:

| Platform | Directory |
| --- | --- |
| macOS | `~/Library/Application Support/oxagen/bin/<version>` |
| Linux | `~/.local/share/oxagen/bin/<version>` |
| Windows | `%LOCALAPPDATA%\oxagen\bin\<version>` |

Enrollment writes this copy's path into every hook, the Claude Code credential helper, the Claude Desktop MCP entry, and the collector service. It never writes a path inside the app. Moving the app to the Trash or removing the package leaves the copy in place, so your agents keep working until you uninstall.

A new version copies itself beside the old one, so an update never replaces a file the running collector holds. The hooks and the collector stay on the old copy until you click **Re-apply**, which the app offers when the two differ. The app removes an old copy at its next launch once no enrollment and no link names it.

## Command line

The app links both executables from the per-user copy into `~/.local/bin` on macOS and Linux. On Windows it writes `.cmd` shims to a directory on your user `PATH`. It never asks for administrator rights, and it never replaces a file it did not write.

Open a new terminal after the first launch. On macOS and Linux, this prints the path of `oxagen`:

```bash
command -v oxagen
```

## Uninstall

In the app, **Uninstall** removes every enrollment, the links, every per-user copy, and `~/.config/oxagen`. Then remove the app: drag it to the Trash on macOS, remove it in **Settings > Apps** on Windows, or remove the package on Linux.

If you removed the app first, run the per-user copy's `oxagen`:

```bash
"$HOME/Library/Application Support/oxagen/bin/<version>/oxagen" agent uninstall
```

Use the Linux or Windows directory from the table above on those platforms. The command does what **Uninstall** does, without the app:

1. It removes every enrollment: the hooks, the collector service, the keys, and the local event log. If an enrollment cannot be fully removed, the command stops here and says what to fix, because a hook that is left would still run the copy.
2. It removes the links in `~/.local/bin`, the lines the app added to your shell profile, and on Windows the shims and the entry on your user `PATH`. The app keeps a list of each of these in `~/.config/oxagen/desktop.json` each time it opens. The command removes only what is still the way the app wrote it. A link you pointed somewhere else stays, and the command names it.
3. It removes every per-user copy and `~/.config/oxagen`. That folder holds your `oxagen login` session, so the `oxagen` command asks you to sign in again afterward.

On Windows the command cannot delete the `oxagen.exe` it is running from. It names that folder, so you can delete it after the command finishes.

Older versions of the app kept no such list. If you removed the app before a version that keeps one ever opened, the command still removes the copies, and it names the links and the profile lines for you to delete by hand.

If the per-user copy is gone as well, the Cursor and Stella hooks on macOS and Linux allow each action instead of blocking it, and Claude Code and Codex report a hook error on each tool call. On Windows the Cursor and Stella hooks block. Install the app again and use **Uninstall**, or run `oxagen agent uninstall` from any other install of the `oxagen` CLI.

## Updates

On macOS, the Oxagen app installs new versions automatically. It checks for one when it opens, every hour, and when you return to the window after 15 minutes or more. It downloads the new version, checks its signature, and replaces the app in the background. Your next restart runs it, and the window shows **Restart** until then.

The app installs automatically only when your account can replace it without a password. When it cannot, for example when a standard account runs it from `/Applications`, it asks first and offers **Install and relaunch** or **Later**. The Updates panel says why.

Windows and Linux always ask first.

Every update is signed, and the app installs nothing whose signature fails. Updates come only from published releases, and the app downloads them from downloads.oxagen.sh.

If **Check for updates** reports an error, install the app once more from [downloads.oxagen.sh](https://downloads.oxagen.sh/) over the old one. Version 2.1.3 and older, and the early builds of 2.1.4, check for updates at an address that no longer answers. The new install checks the right one and finds new versions by itself.

To turn automatic installs off, clear **Install updates automatically** in the Updates panel. The checkbox writes `autoUpdate` to `~/.config/oxagen/desktop.json`, so an administrator can set it for you with a management tool:

```json
{ "autoUpdate": false }
```

With it off, the app still tells you when a new version is out and waits for your click.
