The Oxagen app puts one machine under Oxagen. It installs the `oxagen` CLI and the Tacho wrapper for Claude Code and Codex, signs the machine in to an organization, and enrolls it in a workspace. It gives you one window to see the connection, move the host to another workspace or org, add or drop a wrapper, sign out, and unenroll.

The app keeps no state of its own. Every panel reads the files the CLIs already write (`~/.config/oxagen/config.json`, `~/.config/oxagen/tacho/host.json`, and the collector's `/status` on loopback), and every action runs one of the two CLIs bundled inside the app. Anything you do in the app, you can do from the terminal. `tacho status` and the app's Connection panel read the same files, so they agree.

<Callout type="info">
The app does not run agents. It records, gates, and keeps evidence for the Claude Code and Codex runs that already happen on the machine. Hook-based control is `client_attested`, and the app's This machine panel says so.
</Callout>

## First launch: the setup wizard

On a machine with no enrollment, the app opens a five-step wizard on a single pane. A machine that is already enrolled skips it and opens the management panels described below.

1. **Authenticate with Oxagen.** **Sign in** runs `oxagen login --browser`. **Create an account** runs the same command with `--signup`, which opens the sign-up page first. A new account names its organization and first workspace in the browser, then lands on the consent page, and the app picks up the login from there.
2. **Select an organization and workspace.** The app lists only the organizations and workspaces you belong to.
3. **Register the agents on this machine.** The app runs `tacho detect` to find Claude Code and Codex. It checks your login shell's `PATH` and the usual install directories, so a Finder launch still finds `~/.local/bin/claude`. Every agent it finds is ticked. When you confirm, the app runs `tacho enroll … --harness …`, which writes Oxagen's hooks into each agent's settings.
4. **Confirmation**, or the error and how to retry.
5. **Record a first run.** The app sends one small prompt per registered agent (`tacho verify --harness <agent>`) and confirms it was recorded. Then choose **Open Mission Control** to see it.

## Download

Download from **[downloads.oxagen.sh](https://downloads.oxagen.sh/)**. The page lists every installer for the current version with its size and SHA-256, plus a `SHA256SUMS.txt` per version (`shasum -a 256 -c SHA256SUMS.txt` verifies a download). Each file lives at `https://downloads.oxagen.sh/desktop/<version>/<file>` and never changes once published. A fix ships as a new version.

Every installer comes from a single Tauri 2 project, built by `.github/workflows/desktop.yml` and published with `apps/desktop/scripts/publish-downloads.mjs`. A `desktop-v<version>` tag also attaches the same files to a GitHub release, next to the bare `tacho` and `oxagen` binaries.

| OS | Architecture | File |
| --- | --- | --- |
| macOS 12 or newer | Apple silicon | `Oxagen_<version>_aarch64.dmg` |
| macOS 12 or newer | Intel | `Oxagen_<version>_x64.dmg` |
| Linux | x86_64 | `Oxagen_<version>_amd64.deb`, `Oxagen-<version>-1.x86_64.rpm`, `Oxagen_<version>_amd64.AppImage` |
| Windows | x86_64 | `Oxagen_<version>_x64_en-US.msi` (WiX) or `Oxagen_<version>_x64-setup.exe` (NSIS, installs for the current user) |

Both CLIs ship inside the app as single executables (a copy of Node with the CLI bundle embedded), so the machine does not need Node installed. That is why the app is large (about 235 MB unpacked on macOS, about 80 MB as a `.dmg`), and why each OS builds on its own runner: there is no cross-compile.

Package-manager templates (a Homebrew cask for the `.dmg`, plus a Homebrew formula and a Scoop manifest for the two CLI binaries) live under `tools/packaging/` in the repo. They go live once a tap and a bucket exist. Until then, download from downloads.oxagen.sh.

## First open while builds are unsigned

Code signing runs only when the Apple signing secrets exist in CI. Windows builds are not signed yet. A build made without signing still installs, but the OS warns once:

- **macOS.** The app is ad-hoc signed, and Gatekeeper shows "cannot verify" on first open. Open it from the Finder with a right-click (or Control-click) and choose **Open**, or allow it in **System Settings → Privacy & Security** after the first refusal.
- **Windows.** SmartScreen warns that the publisher is unknown. Choose **More info → Run anyway**.
- **Linux.** The `.deb`, `.rpm`, and `.AppImage` are unsigned, and there is no apt or dnf repository yet. Install the file directly (`sudo dpkg -i`, `sudo rpm -i`, or `chmod +x` the AppImage and run it).

A release built with the Apple certificate in place is Developer ID signed and notarized on macOS, and it opens there without a warning. Windows keeps the SmartScreen prompt until Windows signing is wired into the release workflow.

## Sign in

Press **Sign in**. The app runs `oxagen login --browser`, which opens your browser. The flag forces the browser flow, because the app's sidecar has no terminal. The web app is the org and workspace picker. The loopback callback returns the login to the CLI, which saves it in `~/.config/oxagen/config.json`. The Account panel then shows the org you signed in to, the CLI's default workspace, and the API URL. The token never crosses into the app's webview. The app's shell attaches it to the two picker calls it makes.

**Switch organization…** runs the same flow again. **Sign out** runs `oxagen logout`.

If a saved login is stale, the first picker call gets a 401, the Account panel says *Session expired*, and the primary button returns to **Sign in**.

## Enroll this machine

Once you are signed in, pick the org and workspace in the This machine panel and press **Enroll this machine**. The app runs:

```bash
tacho enroll --org <org> --workspace <workspace> --harness claude-code,codex
```

`enroll` generates an Ed25519 device key, mints a host API key for that workspace, and writes `~/.config/oxagen/tacho/host.json`. It installs the collector (`tachod`) as a user service: launchd on macOS, a systemd user unit on Linux, and a per-user Task Scheduler task on Windows. It merges Tacho's hook entries into each harness's settings and leaves every entry it did not write untouched. From then on, every Claude Code and Codex run on the machine is hash-chained and shipped. The panel shows the agent key that identifies the agent, the org and workspace the host reports to, the enrollment id, the bundle version, collector uptime, spool depth, and last ingest.

The gold button is always the next step: **Sign in** when you are not signed in, **Enroll this machine** when there is no enrollment, **Reassign** or **Apply** when a picker differs from the host, and nothing otherwise.

## Pick or change the workspace

The Workspace panel lists your orgs and that org's workspaces. Pick a different one and press **Reassign to …**. The app runs:

```bash
tacho reassign --org <org> --workspace <workspace>
```

The host API key is minted for one workspace at enrollment, so a move is a revoke plus a fresh enrollment, done as one step. The app revokes the current enrollment, strips the old enrollment's hook groups from both harnesses, and enrolls again in the target with the same device key, loopback port, and local bearer. The fleet page sees one continuous host.

Two scopes coexist, and the app shows both. The org and workspace in `config.json` are the CLI's default for its other commands. The pair in `host.json` is where this machine's runs land. Reassigning changes the second. The CLI default stays until you run `oxagen login` again (`tacho reassign --default` moves both).

## Wrappers: Claude Code and Codex

The Wrappers panel shows each harness with its detected version and whether every hook is present. Tick or untick a harness (the list never empties) and press **Apply wrappers**. The app runs the following, with the list you chose:

```bash
tacho reassign --harness claude-code,codex
```

This is the only way to drop a wrapper. `enroll` can add a harness on a re-apply but never removes one.

| | Claude Code | Codex CLI |
| --- | --- | --- |
| Hook file | `~/.claude/settings.json` (`CLAUDE_CONFIG_DIR`) | `~/.codex/hooks.json` (`CODEX_HOME`) |
| Enforcement | SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, and Stop as command hooks. Each one allows or denies with a reason and fails closed. | The same events, with the same decision shape |
| Telemetry | 28 events as `http` hooks straight to the daemon, plus OpenTelemetry export | PostToolUse, SubagentStart, SubagentStop, PreCompact, PostCompact, SessionEnd, and Interrupt as command hooks. No OTel. |
| Hook command | `tacho hook --enrollment tch_…` | `tacho hook --enrollment tch_… --harness codex` |
| Run label | `agent.harness = claude-code`, `runtime = claude-code` | `agent.harness = codex`, `runtime = codex` |

## Put the CLIs on your PATH

The Command line panel shows where `oxagen` and `tacho` resolve now. **Link** puts them on your PATH without elevation:

- macOS and Linux: symlinks in `~/.local/bin` to the binaries inside the app.
- Windows: `oxagen.cmd` and `tacho.cmd` shims in `%LOCALAPPDATA%\Oxagen\bin`, with that directory added to your user PATH. Open a new terminal afterward.

**Remove links** deletes them. The binaries stay with the app.

Once linked, the terminal and the app share the same files, so `oxagen tacho status` and the panels agree.

## Uninstall

Uninstall in this order. The Uninstall panel walks you through it and offers the second step only once the first is done.

1. **Unenroll.** In This machine, choose **Unenroll…** and confirm. The app runs `tacho unenroll`, which strips the hooks from both harnesses, stops and removes the service, revokes the enrollment on the control plane, and deletes the host credentials. Tick *also delete the local event log* to add `--purge`, which drops the local WAL, spool, and quarantine.
2. **Remove local data.** Deletes `~/.config/oxagen`: the CLI login and whatever Tacho left behind. The app refuses while `host.json` still exists.
3. **The platform uninstaller.** Drag `Oxagen.app` to the Trash on macOS, use *Apps & features* (or the NSIS uninstaller) on Windows, or run `apt remove` or `dnf remove` (or delete the AppImage) on Linux.

If you linked the CLIs, press **Remove links** first, or delete the symlinks and shims by hand.

## Managed machines (MDM)

The same installers deploy through MDM. A post-install script enrolls silently with an Oxagen API key instead of a browser sign-in:

```bash
tacho enroll --token <apiKey> --org <org> --workspace <workspace> --managed --harness claude-code,codex
```

`--managed` also prints the managed settings document. `tacho enroll --print-managed` prints only that document, which locks the hooks so a person on the machine cannot strip them. The run record still carries `enforcement_tier = client_attested`.

## From the terminal instead

Everything above is a CLI command, and the CLIs work without the app: `oxagen login`, `oxagen tacho enroll`, `oxagen tacho status`, `oxagen tacho reassign`, and `oxagen tacho unenroll`. See [Installing the CLI](/docs/cli/installation) and [Account setup](/docs/cli/account-setup). A headless Linux server has no browser for `oxagen login`, so use the `--token` path there. The app is not meant for servers.
