This walkthrough assumes you've [installed the CLI](/docs/cli/installation) and [authenticated it](/docs/cli/account-setup). Run the commands from the root of a project whose agents you want to govern.

## 1. Link the project

```bash
oxagen init
```

`init` resolves an org and workspace — picking interactively when you belong to more than one — and writes `.oxagen/workspace.json`. Every other command reads that file to scope itself, so you don't pass `--org`/`--workspace` on each invocation.

It then checks whether the workspace has a GitHub connection and offers to create one, so the knowledge graph has a source to ground on. Re-running `init` later reuses the existing link instead of re-prompting.

```bash
oxagen init --no-link   # skip the linker (CI, or when the link already exists)
```

## 2. Check what you're allowed to spend

```bash
oxagen budget show
```

This prints each configured spend ceiling — the org's and the active workspace's — with its live burn: period-to-date spend, projection to the end of the period, and whether the admission gate is currently denying.

Set one (org Owner, Admin, or Billing only):

```bash
oxagen budget set --scope workspace --period monthly --limit 500
```

See [Spend budgets](/docs/cli/budget) for the threshold ladder and the rolling-window form.

## 3. Price a workload before you run it

`oxagen cost` makes no network call — it prices token counts against the rate card baked into the CLI:

```bash
oxagen cost --in 200000 --out 40000
```

With no `--model` it compares every priced model cheapest-first and reports the spread. Add `-m <slug>` for one model, or `--rates` to dump the card.

## 4. Explain what an agent did

Given an execution id, render the run as a span tree — every step, tool call, and child execution:

```bash
oxagen trace exec_01J8…
oxagen trace exec_01J8… --json
```

Child executions appear nested under the step that spawned them, so one trace covers a whole fan-out.

## 5. Ground a question in the graph

```bash
oxagen graph search -q "where do we enforce tenant isolation?" -n 5
```

The query runs online and returns only the bounded results your current workspace grants allow — there is no local replica of the workspace graph. See [Knowledge graph from the CLI](/docs/cli/knowledge-graph).

## 6. Curate what agents have learned

```bash
oxagen memory candidates                 # OBSERVATIONs ripe for promotion
oxagen memory show mem_01J8…
oxagen memory promote mem_01J8… --to RULE --enforcement 90 --rationale "Confirmed across 3 runs"
oxagen remember "staging Postgres is on 5433, not 5432" --class RULE
```

Promotions and demotions are recorded as auditable events. See [Memory from the CLI](/docs/cli/memory).

## 7. Manage environments and secrets

```bash
oxagen env list
oxagen secret list                       # masked metadata only
oxagen secret set DATABASE_URL "postgres://…" --env staging
oxagen secret reveal DATABASE_URL --env staging   # recorded to the access log
```

## Where the coding agent went

Nothing in this CLI runs an agent. Oxagen governs, grounds, explains, meters and rates them; the agent itself is [Stella](https://github.com/macanderson/stella), which connects to Oxagen over MCP and the platform API. Invoking a retired command (`oxagen sandbox`, `oxagen eval`, a bare `oxagen "<prompt>"`, …) prints a notice saying exactly that and exits non-zero.
