This walkthrough assumes you have [installed the CLI](/docs/cli/installation) and [authenticated it](/docs/cli/account-setup). Run the commands from the root of a project whose agents you govern.

## 1. Link the project

```bash
oxagen init
```

`init` resolves an org and workspace (it asks you to pick when you belong to more than one) and writes `.oxagen/workspace.json`. Every other command reads that file to scope itself, so you don't pass `--org` or `--workspace` each time.

It then checks whether the workspace has a GitHub connection and offers to create one, so the knowledge graph has a source to ground on. Running `init` again reuses the existing link instead of asking again.

Name the org and workspace to link without a prompt, for example in CI:

```bash
oxagen init --org acme --workspace payments
```

Then write the steering your workspace has published into `.oxagen/`:

```bash
oxagen pull
```

## 2. Check the spend ceiling

```bash
oxagen budget show
```

This prints each configured spend ceiling (the org's and the active workspace's) with its live burn: period-to-date spend, the projection to the end of the period, and whether the admission gate is denying requests now.

Set one (org Owner, Admin, or Billing only):

```bash
oxagen budget set --scope workspace --period monthly --limit 500
```

See [Spend budgets](/docs/cli/budget) for the threshold ladder and the rolling-window form.

## 3. Price a workload before it runs

`oxagen cost` makes no network call. It prices token counts against the rate card built into the CLI:

```bash
oxagen cost --in 200000 --out 40000
```

With no `--model`, it compares every priced model, cheapest first, and reports the spread. Add `-m <slug>` for one model, or `--rates` to print the card.

## 4. Explain what an agent did

Given a run id, `oxagen trace` shows the run as a tree: every step, tool call, and child run:

```bash
oxagen trace aex_01J8…
oxagen trace aex_01J8… --json
```

Child runs appear nested under the step that started them, so one tree covers a whole fan-out.

## 5. Ground a question in the graph

```bash
oxagen graph search -q "where do we enforce tenant isolation?" -n 5
```

The query runs online and returns only the bounded results your workspace grants allow. There is no local copy of the workspace graph. See [Knowledge graph from the CLI](/docs/cli/knowledge-graph).

## 6. Curate what agents have learned

```bash
oxagen memory candidates                 # OBSERVATIONs ripe for promotion
oxagen memory show mem_01J8…
oxagen memory promote mem_01J8… --to RULE --enforcement 90 --rationale "Confirmed across 3 runs"
oxagen remember "staging Postgres is on 5433, not 5432" --class RULE
```

Oxagen records every promotion and demotion as an audit event. See [Memory from the CLI](/docs/cli/memory).

## 7. Manage environments and secrets

```bash
oxagen env list
oxagen secret list                       # masked metadata only
oxagen secret set DATABASE_URL "postgres://…" --env staging
oxagen secret reveal DATABASE_URL --env staging   # recorded to the access log
```

## Where the coding agent went

Nothing in this CLI runs an agent. Oxagen governs, grounds, explains, meters, and rates agents. The coding agent this CLI used to carry is now [Stella](https://github.com/macanderson/stella), which reaches Oxagen over MCP and the platform API. A retired command (`oxagen sandbox`, `oxagen eval`, a bare `oxagen "<prompt>"`, …) prints a notice saying so and exits non-zero.
