As an agent works, it learns things: that a test is flaky for a specific reason, that your team always uses `withTenantDb`, that the staging database is on an unusual port. **Agent memory** is where those lessons live, and Oxagen's memory engine, **Engram**, keeps it. Before an agent starts new work, it recalls the relevant lessons, so it doesn't rediscover the same gotcha twice. Over time, agents repeat fewer mistakes in *your* workspace.

Memory is **workspace-scoped**. Every run in the workspace shares it. It is not kept per conversation, and it never crosses workspaces or organizations.

<Callout type="info">
**Memory is not the knowledge graph.** Agent memory is *experiential*: what an agent **learned** from doing work. The [knowledge graph](/docs/cli/knowledge-graph) is *structural*: what your code and entities **are**. An agent draws on both. Memory tells it what worked last time, and the graph tells it how the system is wired.
</Callout>

## The two axes

Every memory has two independent axes, so how sure Oxagen is that a memory is true stays separate from what the memory is about:

- **Class**: the epistemic ladder, from tentative to settled: **OBSERVATION → RULE → FACT**.
  - `OBSERVATION`: something noticed in passing.
  - `RULE`: a distilled instruction the agent should follow, with an enforcement strength.
  - `FACT`: settled ground truth. Promotion to FACT requires human confirmation.
- **Kind**: the content domain, an open label like `gotcha`, `convention-deviation`, `bug-root-cause`, `preference`, or `constraint`.

And two independent scores:

- **Confidence** (0–100): how sure it is that the memory is *true*. It decays over time and recovers when re-confirmed.
- **Enforcement** (1–100, RULE only): how strongly it *should* be followed.

Memories that are cited often, with good outcomes, resist decay. Unused ones fade and are archived (recoverable, not deleted). Citations create the pressure that surfaces promotion candidates, which closes the loop.

## Capture a memory

Capture a lesson from the shell with `oxagen remember`. It infers the class and kind from your text. Pin the class and enforcement when you want to:

```bash
oxagen remember "the staging DB listens on port 5433"
oxagen remember "always use withTenantDb, never raw db()" --class RULE --enforcement 90
```

| Flag | Purpose |
|---|---|
| `--class <OBSERVATION\|RULE\|FACT>` | Pin the epistemic class instead of inferring it. |
| `--kind <kind>` | Pin the content-domain kind. |
| `--enforcement <1-100>` | How strongly to follow it (RULE only). |
| `--node <ref>` | Anchor the memory to a graph node. |
| `--json` | Machine-readable output. |

## Browse and recall

The full management surface is `oxagen memory`:

```bash
oxagen memory list --class RULE --sort citations   # rules, most-cited first
oxagen memory show mem_01H…                         # one memory in full
oxagen memory edit mem_01H… --lesson "…"            # revise (re-embeds)
oxagen memory candidates                            # observations ripe to promote
oxagen memory dismiss mem_01H…                      # drop one from the candidate queue
oxagen memory demote mem_01H… --to observation      # walk a rule/fact back down
oxagen memory citations --days 30                   # workspace citation analytics
oxagen memory rm mem_01H…                           # delete
```

### Promote up the ladder

When an observation keeps holding up, promote it. Promotion records an audit event. The `--rationale` flag is optional:

```bash
oxagen memory promote mem_01H… --to rule --enforcement 80
oxagen memory promote mem_01H… --to fact \
  --rationale "cited in three reviews; team agreed to enforce"
```

`--to fact` requires human confirmation. `oxagen memory salience` adjusts confidence, enforcement, or lifecycle status (`ACTIVE`/`SUPERSEDED`/`RETRACTED`/`ARCHIVED`) without changing the class.

### Demote back down

Demotion is the audited inverse of promotion, for rules that stopped earning their citations or facts that turned out to be wrong. It only moves down. Demoting to `observation` clears enforcement, and leaving FACT clears its human confirmation:

```bash
oxagen memory demote mem_01H… --to observation
oxagen memory demote mem_01H… --to rule --enforcement 60 \
  --rationale "still useful context, no longer binding"
```

### Dismiss a promotion suggestion

`oxagen memory candidates` shows a ranked window of observations under citation pressure. Dismissing one is durable. The memory stays active and recallable, but it leaves the queue until you restore it, and the next candidate takes its slot:

```bash
oxagen memory dismiss mem_01H…            # silence the suggestion
oxagen memory dismiss mem_01H… --restore  # let it re-qualify later
```

### Citation analytics

A workspace-wide rollup of which memories and graph nodes agents cite, how useful those citations were, and where agents break promoted rules. Read it with:

```bash
oxagen memory citations                   # 30-day window, top 10 per list
oxagen memory citations --days 90 --limit 25
```

### Import existing docs

Turn a folder of Markdown convention and rule docs into memories in bulk:

```bash
oxagen memory import docs/conventions/*.md          # preview
oxagen memory import docs/conventions/*.md --yes     # commit
```

## How agents use memory

An agent can request `recall_memory` over MCP before it works and record a lesson with `write_memory` or `save_memory`. Configure that workflow in the harness or its instructions. Installing the CLI alone does not make an external agent recall or write memories.

Use the curation commands above to review the lessons, promote useful ones, and demote or delete stale ones. A memory's enforcement score is context for the agent, not a server-side denial rule.

## Governance

Memory writes pass the same IAM checks as every capability and leave an audit record. When an agent writes on a person's behalf, the record names both the person and the agent. Because memory lives in the workspace graph, it travels with the workspace and is not locked to Oxagen's storage.
