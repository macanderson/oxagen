`oxagen` is the governance-operations CLI for the Oxagen control plane. It answers the questions an operator asks about a fleet of agents: what did they do, what context did they have, what did it cost, what are they allowed to do next.

Oxagen **governs, grounds, explains, meters/bills and rates** agents — it does not run them. Agentic coding lives in the [`stella`](https://github.com/macanderson/stella) CLI, which talks to Oxagen over MCP and the platform API.

<Callout type="warn">
**The coding agent moved.** The interactive REPL, one-shot turns, fleets, sandboxes, skills, slash commands, evals, and local rules/settings that earlier versions of this CLI shipped were removed. Every removed entry point is still registered and prints a retirement notice pointing at Stella, so a stale script fails loudly instead of silently doing nothing. See [ADR-043](https://github.com/macanderson/oxagen/blob/main/docs/adr/ADR-043-runtime-excision.md).
</Callout>

## Who this is for

These docs are written for **developers and platform operators**. You should be comfortable with a terminal, a package manager (`npm`/`pnpm`), and environment variables. No Oxagen-specific knowledge is assumed.

## What you can do

- **Meter and bill.** `oxagen budget` sets and inspects hard period-to-date spend ceilings for an org or workspace, with live burn against each one. `oxagen cost` prices token usage from the baked-in rate card before you spend anything.
- **Explain a run.** `oxagen trace <executionId>` renders an agent run as a span tree — every step, the tool calls it made, and any child executions it spawned, with timing and spend.
- **Ground answers.** `oxagen graph search` runs a bounded, workspace-scoped semantic search over the governed knowledge graph. See [Knowledge graph from the CLI](/docs/cli/knowledge-graph).
- **Curate what agents learn.** `oxagen memory` and `oxagen remember` manage the workspace's [agent memory](/docs/cli/memory) — the OBSERVATION → RULE → FACT ladder, citation analytics, and auditable promotions.
- **Govern the workspace.** Bind agents to environments (`oxagen agent env`), manage environments (`oxagen env`), and read or write the encrypted credential vault (`oxagen secret`).
- **Route economically.** `oxagen router` inspects the verified-outcome market router — observed outcomes per (task class, model) and the governed routing policy.

## One credential

The CLI needs a single credential: an **Oxagen platform token** (an API key, `oxk_live_…`) plus the org and workspace it acts in. `oxagen login` mints and stores all three.

It makes no LLM calls of its own, so there is no model provider key to configure.

| Credential | What it powers | How the CLI finds it |
|---|---|---|
| **Oxagen platform token** (+ org + workspace) | Every command that calls `api.oxagen.sh`. | `oxagen login`, or `OXAGEN_API_TOKEN` / `OXAGEN_ORG_ID` / `OXAGEN_WORKSPACE_ID` in the environment, or `~/.config/oxagen/config.json`. |

`oxagen cost`, `oxagen logs` and `oxagen telemetry` work offline with no credential at all.
