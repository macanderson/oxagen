Your Oxagen workspace keeps a governed graph of entities, documents, memories, runs, and stable provider metadata. The CLI queries that shared context through an authenticated, workspace-scoped search. It does not download the workspace graph or quietly inject a bulk copy into an agent run.

These commands call the platform, so you need an [authenticated CLI](/docs/cli/account-setup) (an Oxagen API key plus an org and workspace).

<Callout type="info">
**There is no local replica.** The workspace graph stays on the platform, and scoped online capabilities are the only way to read it. There is no bulk graph export, pull cursor, status command, or local copy. `oxagen graph search` is a bounded query, not a sync.
</Callout>

## Search the graph

`oxagen graph search` sends a natural-language query to the platform and returns only the results the current organization, workspace, and capability grants allow:

```bash
oxagen graph search -q "where do we enforce tenant isolation?"
```

| Flag | Description |
|---|---|
| `-q, --query <text>` | Natural-language query (required). |
| `-l, --labels <csv>` | Restrict to domain labels, for example `Person,Repository,PullRequest`. |
| `-n, --limit <n>` | Maximum results, 1–50 (default 10). |
| `--json` | One machine JSON line. This is also the default when stdout is piped. |
| `--quiet` | Suppress progress output on stderr. |

```bash
# Top 5 pull request and commit matches for a rate-limiting question
oxagen graph search -q "rate limiting per org" -l PullRequest,Commit -n 5

# Search for the person who owns a service
oxagen graph search -q "who owns the billing service?" -l Person
```

Every search is online. The server applies tenant scope and RBAC before it returns a bounded result set, and the CLI does not cache a full workspace graph. A deletion, revocation, or permission change takes effect at the authoritative read, not after a client replica catches up.

## What the CLI does not do

The CLI never changes the workspace graph. Shared repository topology is not uploaded through a CLI endpoint. Run records and governed evidence arrive through a separate path from graph writes.

## A typical workflow

```bash
# 1. Authenticate once (see Account setup)
oxagen login --org acme --workspace eng

# 2. Query shared context explicitly
oxagen graph search -q "how does ingestion dual-write to Postgres and Neo4j?"

# 3. Cite what you found when you brief an agent
oxagen graph search -q "ingestion cursor handling" -l Service,Document --json
```

Search is an explicit, bounded read. Running it does not insert results into a later agent turn. An agent that needs the same grounding asks for the same governed capability through the MCP gateway, where the read is metered and audited like any other.
