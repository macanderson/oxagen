Wrapping an agent puts its runs under a mandate: the access it used, the budget it spent, and a record of every step, all attributed to the workspace it ran for. For the capabilities it hands the agent, Oxagen checks the access and budget clauses on the server. The wrapper this page covers is how a run's steps become that record.

Hook-based records are client-attested. The process owner can remove the hooks, so the hook tier does not enforce against that person. Observe mode records activity without enforcing it.

The collector also has a loopback model proxy and an MCP gateway. Their controls apply to calls actually routed through them. A configured base URL alone does not establish that a run reached the gateway tier. Inspect the run's recorded tier and attribution before treating its cost or decisions as gateway-observed evidence.

The MCP gateway serves Oxagen's own tools to Claude Desktop only. Claude Code, Codex, Cursor, and Stella call the MCP servers you configure directly, and their hooks check each call. See the [harness matrix](https://github.com/macanderson/oxagen/blob/main/docs/reference/harness-matrix.md#mcp-gateway) for what can be routed later and what never can.

Supported harness adapters include Claude Code, Codex, Cursor, and Stella. A custom agent can call `tacho hook` around its own steps. The table below describes all four hook adapters.

## Install the Oxagen app

Install the app on the machine the agent runs on before you enroll it. The app bundles `tacho` and `oxagen` and links both onto your PATH on first launch, so every command on this page runs from a new terminal.

## Wrap Claude Code, Codex, Cursor, or Stella

Name the harness on `enroll` or `reassign`:

```bash
tacho enroll --harness claude-code,codex,cursor,stella
```

`enroll` merges the wrapper's hook entries into each harness's own configuration without touching an entry it did not write, and never removes a harness on a re-apply; `reassign --harness <list>` with no `--workspace` is the one way to drop one. See [Account setup](/docs/cli/account-setup) for CLI authentication. You can also use `oxagen agent enroll` with the one-time token issued during agent registration. On a machine that holds more than one agent, `--harness` on `reassign` also names the agent to change. See [Two agents on one machine](#two-agents-on-one-machine).

| | Claude Code | Codex CLI | Stella | Cursor |
| --- | --- | --- | --- | --- |
| Hook file | `~/.claude/settings.json` (`CLAUDE_CONFIG_DIR`) | `~/.codex/hooks.json` (`CODEX_HOME`) | `~/.stella/stella.toml`, or `~/.stella/settings.json` when only that exists (`STELLA_HOME`) | `~/.cursor/hooks.json`. When `CURSOR_CONFIG_DIR` or Linux/BSD `XDG_CONFIG_HOME` changes the config directory, enrollment writes both locations |
| How the entry is written | merged into the JSON hook block | merged into the JSON hook block | a marker-delimited block, `# >>> tacho enrollment tch_… >>>` to `# <<< … <<<`, so your own comments and settings around it survive | Version 1 JSON with flat hook entries, merged by enrollment ID |
| Events wrapped | SessionStart, UserPromptSubmit, PreToolUse, PermissionRequest, Stop as blocking command hooks. SessionEnd as a command hook that is spooled while the collector is down. PostToolUse, SubagentStart, SubagentStop, PreCompact, PostCompact, Interrupt as telemetry | same shape as Claude Code; no PermissionRequest as its own event, no OTel export | SessionStart, UserPromptSubmit, PreToolUse, PostToolUse, Stop, PreCompact, SubagentStart, SubagentStop. Stella has no SessionEnd, PermissionRequest, PostCompact, or Interrupt hook | `sessionStart`, `sessionEnd`, `beforeSubmitPrompt`, `preToolUse`, `postToolUse`, `postToolUseFailure`, `subagentStart`, `subagentStop`, `preCompact`, and `stop` |
| Hook command | `tacho hook --enrollment tch_…` | `tacho hook --enrollment tch_… --harness codex` | `tacho hook --enrollment tch_… --harness stella` | `tacho hook --enrollment tch_… --harness cursor` |
| Session boundary | one hooked Claude Code session. It closes on SessionEnd, or within a minute of the `claude` process exiting | one hooked Codex session. It closes on SessionEnd, or within a minute of the `codex` CLI process exiting. On Windows, and under the app server the Codex app and IDE extension drive, it closes on SessionEnd or after six idle hours | keyed on the Stella process. The session closes when the process exits, since Stella sends no session id and no SessionEnd | Cursor's `conversation_id` identifies the run across turns. It closes on `sessionEnd`, or after one idle hour, because no Cursor process lives exactly as long as one conversation. A later hook reopens it |
| Session label | `agent.harness = claude-code`, `runtime = claude-code` | `agent.harness = codex`, `runtime = codex` | `agent.harness = stella`, `runtime = stella` | `agent.harness = cursor`, `runtime = cursor` |
| Verify it | `tacho verify --harness claude-code` | `tacho verify --harness codex` | `tacho verify --harness stella` runs `stella run "<prompt>"` | `tacho verify --harness cursor` runs Cursor CLI with `-p` |

Cursor uses native camelCase hook events. Enrollment does not import Claude Code hooks or add an MCP server entry. At the veto points (`beforeSubmitPrompt`, `preToolUse`, and `subagentStart`), the writer sets `failClosed: true`. Telemetry-only hooks use `failClosed: false`. The adapter turns an approval request into a denial because Cursor does not enforce `ask` at `preToolUse`. `sessionStart` can supply context but cannot veto. These checks remain client-attested and depend on the installed hooks.

Stella itself is not required before you enroll: `enroll --harness stella` only writes the hook entry. Install Stella when you are ready for it to run:

```bash
curl -fsSL https://raw.githubusercontent.com/macanderson/stella/main/install.sh | sh
```

## Wrap a custom agent

Any agent you run yourself, in a script, a CI job, or your own loop, wraps by piping one JSON payload into `tacho hook --agent <name>` before and after each step. There is no settings file to merge into, because there is no fixed harness: you own the call sites.

```bash
tacho hook --agent <name>
```

`<name>` matches `^[a-z0-9][a-z0-9._-]{0,63}$` and becomes the session's harness label. It cannot be a built-in harness or runtime name (`claude-code`, `codex`, `cursor`, `stella`, `claude-desktop`, `claude-agent-sdk`, `custom`, `proxy`): `tacho hook` refuses those, so a custom agent is never filed as a built-in one. The machine still has to be enrolled first (`tacho enroll`) so `tacho hook` can read `~/.config/oxagen/tacho/host.json` itself; your agent never sees a credential. On a machine with more than one agent enrolled, a custom agent reports under that first enrollment, the one in `~/.config/oxagen/tacho`.

For a complete wrapped agent with tests, see [oxagenai/oxagen-wrapped-agents](https://github.com/oxagenai/oxagen-wrapped-agents). Its Stripe refund agent sends every step through `tacho hook --agent stripe-refunds`, fails closed when `tacho` does not answer, and shows an operator pause denying the next refund before it reaches Stripe.

### The call sequence

Call `tacho hook --agent <name>` around each step of a run, in this order:

1. `SessionStart`, once, before the first prompt.
2. `UserPromptSubmit`, once per prompt the agent receives.
3. `PreToolUse`, before each tool call, and wait for the answer before running the tool.
4. `PostToolUse`, after each tool call, with its result.
5. `Stop`, when the agent finishes a turn.
6. `SessionEnd`, once, when the run ends.

Skip a call and that step is invisible to Oxagen. A `PreToolUse` you skip is a tool call nobody gated; see Limits below.

### Payload

The payload is the same JSON shape Claude Code sends on stdin. Fields you don't have, omit; unrecognized fields are kept, not dropped.

| Field | Type | Carries |
| --- | --- | --- | --- |
| `session_id` | string | your agent's own id for this run |
| `hook_event_name` | string | one of the six events above |
| `cwd` | string, optional | the working directory the step ran in |
| `prompt` | string, optional | the prompt on `UserPromptSubmit` |
| `tool_name` | string, optional | on `PreToolUse` / `PostToolUse` |
| `tool_input` | object, optional | the arguments about to run |
| `tool_use_id` | string, optional | correlates a `PreToolUse` with its `PostToolUse` |
| `tool_response` | unknown, optional | the tool's result, on `PostToolUse` |
| `transcript_path` | string, optional | send `null` (the collector treats `null` the same as omitted) if you have none |

### Answers

`tacho hook` always exits `0` and prints one JSON document on stdout. Read it before you act.

| Event | Field | Meaning |
| --- | --- | --- | --- |
| `PreToolUse` | `hookSpecificOutput.permissionDecision` | `allow`, `deny`, or `ask`, with `permissionDecisionReason` |
| `UserPromptSubmit` | `decision` | `"block"` stops the prompt from reaching the agent |
| `SessionStart` | `continue` / `additionalContext` | `continue: false` stops the run before it starts; `additionalContext` is text to fold into the system prompt |
| every event | (no special field) | an empty object means continue |

When the collector is unreachable, `tacho hook` decides from the last signed policy bundle it cached and spools the event for the daemon to replay once it is back. The answer still exits `0` and still carries a decision; that decision is `enforcement_tier: client_attested`, the same tier Claude Code and Codex run at, so a run that skips the call is the failure mode, not a run that gets a deny.

### A runnable example

Python, using `subprocess`:

```python
import json
import subprocess


def tacho(agent: str, event: str, **fields) -> dict:
    payload = {"session_id": SESSION_ID, "hook_event_name": event, **fields}
    result = subprocess.run(
        ["tacho", "hook", "--agent", agent],
        input=json.dumps(payload),
        capture_output=True,
        text=True,
        check=False,
    )
    return json.loads(result.stdout or "{}")


SESSION_ID = "my-run-42"
tacho("my-agent", "SessionStart", cwd="/work")
tacho("my-agent", "UserPromptSubmit", prompt="fix the failing test")

answer = tacho(
    "my-agent",
    "PreToolUse",
    tool_name="run_shell",
    tool_input={"command": "pytest -x"},
    tool_use_id="call-1",
)
decision = answer.get("hookSpecificOutput", {}).get("permissionDecision", "allow")
if decision == "deny":
    raise RuntimeError(answer["hookSpecificOutput"]["permissionDecisionReason"])

# … run the tool only after an allow or ask you've resolved …

tacho(
    "my-agent",
    "PostToolUse",
    tool_name="run_shell",
    tool_use_id="call-1",
    tool_response={"exit_code": 0},
)
tacho("my-agent", "Stop")
tacho("my-agent", "SessionEnd")
```

TypeScript, using `node:child_process`:

```typescript
import { spawnSync } from "node:child_process";

function tacho(agent: string, event: string, fields: Record<string, unknown> = {}) {
  const payload = JSON.stringify({ session_id: SESSION_ID, hook_event_name: event, ...fields });
  const result = spawnSync("tacho", ["hook", "--agent", agent], { input: payload, encoding: "utf8" });
  return JSON.parse(result.stdout || "{}");
}

const SESSION_ID = "my-run-42";
tacho("my-agent", "SessionStart", { cwd: "/work" });
tacho("my-agent", "UserPromptSubmit", { prompt: "fix the failing test" });

const answer = tacho("my-agent", "PreToolUse", {
  tool_name: "run_shell",
  tool_input: { command: "pytest -x" },
  tool_use_id: "call-1",
});
const decision = answer.hookSpecificOutput?.permissionDecision ?? "allow";
if (decision === "deny") {
  throw new Error(answer.hookSpecificOutput.permissionDecisionReason);
}

// … run the tool only after an allow or ask you've resolved …

tacho("my-agent", "PostToolUse", {
  tool_name: "run_shell",
  tool_use_id: "call-1",
  tool_response: { exit_code: 0 },
});
tacho("my-agent", "Stop");
tacho("my-agent", "SessionEnd");
```

A shell one-liner for a quick check:

```bash
echo '{"session_id":"probe-1","hook_event_name":"SessionStart","cwd":"'"$PWD"'"}' \
  | tacho hook --agent my-agent
```

## Confirm it works

Three places agree, because they all read the same record:

- `tacho status` on the machine: shows each enrollment, each wrapped harness, and whether hooks are present.
- The app's Wrapped agents panel: lists Claude Code, Codex, Cursor, Stella, and every custom agent the collector has seen, each with a health state:

  | State | Means |
  | --- | --- |
  | healthy | runs recorded and delivered to Oxagen |
  | pending | recorded, waiting to send |
  | degraded | hooks missing, Oxagen refused or was unreachable, or something has been pending more than 10 minutes |
  | down | the collector is not answering |
  | idle | wrapped, no runs yet |
  | not wrapped | the harness or agent name has never called the hook |

- The operator console: **Open Oxagen** opens this workspace in the browser, where the run lands in the workspace's fleet record once the collector ships it.

## Two agents on one machine

An agent is one operator on one runtime with one harness, so Claude Code and Codex on your laptop are two agents. Each one gets its own enrollment: its own agent key, device key, credentials, collector port, and event log. One `tachod` service runs a collector for every agent on the machine.

### Enroll the second agent

Register the second agent on the Agents page. Then run the command the page shows on the machine that already runs the first agent:

```bash
oxagen agent enroll --token <oxe_1time_…> --harness codex
```

The first agent keeps recording, and nothing is revoked. The first enrollment stays in `~/.config/oxagen/tacho`. The second one goes into `~/.config/oxagen/tacho/agents/codex/`, a directory named for its harness. The harness's own hook file, such as `~/.codex/hooks.json`, stays where it is, and each hook entry names the enrollment it belongs to.

Three rules decide what an enroll does on a machine that already has an agent:

- A token enrolls one agent with one harness. Pass one `--harness`. A token with two harnesses is refused.
- A harness belongs to one agent. A token for a harness that an agent on the machine already hooks is refused. Pass `--force` to replace that agent's enrollment with the agent the token names. The other agents keep theirs.
- Without a token, `tacho enroll --harness <harness>` adds a harness that no agent hooks to the first enrollment. When that enrollment is live, the command revokes it and enrolls it again under a new id, with the added harness alongside the ones it already hooks. Use a token to add a separate agent.

### Check both agents

```bash
tacho status
```

On a machine with more than one enrollment, the output starts with a count. Each agent's report follows a line that names its harnesses, its agent key, and its directory:

```text
This machine holds 2 enrollments.

Agent       claude-code as acme.core.cc-laptop in /Users/you/.config/oxagen/tacho
…

Agent       codex as acme.core.codex-laptop in /Users/you/.config/oxagen/tacho/agents/codex
…
```

An agent removed on this machine whose revoke has not reached Oxagen yet reads `(retired on this machine)`. An agent revoked from the fleet page reads `(revoked on the fleet page)`.

`tacho status --json` keeps the shape a script already reads. Its top-level fields are the report of the first agent still enrolled on this machine. When the machine holds more than one enrollment, the output adds `enrollments`: one full report per enrollment, each with a `slot` field that names its directory. With one enrollment, `enrollments` is absent. This command lists every agent in both cases:

```bash
tacho status --json | jq -r '(.enrollments // [.])[] | [.host.agent_key, (.host.harnesses // [] | join(",")), .enrolled, .shipping.healthy] | @tsv'
```

`tacho status` exits `1` when no agent on the machine is enrolled, or when any agent's events are not reaching Oxagen (`shipping.healthy` is `false`).

### Remove one agent

```bash
tacho unenroll --harness codex
```

`--harness` names the agent by the harness it hooks. The command removes that agent's hooks, revokes its enrollment, and deletes its keys. The other agents stay enrolled. To remove every agent on the machine, pass `--all`:

```bash
tacho unenroll --all
```

Pass one of the two flags. Passing both is an error. On a machine with more than one enrollment, `tacho unenroll` with neither flag changes nothing. It lists the agents and exits `1`:

```text
error: this machine holds 2 enrollments: claude-code as acme.core.cc-laptop; codex as acme.core.codex-laptop. Pass --harness to name the one to remove, or --all to remove them all
```

Removing one agent restarts the `tachod` service, because one service runs every agent's collector. Until the service is back, the other agents have no collector and no model proxy. Their hooks decide from the cached policy bundle and spool their events, and the collector sends the spooled events when it starts. A model call routed through the proxy fails in that window. If the service does not start again, the command names the agents left without a collector and exits `1`. Run `tacho enroll --harness <harness>` with a harness one of those agents hooks to install the service again.

With `--purge`, the collector log is kept while another agent is still enrolled, because every agent writes to the same log.

### Reassign one agent

```bash
tacho reassign --harness codex --workspace <slug>
```

On a machine with more than one enrollment, `reassign` needs `--harness`. The list picks the agent that hooks at least one of those harnesses, and it becomes that agent's harness list. A list that names harnesses of two agents is refused. Reassign one agent at a time.

`reassign` enrolls the agent again through your CLI session, the way `tacho enroll` does without a token, so run `oxagen login` first. The new enrollment is not linked to any agent on the Agents page, and its agent key comes from the machine's hostname. An agent you enrolled with a token therefore comes back under a different agent key, without its link to the agent you registered and without that agent's mandate. `reassign` prints a warning before it revokes such an agent. To keep the link, do not reassign it:

1. Run `tacho unenroll --harness <harness>` with a harness the agent hooks.
2. Register the agent in the target workspace on the Agents page.
3. Run the command the agent's page shows.

## Limits

A run's cost comes from the usage its model calls reported. Claude Code reports it itself. Codex and Stella on Anthropic report it through the local model proxy once enrollment points them at it. Cursor never does, because Cursor has no setting that routes its model calls through the proxy. Stella on another provider, or with an Anthropic base URL you set yourself, does not either. Such a run records its tool calls and no usage, so its cost is not in any spend total. The Spend page and the Fleet spend tile say how many runs reported no usage, and on which harness, beside each total that leaves them out.

Wrapping is `client_attested`: the hook call is voluntary, so a custom agent that skips it is not gated and not recorded. Nothing on the collector side can force the call or detect that a step happened without it; a missing event shows up in the fleet record as silence, not as a flagged violation. Each agent enrolled with its own one-time token has its own enrollment, host identity, and key. Harnesses enrolled together in one `tacho enroll` share one enrollment. Custom agents report under the first enrollment on the machine, the one in `~/.config/oxagen/tacho`, and stop being recorded when that enrollment is removed.
