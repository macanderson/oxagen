The CLI needs one credential: an **Oxagen API key** (`ox_…`) plus the org and workspace it acts in. The key identifies you, the person running the CLI, to the Oxagen API. The CLI makes no LLM calls of its own, so there is no model provider key to configure.

`oxagen cost`, `oxagen logs`, and `oxagen telemetry` work without a credential. Most platform commands need authentication. `oxagen agent enroll` uses its one-time token instead of a CLI login.

## Install the Oxagen app

To enroll a machine, install the app on it first. The app links the `oxagen` and `tacho` commands onto your PATH on first launch. [Installing the CLI](/docs/cli/installation) covers the `oxagen` CLI on its own.

## 1. Create your Oxagen account

1. Go to [app.oxagen.sh](https://app.oxagen.sh) and click **Sign up**.
2. Enter your name, email, and a password, or use **Google** or **GitHub** sign-in. Oxagen emails you a verification link. Click it before you sign in.
3. On **New organization**, name the organization and its first workspace, review their slugs, and create them.

The app opens the first workspace at `/{org}/{workspace}`. Note your **org slug** and **workspace slug**. Workspace pages sit under `/{org}/{workspace}/…`, and the CLI needs both slugs.

For a full tour of the app, see [Getting started](/docs/getting-started).

## 2. Mint an Oxagen API key

The CLI authenticates to the platform with an API key (`ox_…`), not your password:

1. In the app, go to **Organization → API keys**.
2. Select the workspace and create a named API key. Ordinary keys have no arbitrary per-capability allowlist. See [Authentication](/docs/api/authentication).
3. **Copy the key now.** It is shown only once.

API keys carry org and workspace scope. The CLI sends the key as a Bearer token.

## 3. Authenticate the CLI

Run `oxagen login`. The default flow opens a browser sign-in page:

```bash
oxagen login            # opens a browser — follow the prompt, then pick your org and workspace
```

After you sign in, the consent page asks which org and workspace the CLI acts in. Both pickers stay open even when you belong to only one. When you approve, the browser lands on `app.oxagen.sh/cli/complete`, and the token is already in your terminal. To preselect the org and workspace and skip the picker:

```bash
oxagen login --org your-org-slug --workspace your-workspace-slug
```

**For CI and headless environments**, pass the key directly. There is no browser and no interactive prompt:

```bash
oxagen login --token ox_… --org your-org-slug --workspace your-workspace-slug
```

To sign out and clear the stored login:

```bash
oxagen logout
```

Confirm the credentials work:

```bash
oxagen graph search -q "workspace context" --limit 1
```

### Use environment variables instead

Every value also reads from the environment, which suits CI and provisioning scripts that must not run an interactive flow. Environment variables take precedence over the config file:

```bash
export OXAGEN_API_TOKEN="ox_…"
export OXAGEN_ORG_ID="your-org-slug"
export OXAGEN_WORKSPACE_ID="your-workspace-slug"
```

To target a self-hosted or staging API, set `OXAGEN_API_URL`. It defaults to `https://api.oxagen.sh`.

## Where credentials live

| File | Contents |
|---|---|
| `~/.config/oxagen/config.json` | Your Oxagen API key (`token`), `org`, `workspace`, and `api-url`. Written by `oxagen login`. |
| `<project>/.oxagen/workspace.json` | The project's org and workspace binding, written by `oxagen init`. It holds no secrets. It is one checkout's link, so `oxagen init` adds it to the repository's `.gitignore`, and so does the pull request `oxagen repo init` opens. `oxagen pull` keeps its record of the files it wrote here too. |

The config file holds a secret. It lives under your home directory with your user permissions. Keep it off shared machines and out of version control.
