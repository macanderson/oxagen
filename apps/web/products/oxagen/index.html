Access

Don't hand your agents the keys

An agent under Oxagen has an identity and a mandate. It does not hold a GitHub token, a database password, or a standing grant. When a task needs one of those, the agent asks. The request says who started the task, which agent is asking, which tool it wants, and what data it would reach.

  • A rule you wrote answers. The team that owns the system writes the rule. For example, one rule allows reads of the public repo. Another denies a push to main. A third sends a push to a release branch to the release owner. That person sees the change and answers from the Access page. If a rule allows or denies, the answer comes back in the same call. If a person decides, the run waits for them.
  • The key stays in Oxagen. Oxagen keeps each connection key encrypted under a key you own. When the agent needs the connection, Oxagen uses the key for it and then closes the connection. The agent does not receive the key. It keeps only its own identity. The record shows each use: the request, the rule that answered, and the person who approved it.
  • Each connection has a named owner and a review date. Oxagen records every read of the key. For each call, Oxagen uses the smallest key the provider offers, such as a Stripe restricted key or an AWS key for one bucket. The key lasts for the call plus a margin, and never more than an hour. When you revoke a connection, Oxagen stops using it at the agent's next request.

Fleet

Manage the workforce from one console

Every agent enrolled in Oxagen is on the Fleet page, whoever built it. Next to each one you see its mandate, its open requests, its spend this month against its budget, and its last run.

  • Act from one page. You can answer requests, change a budget, pause an agent, or stop it. Each action is saved in the record: who did it, to which agent, and under which rule.
  • Spend sits next to the agent. The budget, the price of each action, the rule that stops the agent, and the bill per agent, run, and person are on the same page. Finance and the operator read the same numbers.
  • Type @agents to message every running agent in a workspace. Each agent gets the message with its next model request, so no work is thrown away. The delivery report shows the step in each run where the model read it. If that is too late, interrupt, and the agent gets your text at once. Cursor and Stella get messages when a session starts.
  • To pause or stop an agent, Oxagen stops answering its requests. The agent does not have to cooperate. A payment that has been sent cannot be taken back. So if a call like that is already under way, it finishes, and the record says so.

Budget and rules

Limits for actions with real effects

Some actions have real effects: moving money, deleting data, changing production, emailing customers, or changing access. A role alone does not allow them. A person you name sets limits that expire. Then the rule checks each call against those limits.

  • Each tool carries tags for its effects. If a call has a tag that is not in the agent's mandate, the rule denies the call before it runs.
  • Oxagen tracks what is left under each limit, like a bank balance. So two calls at the same moment cannot both use the same room under a limit.
  • Each call with a real effect leaves a receipt. The receipt names the outside system's ID for the effect and the mandate it used. Oxagen checks receipts against the payment processor's own statement. An effect with no receipt opens a critical exception.

Access and record

A definition and an identity for each agent

Each agent has one identity in Oxagen, with an ID that does not change. It also has one definition file in your repo. You change the file with a pull request, like any other code.

  • From that one file, Oxagen writes the agent files for Claude Code and Codex in the same pull request. So both tools run the same agent.
  • Access is set by role, down to the tool version. An agent can never do more than the person it works for. A helper agent it starts can only have less.
  • The agent's own shell and file tools follow the same rules. If the agent may not call a tool, it cannot see the tool or search for it.

Record

Play back any run

Oxagen records every run so you can play it back. Each saved step is linked to the one before it, so a change to any step shows. You can also start again from a step, compare two runs, and export a signed copy.

  • Play a run at up to four times speed. Oxagen skips idle time, so a forty-second tool call does not take forty seconds to watch. The cost adds up as it plays.
  • Start a new run from any step. Oxagen replays the recorded tool results. So you can turn a failure into a test, or check what a different rule would have done.
  • Compare two runs of the same task to find the step where they split. When a run ends, Oxagen signs it. Your auditor can check the signature on their own computer.

Budget and rules

Every dollar, every person

Oxagen shows who spent each dollar, through which agent, and in which run.

  • Oxagen prices each model call that goes through it. It counts each kind of token: input, output, cache reads, cache writes, and reasoning. It saves the price in millionths of a dollar, with the price list it used.
  • Each cost is saved with its step. Each step belongs to a turn, a run, an agent, a person, and a workspace. So adding up spend is simple arithmetic.
  • Oxagen checks each budget before the call goes out. Later, it matches its records to the provider's usage export: by request first, then by key and day, then by invoice line.

Equipment

Give agents the business context their work requires

An agent does not know your business until something tells it. Oxagen builds a knowledge graph for each organization, in its own database, from GitHub, Linear, and Postgres. A knowledge graph is a map of things like teams and services, and how they connect.

  • Each fact links back to the record it came from. Ask a question in plain English. Oxagen shows the answer, the query it ran, and the sources.
  • Oxagen suggests the kinds of things in the map, based on your data. A person reviews them and turns them on. The result is versioned and saved in git.
  • Each run gets its context from this map, within a token budget. The run records how much it used.

Test a rule before you turn it on

Rules are written in Cedar, a policy language. A rule gives the same answer every time, and it is versioned and tested. Before a rule goes live, Oxagen runs it against your recent tool calls. Then it shows what would change.

  • +14calls now denied
  • +3calls now wait for a person

access

Outside text is marked

Oxagen treats tool output as data, not as instructions. If an argument comes from a document, a web page, or another agent's message, Oxagen marks it. If a marked argument would write something, the request goes to a person.

web page→ marked→ asks a person
record

An archive your auditor can check

Oxagen writes full records once, when a run ends. It keeps them for seven years, encrypted under your own keys. It supports legal holds. To erase a record, you delete its key. Each export comes with a script that checks it.

written once7 yearschecks offline

Each run has exactly one person in charge, even when a schedule or a webhook started it. Spend and progress add up person by person.

The short version

What the control plane holds

Oxagen works beside your agents, not inside them. You keep running the agents you chose. Oxagen sets the rules and keeps the record.
