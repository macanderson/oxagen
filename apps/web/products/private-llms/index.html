What leaves

The honest network diagram.

Most "private" AI tools mean the model is private and the telemetry is not. Ours is the boring version: with a local model configured, the agent makes no outbound request at all. Not for a licence check, not for an update, not for anonymous usage stats.

This is enforced in the code, not promised in a policy page — and you can read the code.

Nothing else changes

Private does not mean crippled.

It is the same agent, with the same tools, the same gates, the same task board and the same record. Switching to a local model is a line of configuration — not a lesser mode with half the features and a warning banner.

And because the checks that decide "is this done" are deterministic, they cost the same whichever model you point at them: nothing.

Mix, don't choose

Local for the volume. Frontier for the hard part.

Most of an agent's calls are not the interesting ones — summarising, classifying, deciding what to read next. Those can run on your own hardware all day. Route the handful that genuinely need a frontier model, and keep the rest at home.

Stays local

Summarising a long file. Ranking search results. Naming a change. Deciding what to read next. The cheap, constant, high-volume work.

The short version

What running it privately involves

The agent is a single binary and the model is whatever you already serve. There is no appliance to buy and no runtime of ours sitting in the middle of your traffic.

Weights
Yours. Open-weight models you already run, or ones we help you fit.
Serving
An OpenAI-compatible endpoint on your own host is enough.
Hardware
A laptop for the small models; your existing GPUs for the shared ones.
Agent
The same Stella binary. Configuration, not a separate build.
Network
None required. Air-gapped installs are a supported case, not a workaround.
Records
Run history, cost and events stay in local SQLite you can delete.
Governance
Add the control plane when you want it — it runs in your network too.
