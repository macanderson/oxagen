apps/api · @oxagen/api

The Hono REST service

A Node-runtime Hono service that surfaces every platform capability defined once in /packages under /v1 routes — one of the three parity surfaces alongside the interactive app and the MCP server. No drift, no reimplementation.

oxagen-v2-api.vercel.app Hono 4.12 Node runtime Vercel deployed localhost :3001

What this is

apps/api is the REST surface of the Oxagen platform. Capabilities are authored once in /packages (specifically @oxagen/handlers and @oxagen/oxagen) and this service exposes them as authenticated /v1 HTTP endpoints. It is structurally identical to the MCP server — the same handlers, the same auth boundary, zero duplicated logic.

Every request passes through the middleware stack before reaching a route handler. The API key carries org + workspace scope, so no path segment encoding of tenant identity is needed.

client→ middleware
(auth / IAM / logging)→ /v1 route→ @oxagen/handlers→ store
(PG / Neo4j / CH)
⇄

Parity surface

Every capability reachable here is reachable identically from the app UI and the MCP server. Drift is a build failure.

◈

API-key auth

All requests authenticate via Authorization: Bearer <api-key>. The key carries org + workspace scope — no path segments needed.

⊹

Single chokepoint

All AI calls pass through the single invoke() boundary in @oxagen/ai for metering, IAM enforcement, and telemetry.

Quick start

Run from the monorepo root using pnpm workspace filters. Requires .env.local with valid credentials and a local Postgres on :5433.

# from the monorepo root
pnpm install
pnpm --filter @oxagen/api dev   # tsx watch --env-file=.env.local src/index.ts
# → http://localhost:3001

The dev server uses tsx watch for instant TypeScript restarts. Env values are loaded via --env-file=.env.local; double-quoted values are normalized automatically.

pnpm --filter @oxagen/api build
# runs tsc --noEmit then node build.mjs (bundles for Vercel)

pnpm --filter @oxagen/api start   # tsx --env-file=.env.local src/index.ts
pnpm --filter @oxagen/api typecheck   # tsc --noEmit
pnpm --filter @oxagen/api lint        # eslint src --max-warnings 0
pnpm --filter @oxagen/api test:unit   # vitest run --passWithNoTests

Example: calling a /v1 endpoint

# The API key carries org + workspace scope — no path segments needed.
curl -X POST https://oxagen-v2-api.vercel.app/v1/agent/run \
  -H "Authorization: Bearer oxa_live_xxxxxxxxxxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"Summarise the ontology for workspace acme"}'

Architecture

Source layout

  • src/index.ts — entry point, starts @hono/node-server
  • src/app.ts — Hono app factory, mounts middleware + routes
  • src/routes/ — one file per /v1 capability group
  • src/middleware/ — auth, IAM, error handler, pino request logger
  • src/lib/ — shared request helpers and type utilities
  • src/bootstrap.ts — DB / telemetry initialisation on cold start
  • src/vercel.ts — Vercel serverless adapter export

FAQ & gotchas

▸ Is there an MCP endpoint at /mcp or /mcp/sse on this service?

No. This service is a plain Hono REST API. MCP lives in a separate app: apps/mcp, deployed at oxagen-v2-mcp.vercel.app. Connect MCP clients to https://oxagen-v2-mcp.vercel.app/mcp over streamable HTTP — not to any path on this host.

▸ How does auth work? Where does org/workspace scope come from?

Every request must include Authorization: Bearer <api-key>. The API key is resolved by middleware/auth.ts against the @oxagen/auth package, which looks up the key in Postgres and attaches the resolved org and workspace to the Hono context. No org or workspace path segment is required — the key carries the full scope.

▸ I need to add a new capability. Where does the logic go?

Logic belongs in /packages — either a new export from @oxagen/handlers or an extension to @oxagen/oxagen. The route in apps/api/src/routes/ is thin: it validates the request with Zod, calls the handler, and serialises the response. Never write business logic directly in a route file. The same handler must also be wired in apps/mcp/src/tools/ to maintain parity.

▸ Why is the dev port :3001 and not :3000?

:3000 is reserved for apps/app (the Next.js frontend). The API runs on :3001 to avoid collision when developing both surfaces locally at the same time. Verify your .env.local sets PORT=3001 or the default in src/index.ts.

▸ How is telemetry emitted?

Every route execution records a structured event via @oxagen/telemetry — including the surface origin (api), execution time, token usage (for AI routes), and the trace-id that threads through pino logs and error responses. ClickHouse is the append-only sink; never query telemetry from Postgres.
