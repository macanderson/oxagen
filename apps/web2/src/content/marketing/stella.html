The agent that shows its work.

Stella is our open-source coding agent for the terminal — fast, written in Rust, and model-agnostic. Bring your own keys. Every turn, every tool call, every gate and every cent lands on one deck you can read while it runs.

The Command Deck

One deck. Nothing hidden behind a spinner.

Most agents give you a wall of scrolling text and a bill at the end. Stella gives you a deck: what it planned, what it read, what it changed, what the gates said, and what each step cost — live, in the terminal you already have open.

Session. One turn, unrolled. The skill it pulled in, the files it read, the edits it made, and what each of them cost — in order, as it happens.

Task. Zoom into one unit of work and the deck tells you the thing nobody else will: what has to be true for this to count as done — and which of those checks are deterministic rather than a model's opinion.

Graph. Stella indexes your repo with tree-sitter, so it can answer "what is in this file, and what touches it" by looking it up — not by grepping and hoping.

Skills. The conventions your repo actually follows, kept as small injectable notes — and measured, so you can see which ones earn their tokens and prune the ones that never fire.

MCP. Every external tool server, its transport, its tool count, its latency and its auth state — on one screen, so a slow server is visible instead of just making the agent feel slow.

Issues. Your tracker, in the terminal, through MCP. Sort by heat, hit w, and the work starts as a plan you can read rather than a prompt you have to trust.

Events. A write is not a mystery. The deck shows the file, the size, the timing and the actual source it put on disk — the same event stream the audit trail is built from.

Verified done

A red gate is an automatic "not yet".

Ask most agents whether they finished and they will say yes. Stella runs the checks and shows you the board: which gates passed, which failed, which case failed, and what it cost to find out. When the answer is no, it says no — with the failing case attached.

Everything is a keystroke

One slash. Then fuzzy.

Every command in the deck is in one palette, ranked by what is actually happening right now — the gate board floats to the top while verify is running. Type two letters, hit enter. No menu diving, no mouse.

How it is built

Boring on purpose, where it counts

Stella is the reference implementation of the field manual we write from. The interesting parts are the ones that stop it surprising you.

Nothing leaves by default

No telemetry, no update pings, no analytics. The only network traffic is the model provider you chose, with the key you supplied.

Any model, same agent

Anthropic, OpenAI, Gemini, Vertex, Bedrock, z.ai, DeepSeek, OpenRouter — or a model on your own machine. Swapping providers is a flag, not a rewrite.

One tool, one job

One shell, the file operations, one search, and the coordination tools. A tool that does two things teaches the model neither — so it gets split.

Fan out to a fleet

One goal becomes several tasks, each in its own copy of the repo, each with its own ledger of commits and spend. They report back as one.

Every cent is counted

Per call, per step, per task, per repo. Locally in SQLite you own — and the deck shows the running total while the turn is still going.

Replay any run

Every event is written to a local store, so a run can be re-read, re-scored and argued with after the fact instead of being a story about what happened.

$ brew install macanderson/tap/stella Or curl -fsSL https://raw.githubusercontent.com/macanderson/stella/main/install.sh | sh — then stella init in any repo.

The short version

What you are actually installing

One binary. It reads your repo, talks to the model you pay for, and writes its own history to a file in your project you can delete at any time.
