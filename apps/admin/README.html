The operator console

The internal platform dashboard for Oxagen operators. Built on Next.js and @oxagen/ui. At the foundations milestone this is a stub — a landing page at /, no routes, no auth gate. The operator dashboard described below is the planned product, not the current state.

oxagen-v2-admin.vercel.app stub — landing page only Next.js 16.2.7 localhost :3200

Current status stub

This is not a working admin surface.

As of the foundations milestone, apps/admin renders a single landing page at /. There is no auth gate, no protected routes, no operator UI. The Vercel deployment exists to prove the pipeline works and to reserve the project slot. Do not use this URL as an admin interface — it is not one.

Everything described under "Planned" below is future work, tracked in Linear. The stub exists to avoid a rebuild from scratch when that work begins.

Quick start

Install at the monorepo root, run the admin target. No env file or database is required for the stub.

# from the monorepo root
pnpm install
pnpm --filter @oxagen/admin dev   # → http://localhost:3200
pnpm --filter @oxagen/admin build
pnpm --filter @oxagen/admin start   # serves the production build on :3200

Planned future

The following describes the intended product. None of this exists today. It is documented here so the design intent survives across agent sessions and is not re-decided from scratch when the work begins.

⊞

Tenant management

Create, inspect, suspend, and delete tenant organizations. Override plan limits and feature flags per tenant.

Feature flags

▸ Why the stub ships now

Reserving the Vercel project and the port assignment (:3200) now means zero migration cost when admin work begins. The pipeline, deployment, and monorepo wiring are verified. Building the real product is an additive operation — no structural changes to the repo are needed.

Planned access model future

The admin surface will never be exposed to customers. Access will be gated to @oxagen.ai email addresses exclusively. The planned RBAC model:

RoleWhoDefault
ownerMac Anderson — hardcoded in the access policy—
editorOperators granted explicit editor access—
viewerAny @oxagen.ai email on first loginyes

Session sharing across app, admin, and docs subdomains (cross-subdomain SSO) is planned via a shared Better Auth session that works across *.oxagen.ai. Until brand domains are live this applies only to the Vercel preview domains via explicit cookie config.

▸ Relationship to apps/app auth

The customer-facing app (apps/app) and this operator console will share the same @oxagen/auth package but with different access policies enforced at the session and middleware layer. Admin routes check for @oxagen.ai domain membership and RBAC role; customer routes check for a valid tenant membership. The two policies never mix.
