The interactive agent UI

The product surface customers live in: a Next.js App Router application where a fleet of role-specialized AI agents query and enrich the knowledge graph, fill forms, generate UI, and act on the business — streamed token-by-token over a hand-rolled SSE transport.

oxagen-v2-app.vercel.app Next.js 16.2.7 React 19.2 AI SDK Core ai@6 localhost :3000

What this is

apps/app is Oxagen's flagship surface — the in-app agent where a business's data has already become a live knowledge graph and a swarm of agents (planners, workers, evaluators, coordinators) acts on it. It renders streamed responses, tool calls, and generative UI (components produced from a prompt), and it is one of the three parity surfaces — every capability here is reachable identically from the API and MCP.

user prompt→ apps/app→ /api/v1/chat/stream→ @oxagen agents→ graph + action
≋

RSC streaming

Server Components + streaming over the App Router. Auth lives in server components; the client never sees session tokens.

◇

Generative UI

The model streams structured data (not server-rendered React) and the client maps it to components via the chat registry.

Form auto-fill

The ask bar fills page forms field-by-field or all-at-once with a highlight transition, riding on generateObject.

Quick start

This app is part of the Oxagen monorepo (pnpm + Turborepo). Install once at the root, then run the app target. Requires a local Postgres on :5433 and the workspace env file.

# from the monorepo root
pnpm install
pnpm --filter @oxagen/app dev   # → http://localhost:3000

Env values are double-quoted in dev; loadEnv normalizes them. Never hard-code the prod URL — it lives in env so the brand-domain switch is a single sweep.

pnpm --filter @oxagen/app build
pnpm --filter @oxagen/app start   # serves the production build on :3000
pnpm --filter @oxagen/app test:unit   # vitest
pnpm --filter @oxagen/app test:e2e    # playwright

The chat transport

The client does not use the AI SDK UI layer (@ai-sdk/react, useChat) and never touches ai/rsc/streamUI — both are forbidden here. Instead it consumes the POST /api/v1/chat/stream SSE endpoint through the hand-rolled hook below. Tool calls, generative UI, and message branching all flow through this one stream — there is no second transport.

// apps/app/src/components/chat/use-tool-stream.ts
const stream = useToolStream({
  endpoint: "/api/v1/chat/stream",
  onToolCall: (call) => registry.render(call),  // generative UI
  onToken:    (t)    => append(t),
})

FAQ & gotchas

▸ Why is there no middleware.ts?

Next.js 16 renamed the convention. Request interception lives in apps/app/src/proxy.ts, runs on the Edge runtime, and is limited to cookie inspection, URL rewrites, and redirects — no Node built-ins, no DB calls, no secrets.

▸ Can I use useChat to add a new chat feature?

No. The UI layer of the AI SDK is not used in this product. Extend use-tool-stream.ts and the chat component registry instead, so everything keeps flowing through the single SSE stream.

▸ Where do mutations happen?

Server actions handle mutations; client components subscribe to streamed responses. Auth stays in server components — the client never receives session tokens.

▸ A local prerender crash on /_global-error / /_not-found?

Known macOS / Node 24.14 local-only issue. CI/Linux builds all apps green on both bundlers. Don't chase it as a CI blocker.
