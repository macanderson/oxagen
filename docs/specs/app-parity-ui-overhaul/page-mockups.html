Core model — how a session, an agent, and the prompt fit together

Read this first; it drives the Ask and Agent Builder screens below.
Session ↔ Agent binding
A chat session is always bound to exactly one agent. Switching agent starts a new session. The agent decides the tools, skills, prompt, code-mode, and who can run it.
session.agentId → agent.definition (published version)
one agent → many sessions · one session → one agent
Effective system prompt (composed at run time) Code: ON
1 · Oxagen base orchestration (locked, never editable)
2 · + Coding prompt (injected only when Code = ON)
3 · + Your prompt (customer: selected Prompt template or inline)
4 · + Equipped skill instructions (each skill appends)
The coding layer sits above the customer layer, so turning Code on augments whatever the customer configured. It never replaces it.
