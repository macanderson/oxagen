# get_run

The Run page's header and one page of its frames (`apps/app/ARCHITECTURE.md` §1.2, §3.5; ADR-058). The header is the same row `list_runs` returns. Frames are the run's V2 events for a ledger run, cursored on the run's own `run_seq`, and the session's hash-chained events in ClickHouse `tacho_events` for a wrapped run, cursored on its dense `seq`; both sit behind an opaque cursor this capability owns. Each frame carries its body reference (spec §8.2 `content`) and never its bytes; `get_run_frame_body` reads those on demand.

## Mode

**sync**

## Surface

**Surfaces:** api, mcp, agent

- API: `POST /v1/:org_slug/:workspace_slug/runs/get`
- MCP: `get_run`
- Agent: one of the in-app assistant's seven pins, offered on every turn (`INTERACTIVE_AGENT_CAPABILITIES`). Low risk, no approval.
- CLI: no command. The CLI's run commands cover export, chain and turns, and a run's header is read on the Run page, the API or MCP.
- Authentication: session (org Owner, Admin, or Member; workspace Owner or Member)
- Capability name: `get_run`
- Not billed (`noBillingGate: true`): an SSE poll is not a governed action (ADR-052 exclusion 2). IAM default-deny; medium sensitivity.

## Input

| Field | Type | Required | Constraint |
|---|---|---|---|
| `runId` | string | yes | `arun_…` or `tse_…` |
| `framesAfter` | string | no | a frame or page cursor from an earlier read; omitted reads from the start; a cursor this capability did not write is `invalid_input` |
| `frameLimit` | integer | no | 1-500, default 200 |
| `waitMs` | integer | no | 0-20000, default 0; the handler waits inside the tenant scope, re-reading the store every 500 ms, until a frame past the cursor lands or the budget runs out |

## Output

| Field | Type | Description |
|---|---|---|
| `run` | object | the `list_runs` row for this run, with `replayGrade` (the grade the seal recorded, or null while live or ungraded; `inspect` on a recording with no retained body, on an `observe`-tier run, or with any gap the seal derived from its own rows, spec §8.4), `name` and `summary` (generated by `summarize_run`, or null; a wrapped session's `name` is instead the latest `oxagen:session_title` frame's `session_title` when the harness sealed one, cut to 256 UTF-16 code units with a trailing `…` like every `name` and `taskRef` on `list_runs`), `effort` and `thinking` (`effort` is a wrapped session's latest `request_effort`, the setting a proxied model request's body carried, then its latest `effort_level_setting`, then the latest non-empty `effort` any frame carried, then the effort the session row holds; `thinking` is the latest `always_thinking_enabled`; each is null when nothing recorded it, and both are null for every ledger run), `effortSource` (`request` when `effort` came from a proxied request's body, which wins, or `harness` when it came from the harness's own report; null exactly when `effort` is, #3891), `fit` (the Model fit reading described below, #3893), `verdict` (the witness verdict on its rollup row, ADR-064), and `operatorRole` (the operator's workspace role stamped when the run opened and never read live, as `list_runs` describes it, #3999, ADR-197). A wrapped session's `place` also carries `repository`: the connected repository (`{ host, owner, name, url }`) whose remote hashes to the digest the session's start recorded (`tacho.sessions.git_remote_digest`), matched the way `get_run_work` matches a checkout. `repository` is null when no connected repository matches, and absent when the session recorded no digest or the read of the connected repositories failed, so a caller reads "not read" rather than "none" |
| `frames.frames` | object[] | `{ cursor, seq, type, stage, observedAt, digest, summary, tool, toolStatus, approvalId, body, cost }` |
| `frames.frames[].tool` | string or null | the tool the frame is about, as its producer named it (the ledger's `capability_name` or `tool_name`, a wrapped frame's tool); null when the frame names none |
| `frames.frames[].toolStatus` | string or null | how the tool call ended, as its producer recorded it: the ledger receipt's `outcome` (`completed`, `failed`, `denied`, `cancelled`, `parked`) or a wrapped frame's tool status; null on a frame that records none, an intention included |
| `frames.frames[].approvalId` | string or null | the approval a parked tool call waits on (`apr_…`), as its receipt recorded it; null on every other frame, and on a parked receipt that named no approval. The Run page pairs the receipt with that approval's card by it |
| `frames.frames[].body` | object | `{ digest, bytesRef, redactions, fidelity }`: the sha256 of the redacted bytes (null when the frame carried no content), where they were retained (null under `digest_only` and whenever no body was retained: a wrapped frame's reference is the one the control plane wrote, never one the host set), the redactions made before write, and `full` or `digest_only` |
| `frames.frames[].cost` | `{ micros, currency, basis }` or null | the frame's own cost record; a wrapped session's `llm_call` frames carry one (`client_attested`), ledger frames carry none |
| `frames.cursor` | string or null | the point to continue from, past every frame this read consumed; null when nothing lay past `framesAfter`, so the caller keeps its cursor, and null on a sealed run whose page had nothing behind it (the handler reads one frame past the page to know); a live run keeps its cursor on every non-empty page |
| `witnessFor` | string or null | the worker run this run witnessed, by the first `proof.observed` verdict naming it (spec §8.5 "Stamping", ADR-064); a witness run renders its own tab set. Null for every other run |
| `framesError` | `{ code, message }`, absent when the frames were read | `code` is `frames_unavailable` when the frame store refused the read, such as ClickHouse over its memory cap. The header still answers, `frames.frames` is empty and `frames.cursor` is null, so the caller keeps its cursor and does not read the run as sealed (#4243) |

`run.fit` is the Model fit reading (#3893, ADR-201): whether the model class and the effort setting were the right size for the sealed run. It is generated, not the record, and it names a capability class, never a model id. No model writes it. The durable `run.fit` job computes it with `runFit` (`@oxagen/oxagen/run-fit`) once the cost rollup lands the sealed run's `cost.run_totals` row, and stores it on `tacho.sessions` or `agent.agent_runs` with the seal it read. It reads the run's turns and steps from this row, its prompts and failed tool calls from the transcript's figures (`get_run_transcript.figures`), its output and reasoning tokens from the rollup, and its effort as `run.effort` answers it.

The rule: a first-try run of at most 3 turns or 12 steps argues one class down; a run the operator prompted again, or with a failed tool call, argues one class up; anything else fits, and so does a class at the end of its family. The effort argues one level down (`low`, `medium`, `high`) when a first-try run spent more than a fifth of its output reasoning, and one level up when the run was redone. An effort off that ladder, or a run whose figures were not read, reads `fit`, which names no move.

| Field | Type | Description |
|---|---|---|
| `method` | string | `run-fit/v1`, the rule version the reading was computed under |
| `readAt` | string | RFC 3339; when the reading was computed |
| `sealedAt` | string | RFC 3339; the seal the reading read |
| `read` | object or null | `{ prompts, turns, steps, failed, outputTokens, reasoningTokens }`, the figures the reading read; null when the record lacks one it is keyed on |
| `model` | object or null | `{ verdict: "fit", tier }`, or `{ verdict: "over" \| "under", tier, suggest }` with the class one rung down or up the vendor's family; null when `read` is null or the class sits on no known ladder |
| `effort` | object | `{ verdict: "fit", effort, source }`, `{ verdict: "over" \| "under", effort, source, suggest }`, or `{ verdict: "unseen", why }` where `why` is `not_sent` when Oxagen proxied the calls and the request carried no effort, and `not_proxied` elsewhere |

`fit` is null for a live run, for a run whose stored reading read an earlier seal, and for a run with no reading yet. `list_runs` leaves out `fit` and `effortSource`.

A read that starts at the page cursor or at any frame's own cursor repeats nothing and skips nothing. `summary` is a short label built from identifiers in the frame's receipt (engine, model, tool, outcome, policy decision); an encrypted payload shows the event type and nothing it cannot read. `summary` is for a person to read. A client reads the tool, its outcome and the approval a parked call waits on from `tool`, `toolStatus` and `approvalId`, and never parses them out of the label (ADR-182 rule 3). A parked receipt's label is `create_workspace parked`, with no approval in it. A wrapped frame's `stage` is the stage its kind belongs to (`session`, `turn`, `model`, `tool`, `policy`, `effect`, `proof`, `control`, `chain`).

## Errors

- `not_found` (404): the id belongs to no run in the caller's workspace, whichever store minted it, or it names a witness run and the caller holds an API key (ADR-064).
- `invalid_input` (400): a cursor this capability did not write.

## Poll budget

Every invoke runs the IAM check and the audit and security emissions once, before the handler starts; the wait is inside the handler. With `waitMs: 20000` an idle Run page costs at most three invokes a minute.

## Live: the run frame stream

`GET /v1/:org_slug/:workspace_slug/runs/:run_id/stream` is this capability turned into a live feed (`apps/api/src/routes/v1/run.stream.ts`). It is not a second transport: it is the same SSE shape the in-app agent's stream uses (`POST /chat/stream`), and every iteration of it is one `invoke("get_run")`, so the IAM check, the rules gate and the audit emission happen on each read exactly as they do for a page load. A stream that subscribed underneath the kernel would be a second path to the same frames with none of those gates on it — access revoked mid-stream would keep delivering.

| Line | Payload |
|---|---|
| `event: run` | `{ run }` — the header, once, before any frame |
| `id: <cursor>` + `data:` | one frame, exactly as `get_run` returns it. The `id` is the frame's own cursor |
| `event: done` | `{ reason, cursor }` — `sealed` when the recording has ended and nothing lies past the last page, `idle` when the stream reached its 300 s ceiling with nothing new. The client reconnects from `cursor` |
| `event: error` | `{ message, code, reason, cursor }` — a failure after the stream is open. `reason` is present only for a handler refusal and carries its sub-code. Before it is open, a refusal leaves as a status through the error middleware, not as a 200 whose first line is an error |

**Resuming.** `EventSource` sends the last `id` back as `Last-Event-ID`; a client that is not `EventSource` passes `?after=<cursor>`. A read that starts at either repeats nothing and skips nothing, so a dropped connection costs a round trip and no frames.

**Opening.** The Run page opens the stream at `?after=<frameCursor>`, the last frame its [`get_run_transcript`](run.transcript.get.md) read folded, so the route sends only frames the page has not read. Opened with no cursor, the route sends the run from its first frame, 200 to a read: 41 reads before an 8,000-frame run reaches its head. The page also reads the `event: run` row each time the stream opens. When that row's `commandBlock` says the host went quiet or came back, and the page's own row says otherwise, the page reads itself again, so its stale light moves without a reload. A quiet stream reopens after its 300 s idle ceiling, so the light trails the host by at most the five-minute poll window plus that ceiling.

**Cost.** Each read long-polls inside the handler for up to 20 s (`waitMs`), so an idle stream costs one invoke per 20 s rather than one per client tick. `noBillingGate: true` keeps every one of them off the meter.

The live stream renews its idle deadline when it emits frames. Its terminal
event carries the last emitted frame cursor, including on the final page.

**Error codes.** An `event: error` carries one of four kinds of code (#3652, #4243):

| Code | What it is | What the Run page does |
|---|---|---|
| `authz_denied`, `surface_denied`, `pending_approval`, `forbidden` | The viewer may no longer read the run. `forbidden` is a handler refusal, whatever its reason, such as `session_required` or `run_token_invalid`; the reason travels in `reason` | Stops and says access changed |
| `invalid_input`, `unknown_capability`, `no_handler`, or the reason of a handler refusal other than `forbidden`, such as `run_not_found` | A refusal the client caused, most often a cursor this capability did not write. The message says what was refused | Reads the tail once, then stops |
| `stream_unavailable` | A server fault: a store timed out, or the kernel refused its own output (`invalid_output`). The message is always "Run stream unavailable", and the details go to the server log, never to the client | Reopens at the event's `cursor` after 1 s, doubling the wait each time, and reports the stream lost after five retries with no frame between them. A reopen that fails before the route answers, because its first read hit the same fault and left as a 500 or 503, counts as one of those retries |
| `frames_unavailable` | ClickHouse refused the frame read, most often at its server-wide memory cap. The stream sends the header first, so the page keeps it, and the message says the frames could not be read | Reopens with the same backoff as `stream_unavailable`. The route does not read again itself, because an immediate read adds to the load that caused the refusal |

A kernel code is forwarded only when the API's error middleware would answer it with a 4xx; every code it answers with a 500 is sent as `stream_unavailable`. A transport disconnect with no event keeps EventSource's own retry.
