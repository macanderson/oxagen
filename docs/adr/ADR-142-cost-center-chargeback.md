# ADR-142: Cost-center chargeback on Spend

- **Status:** Accepted
- **Date:** 2026-09-22
- **Owners:** platform
- **Refines:** ADR-060 (the rollup store and its levels). This ADR adds a
  sixth level, `cost_center`, and the statement finance charges spend back
  from.
- **Related:** ADR-086 (`withOrgDb`, the organization-wide read), ADR-055
  (governed action units, which this reported spend is not), the Mission
  Control spec §12.7 (attribution levels) and §12.3 (rounding once, at the
  statement line).

## Context

Finance teams that pay for agent spend charge it back to the teams that ran
it. Spend could be read by operator, agent, model, tool and task, but none of
those is the unit a finance system books against. An organization had no way
to say which cost center an agent or a workspace belongs to, and no statement
it could reconcile a ledger line against.

Three facts shaped the decision:

- Every Spend read was workspace-scoped. A cost center spans workspaces, so a
  per-center total that sums to the organization's total needs an
  organization-wide read.
- The existing levels skip a run that names no key at that level (spec
  §12.7). For chargeback that hides the part of the bill nobody claimed.
- `task` was already a level in the database, the kernel contract and the
  statement. Its key is the ledger run's `goal`, and a tacho run carries none.
  No run in the record carries a task id.

## Decision

### 1. The label list

`cost.cost_centers` holds the organization's valid labels (`org_only` RLS,
generated by `gen-rls-migration.ts`). A label is 1 to 64 letters, digits,
`.`, `_` or `-`, and the same pattern is the CHECK on every column that holds
one. Deleting a label sets `deleted_at`. The unique index on
`(org_id, label)` covers deleted rows, so adding a deleted label back restores
its row, and a statement keyed by label names one row across its history.

### 2. Agent and workspace labels

`agent.agents.cost_center` and `workspace.workspaces.cost_center` are
nullable text. `set_cost_center` checks the label against the live list and
stores the list's spelling. There is no foreign key, since the columns sit in
other schemas.

The rollup resolves each run's cost center when it rebuilds the run's row:
the agent's label if it names a live row, else the workspace's on the same
terms, else null. A deleted label claims no new rollup. A witness run is
charged to its worker's cost center, as it is to the worker's operator.

### 3. The cost-center level

`cost.daily_totals` gains `cost_center`. Unlike the other levels, a run with
no cost center is attributed to the reserved key `~none` rather than left
out. The label pattern refuses `~`, so no label collides with it. Every run
lands in exactly one group at its full run cost and basis, so the level sums
to the same total the run rows do, on the same basis. The Spend page prints
the `~none` row as "No cost center", beside each row's share of the month.

### 4. The chargeback statement

`export_cost_center_statement` reads the month's `cost.run_totals` rows for
every workspace through `withOrgDb`. It answers one line per cost center and
one for `~none`, each with its run count, the runs it could not price, cost in
micros and in cents, the folded basis, and the run ids that make it up, then
one total line. Micros are the figure that reconciles: the lines' micros sum
to the total's. Each line's cents and the total's cents are each rounded once,
half to even, so the cents can differ by the rounding. The handler enforces
org Owner, Admin or Billing, since the kernel's IAM check admits every human
in a non-enterprise organization.

### 5. The task level

The app gains the `task` level the kernel already had. Its key stays the
run's `goal`, because no run carries a task id. A task id belongs on the run
record first. The level can re-key to it once one exists.

### 6. Label case

`cost.cost_centers.label` is citext, so its unique index treats `ENG-1001`
and `eng-1001` as one label. `agent.agents.cost_center`,
`workspace.workspaces.cost_center` and `cost.run_totals.cost_center` are
text, and a text comparison is case-sensitive. The database does not keep
their case aligned with the list. The writers do:

- `set_cost_center` stores the list's spelling, not the spelling it was
  given, so `eng-1001` on an agent is stored as `ENG-1001`.
- The rollup casts the agent's and the workspace's label to citext before it
  looks the label up in the list, and records the list's spelling on the run
  row. The statement and the `cost_center` level group runs by that stored
  spelling, so a label that reached an agent in another case still files its
  runs under the list's spelling.
- `delete_cost_center` clears agents and workspaces whose label matches
  ignoring case.

A new writer of any of the three columns must follow the same rule: store
the list's spelling, and compare against the list ignoring case. Converting
the three columns to citext would move the rule into the schema. That takes
a migration and is deferred. Recorded 2026-09-25 for #3750.

## Alternatives

- **Store the label on the run at admission.** Rejected for now: a ledger run
  and a tacho session are admitted by different writers, and the rollup
  already reads both. Resolving at rollup keeps one reader.
- **Leave unassigned runs out of the level, as §12.7 does.** Rejected: the
  gap would sit between two numbers on the page and on the statement, where a
  reader has to find it by subtraction.
- **Store a cost-center id on agents and workspaces.** Rejected: finance
  books against the label, and a label that names one row for ever gives the
  same stability without a join on every read.

## Consequences

- A run keeps the cost center its first rollup resolved. A later rebuild (a
  reprice, or the nightly sweep of a missed seal) fills a null and changes
  nothing else, so a statement for a closed month stays where finance booked
  it after an agent or workspace is reassigned. Amended 2026-09-23 after
  review of PR #3732; the first version let a rebuild move the run.
- `cost.run_totals` rows written before this change, or before their agent
  or workspace was charged to a label, have a null `cost_center` until they
  are rebuilt, so their spend reads as unassigned. The nightly sweep does not
  revisit them. `pnpm db:backfill-cost-centers` lists the rows a live label
  now claims and, with `--apply`, sends `cost/run.sealed` for each so
  `cost.run-rollup` rebuilds it in place. The pass takes null rows only:
  moving a run from one label to another is not decided here.
- The statement holds a month of the organization's run rows in memory.
  `get_spend` caps a workspace read at 92 days for the same reason. A month is
  inside that bound per workspace, but not across a large organization.
