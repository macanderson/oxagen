# ADR-005 — Single-version monorepo via Changesets

**Date:** 2026-05-27
**Status:** Accepted
**Epic:** Foundations

## Context

The monorepo ships ~19 workspace packages. Releases need to bump
versions, tag the commit, and produce a changelog.

## Decision

Use **single-version** releases across the entire monorepo via
**Changesets**. `pnpm release:patch|minor|major` bumps every package
to the same version, tags `vX.Y.Z`, and publishes via CI on tag push.

## Alternatives considered

- **Independent per-package versioning.** Adds bookkeeping (which
  consumer needs which version) for no benefit while every app and
  package live in the same repo and ship together.
- **`bumpp` / `lerna`.** Bumpp lacks the structured changelog story;
  Lerna is largely superseded by Changesets and Turborepo.
- **Calendar versioning.** Better when releases are continuous and
  semver-meaningless; we still expect users to read `MAJOR.MINOR.PATCH`.

## Consequences

- All `package.json` files carry the same version.
- `CHANGELOG.md` per package generated by Changesets.
- Tag-triggered CI workflow publishes any package marked
  `publishConfig.access: public` (none currently — all private during
  foundations).
- Tradeoff: a small change to one package bumps every package. Acceptable
  while the repo is closed-source; revisit if we split packages into
  separate registries.
