# Security questionnaire

Use these answers for an initial procurement review of identity, authority, credentials, and records. This is an original short questionnaire, not a completed licensed CAIQ or SIG instrument. The [pack baseline](README.md) defines the source reviewed. “Implemented” describes code and requires production evidence before it becomes an assurance about operation.

| Question | Answer and evidence |
| --- | --- |
| Is a SOC 2 report available? | No report evidenced. See [readiness](soc2-readiness.md). |
| Has an independent penetration test completed? | No report evidenced. [#3758](https://github.com/macanderson/oxagen/issues/3758). |
| Is a signed DPA available? | This pack contains a [draft](dpa-template.md), not an executed agreement. |
| Are processor locations documented? | [Recipient inventory](subprocessors.md) distinguishes AWS region from unverified vendor locations. Contract schedule remains incomplete. |
| Does every agent have an identity? | Not every agent. An agent created by [registration](../../packages/handlers/src/agent.register.ts) receives a delegated agent principal for one operator on one runtime with one harness (ADR-198). The [agent schema](../../packages/database/src/schema/agent.ts) permits a null principal. The [workspace qa-chat bootstrap](../../packages/handlers/src/workspace-agents.ts) creates its agent without one, and the [assistant run](../../packages/agent/src/runtime/assistant-run.ts) attaches the `oxagen.assistant` service principal on first use, which is not a delegated principal. Legacy agents may lack one. Confirm provisioning before making an every-agent claim. |
| Are roles checked? | [IAM](../../packages/iam/src/check-iam.ts) and sensitive handler checks apply to governed calls. Tier-dependent fast paths and runtime bootstrap require review. |
| Is tenant isolation implemented? | Postgres RLS and scoped transactions: [tenant helper](../../packages/database/src/tenant.ts), [scope](../../packages/tenancy/src/scope.ts). Dedicated system operations use explicit bypass. RLS filters only while `TENANT_RLS_ENFORCEMENT_ENABLED` is on, which [configuration](../../packages/config/src/env.ts) defaults to on in production only. |
| Are machine credentials scoped? | Partly. [Machine-key scope](../../packages/iam/src/machine-key-scope.ts) limits a key that carries a purpose to that purpose's capability allowlist and denies an unknown purpose. A plain organization key with no purpose passes this check and relies on handler role gates. Key lookup is fenced to the organization. No workspace binding is enforced here. |
| Is MFA available? | TOTP plugin in [authentication](../../packages/auth/src/auth.ts). No claim of universal mandatory MFA. |
| Are passkeys supported? | No passkey plugin in this baseline. |
| Is enterprise SSO available? | Yes in source. The SAML and OIDC [SSO plugin](../../packages/auth/src/sso/plugin.ts) is registered in [authentication](../../packages/auth/src/auth.ts), merged in [#3735](https://github.com/macanderson/oxagen/pull/3735). An organization's plan must include SSO ([entitlement](../../packages/auth/src/sso/entitlement.ts)). Verify deployed status before answering yes to a customer. |
| Does IdP deprovisioning revoke credentials? | Yes in source, merged in [#3832](https://github.com/macanderson/oxagen/pull/3832). The [SCIM route](../../apps/api/src/routes/scim.ts) serves SCIM 2.0 at `/api/scim/v2` for one organization, authenticated by a bearer token an Owner or Admin mints. [The SCIM handler](../../packages/handlers/src/scim.request.ts) runs `removeOrgMemberInTx` in [member lifecycle](../../packages/database/src/member-lifecycle.ts) when the IdP sends `active: false` or DELETE. In one transaction it removes every role and membership, revokes each API key the person created, revokes each Tacho host they enrolled, and expires their unused enrollment tokens. It ends their sessions when their email is on one of the organization's verified domains ([SCIM service](../../packages/handlers/src/lib/scim/service.ts)). It writes an audit row per credential. An Owner is refused. [#3734](https://github.com/macanderson/oxagen/issues/3734) stays open until a live Okta and Entra ID tenant exercise is recorded. |
| Does Require SSO cover API keys and MCP? | Yes in source, merged in [#3832](https://github.com/macanderson/oxagen/pull/3832). Under Require SSO, the [API key resolver](../../packages/auth/src/resolvers/api-key.ts) refuses a key unless its creator is an Owner or has signed in through one of the organization's verified providers. The API answers `403`, and the [MCP server](../../apps/mcp/src/context.ts) refuses the call. The check applies only while the plan includes SSO. |
| Can SSO secrets be rotated? | Yes in source, merged in [#3832](https://github.com/macanderson/oxagen/pull/3832). [SSO secrets](../../packages/database/src/sso-secrets.ts) open under a keyring keyed by each token's key id (`SSO_SECRET_KEY_ID`, `SSO_SECRET_PREVIOUS_KEYS`). A [daily and on-demand job](../../packages/inngest-functions/src/functions/auth.sso-reseal.ts) runs the [re-seal](../../packages/database/src/sso-reseal.ts), which moves each provider's secrets onto the current key. No rotation has been evidenced in production. |
| Do login sessions expire? | Yes. A session expires 30 days after it was created or last extended, and a session used more than one day after its last update is extended (`expiresIn` and `updateAge` in [auth](../../packages/auth/src/auth.ts)). Cookie caching is off. |
| Is access review periodically performed? | No operating access-review evidence supplied. [#3757](https://github.com/macanderson/oxagen/issues/3757). |
| Are secrets field-encrypted? | [Envelope encryption](../../packages/crypto/src/envelope.ts) and [credential resolver](../../packages/plugins/src/credentials/kms.ts) implement specific paths. [OAuth hook limits](../../packages/auth/src/token-encryption.ts) prevent a universal yes. |
| Is stored infrastructure data encrypted? | [Aurora](../../infra/stacks-new/oxagen/data-services.tf) and [node volumes](../../infra/modules/app-node/main.tf) configure encryption. Verify deployed settings. |
| Is public traffic encrypted? | Public TLS terminates at the [ALB](../../infra/stacks-new/oxagen/main.tf). The ALB forwards HTTP to [Caddy](../../infra/tools/caddy/Caddyfile.alb) on the node, and the [node security group](../../infra/modules/app-node/main.tf) admits that traffic only from the ALB. That hop is not encrypted. |
| Are model credentials hidden from the harness? | Supported host custody paths exist in [credential store](../../packages/tacho/src/host/credential-store.ts). Host-owner access remains possible. |
| Can an operator approve or deny governed work? | [Approval runtime](../../packages/agent/src/runtime/approval.ts) and [decision capability](../../packages/oxagen/src/contracts/agent.approval.resolve.ts). |
| Do hooks contain a process? | No. A hook runs inside a process Oxagen does not own. The contained tier is a separate launcher, merged in [#3813](https://github.com/macanderson/oxagen/pull/3813) and recorded in [ADR-152](../adr/ADR-152-the-contained-launcher-measures-a-docker-container-and-the-server-decides-the-tier.md). `tacho run --contained` ([run command](../../packages/tacho/src/cli/run.ts)) starts Claude Code or Codex in a Docker container with no network, a read-only root, and all capabilities dropped ([launcher](../../packages/tacho/src/contained/launcher.ts), [profile](../../packages/tacho/src/contained/profile.ts)). The launcher refuses to start unless it runs as a non-root user on Linux with Docker. The [server](../../packages/handlers/src/tacho.contained_launch.register.ts) records the launch before the run starts. The [CI job](../../.github/workflows/contained.yml) that exercises it stays off until `OXAGEN_CONTAINED_ENABLED` is set, and no production contained run is evidenced. |
| Does a budget stop all spending? | No universal claim. The [proxy](../../packages/tacho/src/collector/model-proxy.ts) refuses routed requests only when the bundle's budget is enforced. It checks two ceilings: a per-session limit, and a per-day limit for the agent on the UTC calendar day ([ADR-160](../adr/ADR-160-an-agent-day-is-a-utc-calendar-day.md), merged in [#3990](https://github.com/macanderson/oxagen/pull/3990)). The day ceiling also holds for a call no session was found for, and counts the agent's other hosts from the control plane ([day spend](../../packages/tacho/src/collector/day-spend.ts)). The [mandate](../../packages/handlers/src/lib/tacho-mandate.ts) signs the day ceiling only to a host that advertises `daily_budget`. The host prices calls from the [rate card](../../packages/handlers/src/lib/tacho-host.ts) the bundle carries, which lists Anthropic and OpenAI models at list price since [#4049](https://github.com/macanderson/oxagen/pull/4049). Negotiated prices are not sent to the host. Unpriced models pass, and a call already in flight is not stopped. Calls that skip the proxy, such as Cursor's, meet neither ceiling. Verify source-to-bundle propagation and the supported harness. |
| Is action history retained? | [Run ledger](../../packages/run-ledger/src/run-store.ts), security events, and telemetry have different records and retention. Since [#3911](https://github.com/macanderson/oxagen/pull/3911), the [GAU ledger](../../packages/billing/src/gau-ledger.ts) also keeps one append-only row per billed governed action, naming the capability or tool, agent, operator, run, and tool call. It records billed actions only, so a denied call has no row. [Retention table](data-retention.md). |
| Can records be checked offline? | [Export guide](../guides/export-and-verify.md) describes integrity verification. It does not establish source completeness. Since [#3987](https://github.com/macanderson/oxagen/pull/3987), a [scheduled job](../../packages/inngest-functions/src/functions/tacho.session-idle-close.ts) closes a wrapped session that sends nothing for 12 hours, with outcome `unknown` and an unobserved tail. [Export](../../packages/handlers/src/run.export.ts) refuses a run that is live or was closed this way. A run's cost reads as an estimate until the run seals. |
| Is full subject erasure automated? | No. [Erasure processor](../../packages/inngest-functions/src/functions/privacy.erasure.execute.ts) reports incomplete multi-store cleanup. |
| Is there a defined retention policy? | Yes, but some policies lack automated deletion. [Retention table](data-retention.md). |
| Are backups configured? | [Aurora](../../infra/stacks-new/oxagen/data-services.tf) and [Neo4j DLM](../../infra/modules/app-node/backup.tf). No inference of ClickHouse backup coverage. |
| Have restores met an RTO or RPO? | No dated restore evidence or measured targets supplied. |
| Are changes reviewed and tested? | [Contribution workflow](../../CONTRIBUTING.md) and [CI](../../.github/workflows/pipeline.yml). Inspect exact commits and checks. |
| Are migrations controlled separately? | Partly. On each push to `main`, after checks, tests, and staging pass, the [pipeline's `migration-gate` job](../../.github/workflows/pipeline.yml) applies pending production migrations, Postgres with [apply-postgres-migrations.sh](../../infra/tools/apply-postgres-migrations.sh) and ClickHouse and Neo4j with [db-migrate.ts](../../tools/scripts/db-migrate.ts), then re-checks all three stores, and `deploy-node` waits for it. The [manual DB workflow](../../.github/workflows/db-migrate.yml) and [run-db-migrations.sh](../../infra/tools/run-db-migrations.sh) are the fallback when the gate refuses. `deploy-web` and the break-glass `manual-app-deploy` do not wait for migrations. |
| Is security reporting documented? | Private channels and response targets in [SECURITY.md](../../SECURITY.md). |
| Is incident response effectiveness measured? | No exercise report or response-time evidence supplied. |
| Is data residency guaranteed? | No. Regional AWS configuration does not cover onward model, SMTP, or storage routes. [Recipients](subprocessors.md). |
| Is customer-operated self-hosting verified? | No. Oxagen ships as a hosted service. No self-host package ships, and [infra](../../infra/README.md) deploys only Oxagen's own AWS accounts. |
| Is a BAA available? | No executed BAA or HIPAA assessment evidenced. |
| Are data used for provider training? | No universal answer from application source. Obtain selected providers' contractual terms for the actual route. |

Attach deployment evidence, vendor terms, access reviews, and restore records before changing a qualified answer to yes. Keep the source revision and review date with any questionnaire sent outside the repository.
