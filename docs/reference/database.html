auth

auth schema

10 tables130 columns54 rows

The auth schema is the identity and access backbone of Oxagen. It stores the canonical user account records, Better Auth-managed sessions, OAuth provider accounts, and email verification tokens that underpin every authentication flow. It also owns first-party API keys (hashed, scoped, org-scoped), encrypted third-party credentials (envelope-encrypted with KMS), and the Better Auth rate-limit bucket store used for brute-force protection. Cross-cutting concerns live here too: user UI and model preferences (1:1 with users, person-scoped not org-scoped) and GDPR compliance tables (Art.20 data export and Art.17 erasure request queues) that provide the durable audit trail for privacy operations.

auth.accounts

⛨ managed 12 rows 17 cols

Better Auth OAuth provider account link table, conforming to Better Auth's drizzle adapter schema (text PK). Each row links an Oxagen user to one external OAuth provider account. The table retains plain-text token columns (accessToken, refreshToken, idToken) because Better Auth writes these on every OAuth callback; they hold only login-scope tokens of low sensitivity. Envelope-encrypted *_enc counterparts are the authoritative store for high-value tokens once OXA-1420 encryption hooks are confirmed stable. The provider/accountId unique index prevents duplicate account links.

org

org schema

8 tables109 columns2,092 rows

The `org` Postgres schema is the central hub for organizational structure and authorization. `org.ts` defines the core multi-tenancy entities: organizations (with plan, type, and profile metadata), org_users (membership join table with role and permissions), and invitations plus access_requests for controlled onboarding and JIT access. `iam.ts` extends the schema with a full RBAC authorization model: principals (human/agent/service identities), roles (system and custom, versioned, org- or workspace-scoped), role_grants (the large permission-grant table mapping roles to capabilities with allow/deny/require_approval effects), and principal_role_assignments (mapping principals to roles with optional workspace scope and time-bounded expiry). All eight tables live in the `org` Postgres schema so drizzle-kit picks them up from a single schemaFilter entry.

billing schema

14 tables182 columns37 rows

The billing schema owns all monetization state for the Oxagen platform, implementing a 1 credit = 1¢ locked-credit model where organizations purchase credits in USD and consume them against metered AI usage. It covers the full Stripe lifecycle: plans (free/build/scale/enterprise tiers), subscriptions (with billing-interval and per-seat tracking), payment methods, invoices and line items, and a raw stripe_events append-only audit store with a separate stripe_event_processing sibling for mutable processing state. Credit accounting is handled by three cooperating tables: credit_balances (cached running total), credit_ledger (immutable audit trail of every delta), and credit_lots (authoritative lot-level source of truth with expiry and SOONEST-EXPIRING-FIRST drainage). Org-level billing preferences — auto-reload thresholds, dunning state, and billing PII — live in org_billing_settings and org_billing_profiles respectively, and billing_disputes tracks chargeback events with automatic credit clawback.
